# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`

## 1. Problem

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), all on the same expensive model, over
the whole `base..head` range, unconditionally re-running on top of whatever the author already ran
(`docs/known-issues.md:589`). Cost scales with `angles × range size`. This run measures where that
cost goes and delivers a cascade (cheap model first, expensive model where warranted) whose failure
mode cannot silently reduce review coverage below today's baseline.

## 2. Invariant (binds every design)

> A cheap-tier failure must degrade to the baseline — a full expensive review — never to less
> review than the baseline would have given.

Router unavailable, timed out, crashed, out of context, unparseable, naming a unit not in the
range, or silently omitting a unit: every one takes the degrade path. There is no code path from
"the cheap tier had a problem" to "less review happened."

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as today |

Designs differ in whether they have an unrecoverable-miss class at all; §7.4's ship bar is set from
that fact per design, not uniformly.

## 3. Decision: measure cost split before selecting a design

**Task 0 (deliverable).** Instrument expensive-tier reviews on a sample of fixtures and report the
exploration/diff-reading split, in tokens and wall-clock, per-fixture distribution (not just a
mean):

- **E — exploration:** tool calls searching or reading outside the diff (grep, unchanged-file
  reads, call-site follow, test reads).
- **D — diff-reading and finding-writing.**

**Decision rule — APPROVED (`decisionrule: measure-first`), fixed before the number is known:**

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 — exploration dominates | cheap-as-explorer (§4.1) |
| ≤ 0.30 — diff-reading dominates | per-file routing (§4.4) |
| 0.30 – 0.60 | angle routing (§4.2) |

**Angle routing is additionally run as a composable second stage in all three branches** —
decided regardless of the ratio, because it is orthogonal to the other three designs.

## 4. Design contracts

### 4.1 Cheap tier as explorer

Cheap model produces a context bundle (call sites, related tests, invariants, prior art); expensive
model reviews the whole diff with that bundle in its seed. Failure (incomplete bundle) degrades to
the expensive tier exploring for itself — no unrecoverable-miss class.

**Ship metric — decided: non-inferiority of end-to-end defect recall against the unaided expensive
panel on the same fixtures**, not context completeness. Reason: an anchoring bundle can reduce how
much the expensive tier explores, which context-completeness cannot detect but end-to-end recall
does. Context completeness is retained only as a diagnostic for explaining a recall failure, never
as the bar.

### 4.2 Route by angle

Cheap tier handles angles judged locally; expensive tier keeps `correctness` and `security`. Change
is a per-angle `AgentLaunch` replacing the current shared launch. No unrecoverable-miss class — every
angle is still reviewed by someone; a cheap-tier miss on an angle is bounded and measurable per
angle. The "local judgement" premise is measured per angle from stratum D's angle-tagged findings
(§5.6), not assumed.

### 4.3 Whole-change triage

**Decision: not used as a general design.** Reason: one false-clean loses an entire change's review,
the highest-stakes failure mode available. **Retained only as a narrow, conservative complement**
on changes where near-certainty is available — dependency bumps, generated files, pure formatting —
expressed as a conservative rule, never as a model judgement.

### 4.4 Per-file routing — retained as a measured control arm

**Decision: run regardless of what the Task 0 decision rule selects**, so the spec reports what
per-file routing would have cost and missed rather than assuming it away.

**Deliverable: empirical relational-defect recall ceiling.** For every class-3 fixture, compare the
files the fix commit touched against the files the introducing PR changed. A defect whose fix lands
outside the introducing diff is one no per-file router could have routed correctly; that fraction is
the recall ceiling for any per-file design, computed from real defects.

## 5. Corpus contract

### 5.1 Ground-truth classes — never pooled into one recall figure

| class | signal | what it proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change | same, bot-found |
| 3 | post-merge fix / revert / regression-fix of code a PR introduced | review MISSED it |

Class 2's label is not "a bot said so" but "a human author agreed and changed the code" (the
acceptance filter); reported separately from class 1 so a reader who distrusts bot-sourced signal
can discount it.

### 5.2 Strata — full factorial, no legs

| stratum | source | visibility | classes |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific (§5.6) |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin, §5.4) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

**Every stratum is probed by every router model**: `router_model × stratum × class`, full factorial
— model access is not a stratifying factor (§6).

### 5.3 Class 1/2 attribution — verified per fixture, never assumed

- `commits == 1` disqualifies the PR (a single-commit PR cannot contain a comment-driven fix
  commit).
- A later commit in the same PR must touch the commented file; how this was verified is recorded
  per fixture.
- Docs-only PRs are excluded.

### 5.4 Reviewer composition

`quite-app` has near-zero human review (287 bot / 13 human comments in the most recent 300) and
cannot carry class 1. Results are reported per repo and per class; a thin cell is recorded as thin,
never merged into a neighbour. Neovim is what keeps class 1 from resting on modular alone.

### 5.5 Class 3 pipeline

1. Candidate fix commits: `git log -i --grep` for `revert|regression|broke` and kin.
2. `git blame` the lines the fix deleted or replaced, at `fix^`.
3. Require a single introducing commit; fan-out (non-attributable) is rejected.
4. That commit's PR at pre-merge state is the fixture; the fix commit's diff states the defect.

Attrition is reported at every stage (candidates → single-attribution → adjudicated-as-defect).

### 5.6 Stratum D — two stratified cells, APPROVED (`corpus: both-stratified`)

Source: `~/.local/share/drovr/runs/skill-stickiness/` — 376 per-angle findings files across 100
panels over 22 tasks; all 100 head SHAs and 22 base SHAs resolve from this worktree (shared object
database, `git rev-parse --git-common-dir` → `/home/sauyon/devel/drovr/.git`). 131 blocking
findings: 79 `.rs`, 51 `.md`, 1 `.json`. Findings carry their angle (feeds §4.2).

Labels: *verified-real* (fix landed, or written up in `docs/known-issues.md` — the only set that
feeds the ship bar), *unverified* (reported, not scored), *rejected* (excluded with reason
recorded).

**`D-rs`** (79 blocking findings pre-filter) and **`D-md`** (51) are scored and reported as
**separate cells, never summed**. **The ship bar must pass on `D-rs` alone**; `D-md` is reported
with its own interval and cannot rescue a failing `D-rs`. Reason: reviewing Rust and reviewing prose
are different tasks a cheap tier could be good at one and useless at the other; pooling would hide
that, and dropping `.md` would forgo a free check of whether cheap-tier competence is domain-shaped.

## 6. Data handling contract

**Qwen is self-hosted.** No third-party egress; no restriction on which model reads which stratum.
The prior egress constraint (and the two-legs structure it forced) is withdrawn — it was based on a
mistaken premise.

**Visibility is unchanged and separate from model access:** `sauyon/drovr` is public;
`modularml/modular` and `quitesh/quite-app` are not. Private fixtures and probe transcripts live
outside any checkout, at `~/.local/share/drovr/cascade-corpus/`. Only aggregates (recall, precision,
counts, analysis) are committed for private strata — no diffs, source excerpts, file paths, or
defect descriptions detailed enough to reconstruct internal design.

**Enforced structurally, not by convention.** Every fixture carries `provenance: Public | Private`,
assigned at harvest from the source repo's GitHub visibility. The write guard refuses to write
`Private`-derived content to any path resolving inside a git checkout, after canonicalisation (so a
symlink out of the corpus directory and back into the repo does not defeat it). Shaped after
`ReviewOutcome::EmptyRange` (`cli/src/code_review.rs:94`): a fixture's body is reachable only
through an accessor requiring a token proving the destination was checked — the illegal state is
unrepresentable, not merely guarded at one call site.

`provenance` keeps a single consumer now that the egress guard is withdrawn with its premise; the
write guard ships with its tests, including the symlink-escape case, in the same change.

**Stated limitation, not closed by this design:** a human running an ad-hoc command outside the
harness.

## 7. Measurement design

### 7.1 Arms

`router_model ∈ {qwen, sonnet} × stratum ∈ {D, M, Q, N} × class ∈ {1, 2, 3}`, design per §3.1, with
per-file routing run as a control arm alongside.

**The ship decision is per router model** — `router_agent` / `router_model` are separate config
keys (§8); a sonnet-routed cascade is a different product from a qwen-routed one.

### 7.2 Class 3 metric — APPROVED (`class3gate: gates-conditional`)

For classes 1, 2, and stratum D, the expensive tier found the defect by construction. Class-3
defects were missed by review, so the expensive tier may miss them too and a cheap tier cannot be
blamed for failing where the expensive tier would also fail. Two numbers:

- **Conditional recall** (gates): of the class-3 defects the expensive tier finds, how many survive
  the cascade.
- **Expensive-tier absolute detection rate on class 3** (reported, gates nothing): what fraction of
  review-missed defects the full panel finds at all.

### 7.3 Discrimination and stopping

**Synthetic controls, per stratum and per class:** NULL (everything cleared; recall 0, saving
maximal) and FLOOD (everything escalated; recall 1.0, saving 0). A real cheap tier must land
strictly inside the bracket on both axes, or those fixtures are rebuilt before anything is scored.

**Positive control:** re-running the expensive tier on a sample must re-find recorded class-1/2
defects at a high rate; if not, the fixtures are re-cut, not the cheap tier.

**Dev/held-out split** assigned before any cheap-tier prompt is written, at task/PR level (no diff
in both). Held-out is scored once, after the prompt is frozen and its `git hash-object` recorded.

**Decision: no `blind-map.json`** — a departure from the prior protocol, recorded rather than
omitted. Reason: the threat here is prompt overfitting, not scorer bias (scoring is set membership
with no human judgement), so the dev/held-out split is the load-bearing control, not blinding.

### 7.4 Ship bar — APPROVED non-uniform (`barshape: by-failure-mode`)

N is sized to the power the bar needs (qwen is unlimited and may read every stratum), not trimmed to
fit the corpus. Wilson 95% lower bound, N required to clear each target given misses observed:

| LB target | 0 misses | 1 miss | 2 misses | 3 misses | 4 misses |
|---|---|---|---|---|---|
| ≥ 0.85 | 22 | 34 | 45 | 55 | 64 |
| ≥ 0.90 | 35 | 53 | 69 | 84 | 99 |
| ≥ 0.95 | 73 | 110 | 142 | 173 | 202 |
| ≥ 0.97 | 125 | 185 | 239 | 290 | 339 |

**Bar set by failure mode, not uniformly:**

- **Designs with an unrecoverable-miss class** (per-file, whole-change): a miss is a defect nobody
  ever looks at again. Recall ≥ 0.98 with Wilson LB ≥ 0.95, target N ≥ 142 per gated cell.
- **Designs whose failure degrades to baseline** (angle routing, cheap-as-explorer): the failure is
  a cost regression, not a lost defect. Non-inferiority against the unaided expensive panel, cascade
  recall lower bound ≥ 0.90 of the unaided panel's point estimate, target N ≥ 69.

**Decision: do not target beyond 0.95 LB even for unrecoverable-miss designs.** Reason: N = 239 for
a two-miss tolerance at LB ≥ 0.97 buys a 0.02 improvement in a bound whose real uncertainty is
dominated by corpus-construction choices (§7.5), not sampling error — that corpus spend is worth
more as a fourth stratum.

**Gate order:** 0. N floor met, else null for that cell. 1. Instrument discriminates (§7.3). 2. The
recall bar above. 3. Escalation/skip rate leaves a real saving. 4. Measured end-to-end cost < 0.80×
the non-cascade panel.

**Cell definition and pooling.** `N ≥ 142` per `(model × stratum × class)` cell would be 24 cells
and is not reachable; the floor applies to the gated number **pooled across strata within one
`(model × class)`**. Pooling across strata buys power; pooling across classes would destroy meaning
(forbidden by §5.1). Per-stratum numbers are always reported alongside; if per-stratum recall is
more heterogeneous than sampling explains, the pooled figure is not reported as the headline and the
discrepant stratum is reported as the finding.

**Ship decision:** bars 1 and 2 are the ship decision. Failing 3 or 4 ships the code behind its
off-by-default flag with the negative economics written up. Precision, hint quality, context
completeness, and class-3 absolute detection are reported and are not decision inputs.

**Freezing.** Strata D and N are frozen by a MANIFEST in the shape of
`docs/skill-evidence/arms/MANIFEST.md` — `git hash-object --no-filters` blob SHAs, a commit cell
that must contain the blob at the recorded path, header-resolved columns, a test re-checking every
row. Strata M and Q are frozen the same way in the private corpus directory, with only the row count
and the manifest's digest committed.

**Ledger.** Every cheap-tier invocation counted in an append-only ledger with per-stage ceilings,
arithmetic checked by a test. Retries count.

### 7.5 Stated limitations

1. Corpus construction is now the largest limitation, not model access: each class filter
   (comment→fix attribution, single-blame attribution, verified-real) selects a reachable subset of
   defects. Class 3 keeps only cleanly-attributable defects (7 of 40 candidates in the §5.5
   validation sample), which are plausibly the simpler ones — the measured ceiling may be optimistic
   in a direction no interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never an absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed entirely; class 3 supplies that.
4. Class 1 rests on modular and neovim only.

## 8. Configuration contract

```toml
[review.cascade]
enabled = false            # DEFAULT, stays off in this run regardless of result
mode = "<undecided>"       # explorer | angle | file | change — SET BY TASK 0 (§3.1), no default ships
                           # until the measurement picks one
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000       # expiry takes the degrade path of §2
```

**Cheap tier invocation: headless, not a herdr pane** — `opencode run --agent plan -m <model>`,
verified working this session. Reason: a cold `opencode` reviewer pane swallows its seed and the
panel cannot converge (`docs/known-issues.md:3437`); the headless path routes around that bug rather
than fixing it, and the bug stays open and documented. `opencode run` stdout is a subprocess pipe,
not the rendered terminal view `cli/src/code_review.rs:1` refuses to scrape. Read-only via
`--agent plan` with `--auto` absent; `readonly_displace` (`cli/src/config.rs:589`) runs first.

**Deliverables:**

1. Task 0 cost instrumentation and its report.
2. Relational-defect recall ceiling (§4.4).
3. Corpus harvesters — class 1/2 attribution, class 3 blame-back — each reporting attrition.
4. Fixtures + MANIFESTs; D and N committed, M and Q private.
5. `provenance` typing, write guard, tests.
6. Cheap-tier implementation for the selected mode plus the per-file control arm.
7. Cascade stage in `cli/src/code_review.rs`, behind `enabled = false`.
8. `docs/cascade-evidence/results.md` — controls, dev numbers, one held-out score per
   (model × stratum × class), each bar in order, ship decisions, §7.5 limitations, aggregates only.
9. Run ledger.

**Guard-with-artifact.** Every set this run extends — config keys, the `mode` enum, the cheap
tier's output vocabulary, ledger columns, MANIFEST rows, fixture list, the class enum — has its
guarding test extended in the same change.

## 9. Scope boundaries

**Out, deliberately:** flipping the default on; changing the angle set, severity model, merge or
resume path; a second measurement instrument; fixing `docs/known-issues.md:3437` (routed around, not
fixed — pane bug stays open and documented); any tier between qwen and opus.

**`ko-ag/qwen3.6-35b-abliterated` is an abliterated build** (safety tuning removed) — recorded so a
writeup doesn't describe a different experiment than the one run. Under every design in §4 its
output is either a routing decision or a context bundle, never a finding that reaches a verdict.
