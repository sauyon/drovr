# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`
**Status:** approved 2026-08-06, turn 1. No open questions.

## 1. Problem

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), all on the same expensive model, over
the whole `base..head` range. Cost scales with `angles × range size`, and the driver re-runs the
full panel unconditionally regardless of what the author already ran
(`docs/known-issues.md:589`).

A cheap-first cascade is the target design. The risk it introduces: a cheap tier's false negative
is unrecoverable if nothing downstream re-checks what the cheap tier waved through — a `Clean`
produced that way is byte-identical to a real one. This repo has hit that vacuous-pass class ten
times (`docs/known-issues.md:526`, `:589`). §2 is the invariant that prevents a cascade design from
adding an eleventh.

This run is a measurement with a feature attached, not a feature with a benchmark attached. The
first measurement (§3) decides which design ships; nothing downstream is committed ahead of it.

## 2. Degrade invariant (binding on every design)

> A cheap-tier failure must degrade to the baseline — a full expensive review — never to less
> review than the baseline would have given.

Router unavailable, timed out, crashed, out of context, unparseable, naming a unit not in the
range, or silently omitting a unit: every one of these takes the degrade path. There is no code
path from "the cheap tier had a problem" to "less review happened." Per-instantiation meaning:

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as today |

Designs differ in whether they have an *unrecoverable-miss class* at all (a miss that nothing ever
re-checks) versus one whose worst case is a cost regression. §7.4's ship bar is set from that
distinction per design, not applied uniformly.

## 3. Design selection is measured, not chosen up front

**Task 0 (deliverable 1).** Instrument expensive-tier reviews on a sample of fixtures and report
the exploration/diff-reading split, in tokens and wall-clock, per fixture (not just a mean — a
ratio that swings by change size is itself a finding):

- **E — exploration:** tool calls that search or read outside the diff (grep, unchanged-file reads,
  call-site follows, test reads).
- **D — diff-reading and finding-writing.**

Reported as `E/(E+D)`.

**Decision — pre-registered rule (`decisionrule: measure-first`), chosen before the number is
known:**

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 | cheap-as-explorer (§4.1) |
| ≤ 0.30 | per-file routing (§4.4) |
| 0.30 – 0.60 | angle routing (§4.2) |

**Decision:** angle routing is additionally evaluated as a composable second stage in all three
branches — it is orthogonal to the ratio and to whichever primary design is selected.

**Decision:** per-file routing (§4.4) runs as a measured control arm regardless of which branch is
selected, so the spec reports what it would have cost and missed rather than assuming it away.

## 4. Candidate designs — contracts and ship criteria

### 4.1 Cheap tier as explorer / context-builder

Cheap model locates call sites, related tests, invariants, prior art; hands the expensive model a
context bundle. The expensive model reviews the **whole** diff with the bundle in its seed —
nothing is skipped, so this design has no unrecoverable-miss class; its failure mode is an
incomplete bundle, which degrades to the expensive tier exploring for itself (§2).

**Decision — ship metric is non-inferiority of end-to-end defect recall against the unaided
expensive panel on the same fixtures**, not context completeness. Rationale: a partial bundle may
anchor the reviewer into exploring less than if it had been handed nothing, which context
completeness cannot detect but end-to-end recall does. Context completeness (did the bundle contain
the file/symbol the defect required?) is retained only as a diagnostic for explaining a failure.

Largest architectural change of the four: needs its own read-only launch, a bundle format, and a
seed extension.

### 4.2 Route by angle

Cheap tier takes angles whose judgement is local; expensive tier keeps correctness and security.
Implementation is a per-angle `AgentLaunch` replacing the current shared launch — the smallest diff
of any candidate, since `cfg.angles` is already the fan-out dimension. No unrecoverable-miss class:
every angle is still reviewed by someone; failure is "the cheap tier did a worse job on that angle,"
bounded and measurable per angle.

**Decision:** which angles are cheapenable is measured per angle, not assumed — stratum D findings
carry their angle (§5.6), which makes this testable rather than argued.

### 4.3 Whole-change triage — not adopted as a general design

One decision per change: does it need deep review at all. Rejected as the general mechanism because
a false clean loses an entire change's review, and no achievable recall bar makes that acceptable
at scale.

**Decision:** retained only as a narrow, conservative complement on changes where near-certainty is
available — dependency bumps, generated files, pure formatting — expressed as a fixed conservative
rule, never as a model judgement, and never as the general design.

### 4.4 Per-file routing — control arm

The original design, kept in the run regardless of §3's outcome (decision, §3). A router judging a
file in isolation cannot see relational defects — bugs visible only from a call site, invariant, or
test in a different file — a recall ceiling no model quality fixes.

**Deliverable 2 — empirical relational-defect recall ceiling.** For every class-3 fixture (§5.1),
compare the files the *fix* commit touched against the files the *introducing* PR changed. A defect
whose fix lands outside the introducing diff is one no per-file router could have routed correctly;
that fraction is the ceiling, computed from real defects.

## 5. Corpus

### 5.1 Ground-truth classes — never pooled into one recall figure

| class | signal | proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change | same, bot-found |
| 3 | post-merge fix / revert / regression-fix of code a PR introduced | review MISSED it |

**Decision:** class 2 requires the acceptance filter — not "a bot said so" but "a human author
agreed and changed the code" — which is what makes it distinct from a same-model-family circularity
problem. Reported separately from class 1 so a reader who disagrees with the filter can discount it.

### 5.2 Strata — full factorial, no legs

| stratum | source | visibility | classes carried |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific (§5.6) |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin, §5.4) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

**Decision:** every stratum is probed by every router model — `router_model × stratum × class` is a
full factorial. Model access is not a stratifying factor (§6: qwen is self-hosted, no egress
restriction). Neovim's role is corpus diversity and public reproducibility, measured this session at
33 inline review comments per 40 merged PRs (`ghostty-org/ghostty` yielded 9/40 and is not used).

### 5.3 Class 1/2 attribution — verified per fixture, never assumed

- `commits == 1` disqualifies the PR (a single-commit PR cannot contain a comment-driven fix
  commit) — disqualifies modular 94850 (13 comments, 16 files) and 95031 (11 comments, 11 files).
- A later commit in the same PR must touch the commented file (ideally the commented lines); the
  verification method is recorded per fixture.
- Docs-only PRs are excluded (modular 95055).

Best class-1/2 candidate: modular PR 94953 (26 comments — 5 bot, 21 human — 9 files, +339/−158, 6
commits). PR 94602 (13 human comments, 71 files, +6851/−108, 5 commits) is available as a
large-diff fixture; its size makes per-defect attribution harder.

### 5.4 Reviewer composition

Of the 300 most recent review comments: modular is 47 bot / 253 human (`cursor[bot]` top single
reviewer at 36); quite-app is 287 bot / 13 human (`gemini-code-assist[bot]` at 240, its only human
reviewer is `sauyon` at 13).

**Decision:** quite-app cannot carry class 1 — it has essentially no human review. Results are
reported per repo and per class; a thin cell is recorded as thin, never merged into a neighbour.

### 5.5 Class 3 pipeline — validated end-to-end

1. Candidate fix commits: `git log -i --grep` for `revert|regression|broke` and kin.
2. `git blame` the lines the fix deleted or replaced, at `fix^`.
3. Require a single introducing commit — fan-out means the defect is not cleanly attributable and
   is rejected.
4. That commit's PR at pre-merge state is the fixture; the fix commit's diff is the human-authored
   label of what the defect was and where.

Validated on quite-app: fix `cb1adad` deleted lines in `quited/qrun/src/sip_clone.rs`; blame
resolves to single commit `55b80032`.

Raw signal (matching commits in the last 2000, case-insensitive, overlapping): modular
`Revert` 28 / `regression` 70 / `broke` 26; quite-app 29 / 36 / 28.

**Attrition is reported at every stage** (candidates → single-attribution → adjudicated-as-defect).
Of 40 class-3 candidates sampled in quite-app, 7 touched ≤ 2 files; step 3 rejects the rest as
batched fixes.

### 5.6 Stratum D

`~/.local/share/drovr/runs/skill-stickiness/` holds 376 per-angle findings across 100 panels over 22
tasks, plus every `<task>-base.sha` and `<task>-review-<iter>.head`. All 100 head SHAs and 22 base
SHAs resolve from this worktree (`git rev-parse --git-common-dir` → `/home/sauyon/devel/drovr/.git`).
131 blocking findings: 79 `.rs`, 51 `.md`, 1 `.json`, over 20 tasks. Findings carry their angle,
which is what makes §4.2's per-angle premise testable.

Labels: *verified-real* (a fix landed, or it is written up in `docs/known-issues.md`) — the only set
that feeds the ship bar; *unverified* — reported, not scored; *rejected* — excluded with the reason
recorded.

**Decision (`corpus: both-stratified`): stratum D scores as two stratified cells, `D-rs` (79
blocking findings, pre-filter) and `D-md` (51), reported separately and never summed.** Rust and
prose review are different tasks; a cheap tier could be good at one and useless at the other, and
pooling would hide that. **The ship bar must pass on `D-rs` alone; `D-md` is reported with its own
interval and cannot rescue a failing `D-rs`.**

## 6. Data handling

**Decision: the egress constraint is withdrawn in full.** Qwen is self-hosted — no third-party
egress, no restriction on which model reads which stratum. This withdraws the earlier two-legs
structure and the qwen-on-real-traffic gap along with it.

**What is unchanged, because it was always about publishing rather than about which model reads
what:** `sauyon/drovr` is public; `modularml/modular` and `quitesh/quite-app` are not. Private
fixtures and probe transcripts live outside any checkout (`~/.local/share/drovr/cascade-corpus/`).
Only aggregates are committed — recall, precision, counts, analysis. No diffs, no source excerpts,
no file paths from those repos, no defect description detailed enough to reconstruct internal
design.

**Contract — `provenance` typing.** Every fixture carries `provenance: Public | Private`, assigned
at harvest from the source repo's GitHub visibility, not from a path convention or recollection. The
write guard refuses to write `Private`-derived content to any path resolving inside a git checkout,
after canonicalisation — a symlink out of the corpus directory and back into the repo does not
defeat it. Shaped after `ReviewOutcome::EmptyRange` (`cli/src/code_review.rs:94`): a fixture's body
is reachable only through an accessor requiring a token proving the destination was checked, so the
illegal state is unrepresentable rather than guarded at one call site.

`provenance` keeps a single consumer now that the egress guard is withdrawn — one field with one
purpose, not two with one vestigial.

**Deliverable 5.** Write guard ships with its tests in the same change, including the
symlink-escape case. **Not closed by this guard:** a human running an ad-hoc command outside the
harness.

## 7. Measurement

### 7.1 Arms

`router_model ∈ {qwen, sonnet} × stratum ∈ {D, M, Q, N} × class ∈ {1, 2, 3}`, design fixed by §3,
per-file routing run as a control arm alongside.

**Contract:** the ship decision is per router model, so `router_agent` and `router_model` are
separate config keys (§8) — a sonnet-routed cascade is a different product from a qwen-routed one.

### 7.2 Class 3 metric (`class3gate: gates-conditional`)

For classes 1, 2, and stratum D the expensive tier found the defect by construction. Class-3
defects were missed by review, so the expensive tier may miss them too — a cheap tier cannot be
blamed for failing on a defect the expensive tier would also fail on.

**Decision — two metrics:**
- **Conditional recall** (gates): of the class-3 defects the expensive tier finds, how many survive
  the cascade.
- **Expensive-tier absolute detection rate on class 3** (reported, does not gate): what fraction of
  review-missed defects the full panel finds at all.

### 7.3 Discrimination and controls

**Decision — synthetic brackets.** NULL (everything cleared: recall 0, saving maximal) and FLOOD
(everything escalated: recall 1.0, saving 0) bracket the metric, both free to compute. Per stratum
and per class, a real cheap tier must land strictly inside the bracket on both axes, or those
fixtures are rebuilt before anything is scored. (Rationale: the prior run's instrument did not
discriminate — unaided agents scored 3/4 and 4/4 with no skill at all.)

**Decision — positive control.** Re-running the expensive tier on a sample must re-find recorded
class-1/2 defects at a high rate; if not, the fixtures are not reviewable in isolation and the
corpus needs re-cutting, not the cheap tier.

**Decision — dev/held-out split, no `blind-map.json`.** Split assigned before any cheap-tier prompt
is written, at task/PR level so no diff appears in both. Held-out is scored once, after the prompt
is frozen and its `git hash-object` recorded. Rationale: the threat here is prompt overfitting, not
scorer bias — scoring is set membership with no human judgement — so the split is the load-bearing
control and a blind map is unnecessary. This is a deliberate departure from the prior protocol.

### 7.4 Ship bar (`barshape: by-failure-mode`)

N floors below are Wilson 95% lower bound, computed from misses actually observed:

| LB target | 0 misses | 1 miss | 2 misses |
|---|---|---|---|
| ≥ 0.90 | 35 | 53 | 69 |
| ≥ 0.95 | 73 | 110 | 142 |

**Decision — the bar is set by failure mode, not uniformly:**

- **Designs with an unrecoverable-miss class** (per-file, whole-change): a miss is a defect nobody
  ever looks at again. **Recall ≥ 0.98 with Wilson LB ≥ 0.95, target N ≥ 142** per gated cell.
- **Designs whose failure degrades to baseline** (angle routing, cheap-as-explorer): failure is a
  cost regression, not a lost defect. **Non-inferiority against the unaided expensive panel — cascade
  recall LB ≥ 0.90 of the unaided panel's point estimate, target N ≥ 69.** Rationale: demanding 0.95
  LB here buys nothing real (the expensive tier still reviews everything) and costs a corpus.

Going above 0.95 LB is rejected for the unrecoverable designs too: N = 239 for a two-miss tolerance
at LB ≥ 0.97 buys 0.02 on a bound whose real uncertainty is dominated by corpus construction (§7.5),
not sampling error.

**Gate order:** 0. N floor met, else the cell is null. 1. Instrument discriminates (§7.3). 2. Recall
bar above. 3. Escalation/skip rate leaves a real saving. 4. Measured end-to-end cost < 0.80× the
non-cascade panel.

**Contract — pooling.** `N ≥ 142` per `(model × stratum × class)` cell would require 24 cells and is
not reachable. **Decision:** the gated floor applies to strata pooled within one `(model × class)`
— pooling across strata buys power; pooling across classes would destroy meaning, which is why §5.1
forbids only the latter. Per-stratum numbers are always reported alongside; pooling is conditional
on agreement — if per-stratum recall is more heterogeneous than sampling explains, the pooled figure
is not reported as the headline, and the discrepant stratum is reported as the finding.

**Decision — bars 1 and 2 are the ship decision.** Failing bar 3 or 4 ships the code behind its
off-by-default flag with the negative economics written up. Precision, hint quality, context
completeness, and class-3 absolute detection are reported and are not decision inputs.

**Contract — freezing.** Stratum D and N fixtures are frozen by a MANIFEST in the shape of
`docs/skill-evidence/arms/MANIFEST.md`: `git hash-object --no-filters` blob SHAs, a commit cell that
must contain the blob at the recorded path, header-resolved columns, a test re-checking every row.
Strata M and Q are frozen the same way in the private corpus directory, with only the row count and
the manifest's digest committed.

**Contract — ledger.** Every cheap-tier invocation is counted in an append-only ledger with
per-stage ceilings, arithmetic checked by a test. Retries count.

### 7.5 Stated limitations

1. The largest limitation is corpus construction, not model access: every class is defined by a
   filter (comment→fix attribution, single-blame attribution, verified-real), and each filter
   selects a reachable subset of defects. Class 3 keeps only cleanly-attributable defects (7 of 40
   candidates, §5.5), which are plausibly the simpler ones — the measured ceiling may be optimistic
   in a direction no interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never an absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed entirely, which is what class 3 supplies.
4. Class 1 rests on modular and neovim only (§5.4).

## 8. Configuration contract

```toml
[review.cascade]
enabled = false            # default; stays off in this run regardless of result
mode = "<undecided>"       # explorer | angle | file | change — set by Task 0's decision rule (§3).
                           # No default ships until the measurement picks one.
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000       # expiry takes the degrade path of §2
```

`router_agent` / `router_model` are separate keys from the above (§7.1) — the ship decision is per
router model.

**Decision — cheap tier runs headless, not as a herdr pane:** `opencode run --agent plan -m
<model>`, verified working this session. Every cold `opencode` reviewer pane swallows its seed and
the panel cannot converge (`docs/known-issues.md:3437`), so the pane path is closed for this
backend; `opencode run` stdout is a subprocess pipe, not the rendered terminal view
`cli/src/code_review.rs:1` refuses to scrape — headless routes around the bug rather than fixing it.
Read-only is enforced via `--agent plan` with `--auto` absent; the `readonly_displace` protection
(`cli/src/config.rs:589`) runs first.

**Contract — guard-with-artifact.** Every set this run extends (config keys, the `mode` enum, the
cheap tier's output vocabulary, ledger columns, MANIFEST rows, fixture list, the class enum) has its
guarding test extended in the same change.

## 10. Out of scope

- Flipping `enabled` to `true` by default.
- Changing the angle set, severity model, or merge/resume path.
- A second measurement instrument.
- Fixing `docs/known-issues.md:3437` (the pane bug) — the headless cheap tier routes around it; the
  bug stays open and documented, not fixed.
- Any tier between qwen and opus.
- Whole-change triage as a general mechanism (§4.3) — only its narrow conservative-rule form is in
  scope.

removed). Under every design in §4 its output is either a routing decision or a context bundle,
never a finding that reaches a verdict directly.
