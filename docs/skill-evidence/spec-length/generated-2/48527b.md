# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`

## 1. Problem and shape of the run

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), every one on the same expensive model,
over the whole `base..head` range. Cost scales with `angles × range size`.

A cheap-first cascade is the obvious saving and the obvious way to ship a silent regression: a
cheap tier's false negative is unrecoverable downstream, and a `Clean` produced that way is
byte-identical to a real one (`docs/known-issues.md:526`, `:589`). **This run is a measurement
with a feature attached, and the design is not chosen until the measurement says which one to
build** — no cascade mode ships as default regardless of outcome (§8).

## 2. Invariant — binds every design

> A cheap-tier failure must degrade to the baseline (a full expensive review), never to less
> review than the baseline would have given.

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as today |

Router unavailable, timed out, crashed, out of context, unparseable, naming a unit not in the
range, or silently omitting a unit — all take the degrade path. No code path goes from "the
cheap tier had a problem" to "less review happened."

Designs differ in whether they carry an unrecoverable-miss class at all; that fact sets the ship
bar per design (§7.4), not a uniform bar.

## 3. Decision: measure-first (`decisionrule: measure-first`) — APPROVED

**Task 0** instruments expensive-tier reviews on a sample of fixtures and reports, per fixture (not
just as a mean), the split between:
- **E — exploration:** tool calls searching or reading outside the diff (grep, unchanged-file
  reads, call-site follows, test reads).
- **D — diff-reading and finding-writing.**

Reported as `E/(E+D)`. The design is picked by this pre-registered rule, decided before the number
is known:

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 | cheap-as-explorer (§3.1) |
| ≤ 0.30 | per-file routing (§3.4, control arm regardless — §3.4) |
| 0.30 – 0.60 | angle routing (§3.2) |

Angle routing is additionally evaluated, in all three branches, as a composable second stage: it
is orthogonal to the E/D ratio.

### 3.1 If cheap-as-explorer is selected

The cheap model builds a context bundle (call sites, related tests, invariants, prior art); the
expensive model reviews the whole diff with that bundle in its seed.

Its ship metric is **non-inferiority of end-to-end defect recall against the unaided expensive
panel on the same fixtures** — not context completeness. Reason: a partial bundle may anchor the
reviewer into exploring less, which context-completeness cannot detect but recall-against-baseline
does. Context completeness is retained only as a diagnostic for explaining a failure.

### 3.2 If angle routing is selected

Cheap handles angles whose judgement is local; expensive keeps angles needing whole-system context.
Implementation is a per-angle `AgentLaunch` instead of one shared launch. This design has no
unrecoverable-miss class — every angle is still reviewed by someone — so it is bar-classed as
baseline-degrading (§7.4). Which angles route where is decided from the per-angle recall data
gathered against the corpus (§5), not assumed from angle name.

### 3.3 Whole-change triage — narrow complement only, never the general design

Reason: one false-clean loses an entire change's review, the highest-stakes failure available. In
scope only as a conservative rule (not a model judgement) on near-certain cases — dependency
bumps, generated files, pure formatting.

### 3.4 Per-file routing — always run as a measured control arm

Kept in the run **regardless of which design §3's rule selects**, so the spec reports what it would
have cost and missed rather than assuming it away. It carries an unrecoverable-miss class (§7.4)
because a router judging a file in isolation cannot see relational defects — bugs visible only
from a call site, invariant, or test in a different file.

**Deliverable: empirical recall ceiling for per-file routing.** For every class-3 fixture (§5.1),
compare files the *fix* commit touched against files the *introducing* PR changed. A defect whose
fix lands outside the introducing diff is one no per-file router could have routed to. That
fraction is the ceiling, computed from real defects.

## 4. Corpus

### 4.1 Ground-truth classes — never pooled into one recall figure

| class | signal | what it proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change | same, bot-found |
| 3 | post-merge fix / revert / regression-fix of code a PR introduced | review MISSED it |

Class 2 requires the acceptance filter (a human author agreed and changed the code, not just "a
bot said so") and is reported separately from class 1.

### 4.2 Strata — every stratum probed by every router model (no "legs")

| stratum | source | visibility | classes carried |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific (§4.5) |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin — §4.3) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

Design is a full factorial: `router_model × stratum × class`.

### 4.3 Class 1/2 attribution — verification rules

- `commits == 1` disqualifies the PR (a single-commit PR cannot contain a comment-driven fix
  commit).
- A later commit in the same PR must touch the commented file (ideally the commented lines); how
  it was verified is recorded per fixture.
- Docs-only PRs excluded.
- `quite-app` has essentially no human review (13 human comments vs. 287 bot, in the last 300) and
  cannot carry class 1; neovim is what keeps class 1 off modular alone.
- Results reported per repo and per class; a thin cell is recorded as thin, never merged into a
  neighbour.

Fixture candidates for class 1/2: modular PR 94953 (26 comments, 9 files, 6 commits) is the primary
candidate; PR 94602 (13 comments, 71 files, 5 commits) is available if a large-diff fixture is
wanted.

### 4.4 Class 3 — harvest pipeline

1. Candidate fix commits: `git log -i --grep` for `revert|regression|broke` and kin.
2. `git blame` the lines the fix **deleted or replaced**, at `fix^`.
3. Require a single introducing commit; fan-out (non-clean attribution) is rejected.
4. That commit's PR at pre-merge state is the fixture; the fix commit's diff states the defect and
   location. Human-authored label, no invention.

Validated end-to-end on `quite-app` (fix `cb1adad` → `quited/qrun/src/sip_clone.rs` → blame
resolves to single commit `55b80032`). Harvesters report attrition at every stage (candidates →
single-attribution → adjudicated-as-defect).

### 4.5 Stratum D — scored as two stratified cells (`corpus: both-stratified`) — APPROVED

Source: `~/.local/share/drovr/runs/skill-stickiness/` — 376 per-angle findings files, 100 panels,
22 tasks; all 100 head SHAs and 22 base SHAs resolve from this worktree's shared object database.
131 blocking findings: 79 `.rs`, 51 `.md`, 1 `.json`.

`D-rs` (79 findings, Rust) and `D-md` (51 findings, prose) are measured and reported separately,
**never summed**. **The ship bar must pass on `D-rs` alone**; `D-md` is reported with its own
interval and cannot rescue a failing `D-rs`. Reason: reviewing Rust and reviewing prose are
different tasks a cheap tier could be good at one and useless at the other; pooling would hide
that. This was a reviewer decision against this spec's own recommendation (`rs-only`) — see §9.

Labels: *verified-real* (fix landed, or written up in `docs/known-issues.md`) is the only set that
feeds the bar; *unverified* is reported, not scored; *rejected* is excluded with the reason
recorded.

## 5. Data handling

**Qwen is self-hosted: no third-party egress, no restriction on which model reads which stratum.**
The prior egress constraint (and the two-legs structure it forced) is withdrawn.

**What is still enforced, unchanged:** `sauyon/drovr` is public; `modularml/modular` and
`quitesh/quite-app` are not. Private fixtures and probe transcripts live outside any checkout, at
`~/.local/share/drovr/cascade-corpus/`. Only aggregates (recall, precision, counts, analysis) are
committed to the repo — no diffs, no source excerpts, no file paths from the private repos, no
defect description detailed enough to reconstruct internal design.

**Interface: `provenance: Public | Private`**, assigned per fixture at harvest time from the source
repo's GitHub visibility (not a path convention). The write guard refuses to write
`Private`-derived content to any path resolving inside a git checkout, after canonicalisation
(closes the symlink-escape case). A fixture's body is reachable only through an accessor requiring
a token proving the destination was checked — the guard is a type-level property, not a call-site
check (shaped after `ReviewOutcome::EmptyRange`, `cli/src/code_review.rs:94`).

The write guard ships with tests in the same change, including the symlink-escape case. **Not
closed by this guard:** a human running an ad-hoc command outside the harness.

## 6. Measurement design

### 6.1 Arms

`router_model ∈ {qwen, sonnet}` × `stratum ∈ {D, M, Q, N}` × `class ∈ {1, 2, 3}`, plus per-file
routing as a control arm (§3.4) alongside whichever design §3 selects.

**The ship decision is per router model** — `router_agent` / `router_model` are separate config
keys (§8); a sonnet-routed cascade and a qwen-routed cascade ship independently.

### 6.2 Class 3 needs a second metric (`class3gate: gates-conditional`) — APPROVED

For classes 1, 2, and stratum D, the expensive tier found the defect by construction. Class-3
defects were missed by review, so the expensive tier may miss them too and a cheap tier cannot be
blamed for failing where the expensive tier would also fail.

- **Conditional recall** (of the class-3 defects the *expensive tier* finds, how many survive the
  cascade) is the number that gates.
- **Expensive-tier absolute detection rate on class 3** is reported, not gating.

### 6.3 Controls

- **NULL** (everything cleared, recall 0) and **FLOOD** (everything escalated, recall 1.0) bracket
  every stratum/class cell. A real cheap tier must land strictly inside the bracket on both axes,
  or those fixtures are rebuilt before anything is scored.
- **Positive control:** re-running the expensive tier on a sample must re-find recorded class-1/2
  defects at a high rate; if not, the corpus needs re-cutting, not the cheap tier.
- **Dev/held-out split** assigned before any cheap-tier prompt is written, at task/PR level (no
  diff in both). Held-out is scored **once**, after the prompt is frozen and its `git hash-object`
  recorded. There is no `blind-map.json` — the split is the load-bearing control against prompt
  overfitting, and scoring is set membership with no human judgement, so a blind map adds nothing.
  This is a deliberate departure from the prior protocol.

### 6.4 Ship bar (`barshape: by-failure-mode`) — APPROVED, non-uniform

- **Designs with an unrecoverable-miss class** (per-file, whole-change): recall ≥ 0.98 with Wilson
  95% LB ≥ 0.95, target N ≥ 142 per gated cell. Reason: a miss here is a defect nobody looks at
  again.
- **Designs whose failure degrades to baseline** (angle routing, cheap-as-explorer):
  non-inferiority against the unaided expensive panel, cascade recall LB ≥ 0.90 of the unaided
  panel's point estimate, target N ≥ 69. Reason: failure here is a cost regression, not a lost
  defect, so a 0.95 LB buys nothing real and costs a corpus (N = 142 vs. N = 69).

**Gate order:** 0. N floor met, else null for that cell. 1. Instrument discriminates (NULL/FLOOD
bracket, §6.3). 2. The recall bar above. 3. Escalation/skip rate leaves a real saving. 4. Measured
end-to-end cost < 0.80× the non-cascade panel. **Bars 1 and 2 are the ship decision.** Failing 3 or
4 ships the code behind its off-by-default flag with the negative economics written up. Precision,
hint quality, context completeness, and class-3 absolute detection are reported and are **not**
decision inputs.

**Pooling:** the gated number is pooled across **strata** within one `(model × class)` cell (24
per-stratum cells is not reachable at N ≥ 142 each); pooling across **classes** is never done
(§4.1). Per-stratum numbers are always reported alongside pooling, and if per-stratum recall is
more heterogeneous than sampling explains, the pooled figure is not reported as the headline — the
discrepant stratum is reported as the finding.

### 6.5 Freezing and ledger

- Stratum D and N fixtures are frozen by a MANIFEST in the shape of
  `docs/skill-evidence/arms/MANIFEST.md`: `git hash-object --no-filters` blob SHAs, a commit cell
  that must contain the blob at the recorded path, header-resolved columns, a test re-checking
  every row.
- Strata M and Q are frozen the same way in the private corpus directory; only row count and the
  manifest's digest are committed to the repo.
- Every cheap-tier invocation (retries included) is counted in an append-only ledger with
  per-stage ceilings, arithmetic checked by a test.

### 6.6 Stated limitations (reported with results, not decision inputs)

1. Corpus construction, not model access, is the largest limitation: every class is defined by a
   filter (comment→fix attribution, single-blame attribution, verified-real), and each filter
   selects a reachable subset of defects — class 3 keeps only cleanly-attributable defects (7 of 40
   candidates in the quite-app sample), which are plausibly the simpler ones. The measured ceiling
   may be optimistic in a direction no interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed entirely, which class 3 supplies.
4. Class 1 rests on modular and neovim only.

## 7. Configuration and cheap-tier execution

```toml
[review.cascade]
enabled = false            # DEFAULT, stays off in this run regardless of result
mode = "<undecided>"       # explorer | angle | file | change — set by Task 0 (§3), not before.
                            # No default ships until the measurement picks one.
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000        # expiry takes the degrade path of §2
```

The cheap tier runs **headless**, not as a herdr pane: `opencode run --agent plan -m <model>`.
Reason: every cold `opencode` reviewer pane swallows its seed and the panel cannot converge
(`docs/known-issues.md:3437`), so the pane path is closed for this backend; `opencode run` stdout
is a subprocess pipe, not the rendered terminal view `cli/src/code_review.rs:1` refuses to scrape.
Read-only is enforced via `--agent plan` with `--auto` absent, and `readonly_displace`
(`cli/src/config.rs:589`) runs first.

`ko-ag/qwen3.6-35b-abliterated` is an abliterated build (safety tuning removed) — recorded because
a writeup omitting it would describe a different experiment. Under every design in §3 its output is
either a routing decision or a context bundle, never a finding that reaches a verdict.

**Guard-with-artifact throughout:** every set this run extends — config keys, the `mode` enum, the
cheap tier's output vocabulary, ledger columns, MANIFEST rows, fixture list, the class enum — has
its guarding test extended in the same change.

## 8. Deliverables

1. Task 0 cost instrumentation and its report.
2. Relational-defect ceiling for per-file routing (§3.4).
3. Corpus harvesters (class 1/2 attribution, class 3 blame-back), each reporting attrition.
4. Fixtures + MANIFESTs; D and N committed, M and Q private.
5. `provenance` typing, write guard, tests.
6. Cheap-tier implementation for the selected mode plus the per-file control arm.
7. Cascade stage in `cli/src/code_review.rs`, behind `enabled = false`.
8. `docs/cascade-evidence/results.md`: controls, dev numbers, one held-out score per
   (model × stratum × class), each bar in order, ship decisions, §6.6 limitations, aggregates only.
9. Run ledger.

## 9. Scope boundaries

**Out, deliberately:** flipping the `enabled` default on; changing the angle set, severity model,
merge or resume path; a second measurement instrument; fixing `docs/known-issues.md:3437` (the
headless cheap tier routes around it — the pane bug stays open and documented); any tier between
qwen and opus.

## 10. Decisions — approved 2026-08-06, turn 1

| # | question | decision | where it binds |
|---|---|---|---|
| 1 | Unit of escalation | `measure-first` — Task 0 measures `E/(E+D)`, the pre-registered rule picks explorer / angle / per-file | §3 |
| 2 | Ship bar shape | `by-failure-mode` — 0.98 / LB ≥ 0.95 (N ≥ 142) where a miss is unrecoverable; non-inferiority at LB ≥ 0.90 (N ≥ 69) where failure degrades to baseline | §6.4 |
| 3 | Class 3's role | `gates-conditional` — gates on conditional recall against the expensive tier's finds; absolute detection is reported, not gating | §6.2 |

the decision that was made. No open questions remain.
