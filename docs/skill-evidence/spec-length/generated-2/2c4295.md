# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`

## 1. Scope

`drovr code-review run` currently spawns one reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), all on the same expensive model, over
the whole `base..head` range. This run measures where review cost actually goes, builds the
corpus and instrumentation to evaluate a cheap-tier cascade safely, and ships a cascade
implementation behind an off-by-default flag. The design of the cascade itself (which unit gets
routed to the cheap tier) is selected by measurement inside this run, not pre-chosen — see §3.

## 2. Binding invariant

> A cheap-tier failure must degrade to the baseline — a full expensive review — never to less
> review than the baseline would have given.

No code path exists from "the cheap tier had a problem" (unavailable, timed out, crashed, out of
context, unparseable, named a unit outside the range, or silently omitted a unit) to "less review
happened." Every design's failure mode is required to resolve against this invariant; §7.4's ship
bar is set by whether a given design can violate it at all (unrecoverable-miss designs vs.
degrades-to-baseline designs).

## 3. Cascade design: selected by measurement, not fixed in advance

**Decision (`decisionrule: measure-first`):** Task 0 instruments a sample of expensive-tier
reviews and reports the exploration-vs-diff-reading split, `E/(E+D)`:
- **E** — tool calls that search or read outside the diff (grep, unchanged-file reads, call-site
  follow, test reads).
- **D** — reading the diff, reasoning over it, composing findings.

Reported as `E/(E+D)` per fixture (distribution, not only a mean).

The design is picked by this pre-registered rule, run before the number is known:

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 | cheap-as-explorer (§3.1) |
| ≤ 0.30 | per-file routing (§3.4) |
| 0.30 – 0.60 | angle routing (§3.2) |

Angle routing (§3.2) is additionally evaluated as an orthogonal, composable second stage in all
three branches, regardless of which branch is primary.

Reason this rule exists rather than a chosen design: per-file routing only removes diff-reading
cost, not exploration cost, so if exploration dominates, per-file routing's saving is capped far
below what a cascade could achieve — the ratio determines which design is worth building at all.

### 3.1 Cheap tier as explorer / context-builder

The cheap model builds a context bundle (call sites, related tests, invariants, prior art); the
expensive model reviews the whole diff with that bundle in its seed. Nothing is skipped, so this
design has no unrecoverable-miss class — failure degrades to the expensive tier exploring for
itself.

**Ship metric: non-inferiority of end-to-end defect recall against the unaided expensive panel on
the same fixtures**, not context-bundle completeness. Reason: bundle completeness cannot detect
anchoring (a plausible-looking but incomplete bundle causing the expensive tier to explore less
than it would with no bundle at all), and anchoring is the failure mode that matters. Bundle
completeness is retained only as a diagnostic for explaining a failure.

### 3.2 Route by angle

Cheap handles angles whose judgement is local; expensive keeps angles needing whole-system
context. Implemented as a per-angle `AgentLaunch` instead of one shared launch. Has no
unrecoverable-miss class — every angle is still reviewed by someone. "Local judgement" per angle
is measured, not assumed, using stratum D's per-finding angle labels (§5.6).

### 3.3 Whole-change triage

Out of scope as a general mechanism (one false-clean loses an entire change's review — an
unrecoverable-miss class with the highest blast radius of any design). Retained only as a narrow,
conservative complement expressed as a fixed rule (not a model judgement) for near-certain cases:
dependency bumps, generated files, pure formatting.

### 3.4 Per-file routing — control arm

Run in every branch regardless of which design §3's rule selects, so the spec reports what
per-file routing would have cost and missed rather than assuming it away. Has an
unrecoverable-miss class: a router judging a file in isolation cannot see relational defects
visible only from a call site, invariant, or test in a different file.

**Deliverable:** the empirical recall ceiling for any per-file design — for every class-3 fixture
(§5.1), the fraction of defects whose fix commit lands outside the introducing PR's diff, i.e. no
per-file router could have routed to them.

## 4. Corpus

### 4.1 Ground-truth classes

| class | signal | proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change | same, bot-found |
| 3 | post-merge fix/revert/regression-fix of code a PR introduced | review MISSED it |

Never pooled into one recall figure — they measure different things (class 3 is defects that
slipped through entirely; classes 1/2 are, by construction, catchable ones). Class 2 requires
human-author acceptance of the bot comment (not just its existence) to avoid circularity with
"found by the kind of agent being tested"; reported separately from class 1 for a reader who
wants to discount it.

Class 1/2 attribution rules: a PR with `commits == 1` is disqualified (cannot contain a
comment-driven fix commit); a later commit in the same PR must touch the commented file; docs-only
PRs are excluded. How attribution was verified is recorded per fixture.

Class 3 pipeline: candidate fix commits found via `git log -i --grep` for
`revert|regression|broke`; `git blame` the lines the fix deleted/replaced at `fix^`; require a
**single** introducing commit (fan-out is rejected as not cleanly attributable); that commit's PR
at pre-merge state is the fixture, the fix commit's diff states the defect. No invented labels.

### 4.2 Strata

| stratum | source | visibility | classes carried |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific, §4.3 |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin — no meaningful human review volume) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

Every stratum is probed by every router model — model access is not a stratifying factor (§5). The
design is a full factorial `router_model × stratum × class`; there are no partial legs. Neovim is
included for corpus diversity (third language) and reproducibility (public, rebuildable off this
machine).

Reported per repo and per class; a thin cell (e.g. class 1 in Q) is reported as thin, never merged
into a neighboring cell.

### 4.3 Stratum D — scored as two stratified cells

**Decision (`corpus: both-stratified`):** `D-rs` (Rust-file findings) and `D-md` (prose/skill-file
findings) are measured and reported separately, never summed into one stratum-D number. **The
ship bar must pass on `D-rs` alone**; `D-md` is reported with its own interval and cannot rescue a
failing `D-rs`. Reason: reviewing Rust and reviewing prose are different tasks a cheap tier could
plausibly be good at one and useless at the other — pooling would hide that.

Source: `~/.local/share/drovr/runs/skill-stickiness/` — 376 per-angle findings files across 100
panels over 22 tasks, all 100 head SHAs and 22 base SHAs resolved from this worktree's shared
object database. 131 blocking findings (79 `.rs`, 51 `.md`, 1 `.json`) over 20 tasks, carrying
their angle (this is what makes §3.2's per-angle premise testable).

Labels: *verified-real* (fix landed, or written up in `docs/known-issues.md`) — the only set that
feeds the ship bar; *unverified* — reported, not scored; *rejected* — excluded, reason recorded.

## 5. Data handling

**Decision:** Qwen is self-hosted — there is no third-party egress, and no restriction on which
model may read which stratum. This withdraws the earlier egress-based two-legs structure in full.

What survives (this was always about publishing, not about which model reads what): `sauyon/drovr`
is public; `modularml/modular` and `quitesh/quite-app` are not. Private fixtures and probe
transcripts live outside any checkout, at `~/.local/share/drovr/cascade-corpus/`. Only aggregates
(recall, precision, counts, analysis) are committed — no diffs, no source excerpts, no file paths
from private repos, no defect description detailed enough to reconstruct internal design.

**Contract — write guard.** Every fixture carries `provenance: Public | Private`, assigned at
harvest time from the source repo's GitHub visibility (not a path convention, not recollection).
The write guard refuses to write `Private`-derived content to any path resolving inside a git
checkout, after canonicalisation, so a symlink out of the corpus directory and back into the repo
does not defeat it. A fixture's body is reachable only through an accessor requiring a token
proving the destination was checked — the illegal state is made unrepresentable, following the
`ReviewOutcome::EmptyRange` precedent (`cli/src/code_review.rs:94`) where a single call-site guard
left the state representable for the next caller. The write guard ships with tests in the same
change, including the symlink-escape case, per §7's guard-with-artifact rule. Not covered: a human
running an ad-hoc command outside the harness.

The prior egress guard is withdrawn with its premise; `provenance` keeps its one remaining
consumer (the write guard) rather than serving two purposes with one vestigial.

## 6. The measurement

### 6.1 Arms

`router_model ∈ {qwen, sonnet}` × `stratum ∈ {D, M, Q, N}` × `class ∈ {1, 2, 3}`, with the primary
design fixed by §3's rule and per-file routing (§3.4) run as a control arm alongside in every case.

**Contract:** the ship decision is per router model. `router_agent` and `router_model` are
separate config keys (§8) — a sonnet-routed cascade is a different product from a qwen-routed one
and is shipped/not-shipped independently.

### 6.2 Class 3 metric

**Decision (`class3gate: gates-conditional`):** class-3 defects were missed by the expensive tier
by definition of the class, so a cheap tier cannot be faulted for missing what the expensive tier
would also miss. Two numbers are reported:
- **Conditional recall** (gates) — of the class-3 defects the expensive tier finds, how many
  survive the cascade.
- **Expensive-tier absolute detection rate on class 3** (does not gate) — fraction of
  review-missed defects the full panel finds at all; reported as the run's scientific output on
  the review system's ceiling.

### 6.3 Discrimination and controls

Two synthetic controls bracket the metric, both free: NULL (everything cleared — recall 0, saving
maximal) and FLOOD (everything escalated — recall 1.0, saving 0). Per stratum and per class, a
real cheap tier must land strictly inside the bracket on both axes, or those fixtures are rebuilt
before anything is scored. Reason this check exists: the prior run's instrument did not
discriminate — unaided agents scored 3/4 and 4/4 with no skill applied at all.

**Positive control:** re-running the expensive tier on a sample must re-find recorded class-1/2
defects at a high rate; if not, the corpus needs re-cutting, not the cheap tier.

**Contract — dev/held-out split.** Assigned before any cheap-tier prompt is written, at task/PR
level so no diff appears in both splits. Held-out is scored exactly once, after the prompt is
frozen and its `git hash-object` recorded. There is no `blind-map.json` — the threat model here is
prompt overfitting (scoring is set membership with no human judgement, so scorer bias is not a
threat), and the split alone controls for it. This is a deliberate departure from the prior
protocol.

### 6.4 Ship bar — non-uniform by failure mode

**Decision (`barshape: by-failure-mode`):**
- **Designs with an unrecoverable-miss class** (per-file routing, whole-change triage): recall ≥
  0.98 with Wilson 95% LB ≥ 0.95, target N ≥ 142 per gated cell. Reason: a miss here is a defect
  nobody ever looks at again, so the bar is set as high as N can afford.
- **Designs whose failure degrades to baseline** (angle routing, cheap-as-explorer):
  non-inferiority against the unaided expensive panel, cascade recall LB ≥ 0.90 of the unaided
  panel's point estimate, target N ≥ 69. Reason: failure here is a cost regression, not a lost
  defect (the expensive tier still reviews everything), so demanding LB ≥ 0.95 buys nothing real
  and costs a corpus that isn't warranted.

No bar above LB ≥ 0.95 is used for any design: the corpus cost of a tighter interval (N = 239 for
LB ≥ 0.97) is worse-spent than on a fourth stratum, since real uncertainty here is dominated by
corpus-construction choices (§7), not sampling error.

**Contract — N pooling.** `N ≥ 142` per full `(model × stratum × class)` cell is 24 cells and not
reachable. The floor applies to the gated number pooled across **strata** within one
`(model × class)` — pooling across classes is forbidden (§4.1: different classes measure different
things). Per-stratum numbers are always reported alongside; if per-stratum recall is more
heterogeneous than sampling explains, the pooled figure is not reported as the headline and the
discrepant stratum is reported as its own finding.

**Contract — gate order.** Evaluated in order per gated cell: **0.** N floor met, else null for
that cell. **1.** Instrument discriminates (§6.3). **2.** The recall bar above. **3.**
Escalation/skip rate leaves a real saving. **4.** Measured end-to-end cost < 0.80× the non-cascade
panel.

Bars 1 and 2 are the ship decision. Failing 3 or 4 ships the code behind its off-by-default flag
with the negative economics written up. Precision, hint quality, context completeness, and class-3
absolute detection are reported and are not decision inputs.

**Contract — freezing.** Strata D and N: frozen by a MANIFEST in the shape of
`docs/skill-evidence/arms/MANIFEST.md` — `git hash-object --no-filters` blob SHAs, a commit cell
that must contain the blob at the recorded path, header-resolved columns, a test re-checking every
row. Strata M and Q: frozen the same way in the private corpus directory, with only the row count
and the manifest's digest committed publicly.

**Contract — ledger.** Every cheap-tier invocation is counted in an append-only ledger with
per-stage ceilings; arithmetic checked by a test. Retries count.

## 7. Guard-with-artifact

Every set this run extends — config keys, the `mode` enum, the cheap tier's output vocabulary,
ledger columns, MANIFEST rows, fixture list, the class enum — ships its guarding test in the same
change that extends it. No exceptions.

```toml
[review.cascade]
enabled = false            # default; stays off in this run regardless of measured result
mode = "<set by Task 0>"   # explorer | angle | file | change — value comes from §3's
                            # pre-registered decision rule applied to Task 0's measured E/(E+D);
                            # no design is hardcoded ahead of that measurement.
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000        # expiry takes the degrade path of §2
```

**Contract — cheap-tier execution.** Headless, not a herdr pane: `opencode run --agent plan -m
<model>`. Read-only via `--agent plan` with `--auto` absent; `readonly_displace`
(`cli/src/config.rs:589`) runs first. Reason headless, not a pane: a cold `opencode` reviewer pane
swallows its seed and the panel cannot converge (`docs/known-issues.md:3437`), so the pane path is
closed for this backend; `opencode run` writes to a subprocess pipe, which is not the rendered
terminal view `cli/src/code_review.rs:1` refuses to scrape.

`ko-ag/qwen3.6-35b-abliterated` is an abliterated build (safety tuning removed); recorded because
omitting it would describe a different experiment. Under every design in §3 its output is either a
routing decision or a context bundle, never a finding that reaches a verdict.

## 9. Deliverables

1. Task 0 cost instrumentation and its report.
2. Relational-defect ceiling for per-file routing (§3.4).
3. Corpus harvesters — class 1/2 attribution, class 3 blame-back — each reporting attrition.
4. Fixtures + MANIFESTs; D and N committed, M and Q private.
5. `provenance` typing, write guard, tests (§5).
6. Cheap-tier implementation for the selected mode, plus the per-file control arm.
7. Cascade stage in `cli/src/code_review.rs`, behind `enabled = false`.
8. `docs/cascade-evidence/results.md` — controls, dev numbers, one held-out score per
   `(model × stratum × class)`, each bar in order, ship decisions, limitations (§10), aggregates
   only.
9. Run ledger.

## 10. Stated limitations

1. Corpus construction, not model access, is now the largest limitation: every class is defined by
   a filter (comment→fix attribution, single-blame attribution, verified-real), and each filter
   selects a reachable subset of defects. Class 3 keeps only cleanly-attributable defects (7 of 40
   candidates sampled in quite-app), which are plausibly the simpler ones — the measured ceiling
   may be optimistic in a direction no interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never an absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed entirely, which only class 3 supplies.
4. Class 1 rests on modular and neovim only — quite-app has essentially no human review.

## 11. Out of scope

- Flipping `enabled` to `true` by default.
- Changing the angle set, severity model, or the merge/resume path.
- A second measurement instrument beyond this run's.
- Fixing `docs/known-issues.md:3437` (the headless cheap tier routes around it; the pane bug stays
  open and documented).
- Any tier between qwen and opus.
