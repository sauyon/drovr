# Tiered (cascade) code review for drovr — spec

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`

## Problem this run addresses

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), all on the same expensive model, over
the whole `base..head` range, unconditionally re-running the panel on top of whatever the author
already ran (`docs/known-issues.md:589`). A cheap-first cascade is the obvious cost saving and the
obvious way to ship a silent quality regression, because a cheap tier's false negative is
unrecoverable by default: nothing downstream re-checks what the cheap tier waved through, and a
resulting `Clean` is byte-identical to a real one. This run is a measurement with a feature
attached, not a feature with a measurement attached.

## Decisions

### 1. Unit of escalation — `measure-first`

Chosen before Task 0's number is known, because that is the only time it can honestly be chosen.
Task 0 instruments expensive-tier reviews on a fixture sample and reports the exploration/diff-read
split as `E/(E+D)` (tokens and wall-clock, per-fixture distribution, not just a mean). The measured
ratio picks the primary design:

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 (exploration dominates) | cheap-as-explorer |
| ≤ 0.30 (diff-reading dominates) | per-file routing |
| 0.30–0.60 | angle routing (insensitive to the ratio) |

**Reason:** the human's challenge — most review cost is exploration, not diff-reading — determines
which design's savings are real; committing to a design before measuring it would assume the
answer. Angle routing is additionally run as a composable second stage in all three branches: it is
orthogonal to the primary design and its value doesn't depend on the ratio.

Per-file routing is retained as a measured **control arm** regardless of which design wins, so the
spec reports what it would have cost and missed rather than assuming it away. Whole-change triage
(skip review of a whole change) is out as a general mechanism — one false-clean loses an entire
change's review — and is retained only as a narrow, conservative, rule-based (not model-judgement)
complement for near-certain cases (dependency bumps, generated files, pure formatting).

### 2. Ship bar shape — `by-failure-mode`

The bar is not uniform across designs. **Reason:** designs differ in whether a cheap-tier miss is
recoverable, and a uniform bar either wastes corpus on designs that don't need it or under-protects
the ones that do.

- **Designs with an unrecoverable-miss class** (per-file, whole-change): a miss is a defect nobody
  ever looks at again. Bar: recall ≥ 0.98 with Wilson 95% lower bound ≥ 0.95, target N ≥ 142 per
  gated cell.
- **Designs whose failure degrades to baseline** (angle routing, cheap-as-explorer): failure is a
  cost regression, not a lost defect, since the expensive tier still reviews everything. Bar:
  non-inferiority against the unaided expensive panel, cascade recall lower bound ≥ 0.90 of the
  unaided panel's point estimate, target N ≥ 69.

Not going higher than 0.95 LB for unrecoverable designs: N = 239 for LB ≥ 0.97 buys a 0.02 tighter
bound dominated by corpus-construction uncertainty (see Limitations), not sampling error.

Gate order, evaluated in sequence: **0.** N floor met, else null result for that cell. **1.**
Instrument discriminates (see NULL/FLOOD below). **2.** Recall bar above. **3.** Escalation/skip
rate leaves a real saving. **4.** Measured end-to-end cost < 0.80× the non-cascade panel. Bars 1–2
are the ship decision; failing 3 or 4 ships the code behind `enabled = false` with the negative
economics written up. Precision, hint quality, context completeness, and class-3 absolute detection
are reported but are not decision inputs.

**N is pooled across strata within one `(model × class)`**, not per `(model × stratum × class)` —
`N ≥ 142` per full cell would require 24 cells and is unreachable. **Reason:** pooling across strata
buys statistical power without destroying meaning (unlike pooling across classes, which §5.1
forbids because classes differ in difficulty/meaning). Per-stratum numbers are always reported
alongside; if per-stratum recall is more heterogeneous than sampling explains, the pooled figure is
not reported as the headline and the discrepant stratum is called out as a finding.

### 3. Class 3's role — `gates-conditional`

Class-3 defects (post-merge fix/revert of code a PR introduced) were missed by review by
definition, so the expensive tier may miss them too — a cheap tier can't fairly be blamed for
missing what the expensive tier would also miss. Two metrics, reported separately:

- **Conditional recall** (gates): of the class-3 defects the expensive tier finds, how many survive
  the cascade.
- **Expensive-tier absolute detection rate on class 3** (does not gate): what fraction of
  review-missed defects the full panel finds at all — reported as the run's most interesting
  scientific output, not as a decision input.

### 4. Stratum D scope — `both-stratified`

Stratum D (drovr's own `skill-stickiness` findings) is scored as two separate cells, `D-rs` (79
blocking `.rs` findings pre-filter) and `D-md` (51 `.md`/prose findings), never summed. **The ship
bar must pass on `D-rs` alone**; `D-md` is reported with its own interval and cannot rescue a
failing `D-rs`. **Reason:** reviewing Rust and reviewing prose are different tasks a cheap tier
could plausibly be good at one and useless at the other; pooling would hide that, and dropping
`.md` would forgo a free check of whether cheap-tier competence is domain-shaped. This decision was
made against this spec's own `rs-only` recommendation — the interview reviewer chose the stricter,
two-cell option.

All four decisions above were approved at the 2026-08-06 gate, turn 1, with no free-text feedback or
block annotations. They are binding on the plan phase, which does not re-litigate them. No open
questions remain from this gate; anything the plan phase discovers outside their scope is a new
question for a new gate.

### Other approved/settled points

- **Egress constraint withdrawn.** Qwen is self-hosted; there is no third-party egress and no
  restriction on which model may read which stratum. This removes the earlier two-legs structure
  and the qwen-on-real-traffic gap entirely (it is not carried forward as a limitation).
  Publication visibility is unchanged and is a separate concern (see Data handling below).
- **Neovim (stratum N) included.** Justified on corpus diversity and reproducibility — a third
  language/codebase, publicly rebuildable off this machine — not as a workaround for any access
  constraint. Selected over `ghostty-org/ghostty` (33 inline comments per 40 merged PRs vs.
  ghostty's 9 per 40).
- **Dev/held-out split, no `blind-map.json`.** Split assigned before any cheap-tier prompt is
  written, at task/PR level so no diff appears in both; held-out is scored once, after the prompt is
  frozen and its `git hash-object` recorded. **Reason:** the threat model here is prompt overfitting,
  not scorer bias (scoring is set membership, no human judgement), so the split alone is the
  load-bearing control — a blind map is unneeded ceremony carried from a prior protocol and is
  deliberately dropped.
- **Discrimination controls.** NULL (everything cleared: recall 0, saving maximal) and FLOOD
  (everything escalated: recall 1.0, saving 0) bracket every stratum/class cell; a real cheap tier
  must land strictly inside on both axes or those fixtures are rebuilt before scoring. Positive
  control: the expensive tier re-run on a sample must re-find recorded class-1/2 defects at a high
  rate, or the fixtures (not the cheap tier) are re-cut.

## Interfaces and contracts

### Configuration (`[review.cascade]`)

```toml
[review.cascade]
enabled = false            # stays off in this run regardless of measured result
mode = "<undecided>"       # explorer | angle | file | change — set by Task 0 (decision 1), not before
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000       # expiry takes the degrade path (see invariant below)
```

`router_agent`/`router_model` are config keys distinct from the expensive-tier agent/model, because
the ship decision is per router model — a sonnet-routed cascade and a qwen-routed cascade are
evaluated, and may ship, independently.

### The degrade invariant (binds every design in §4 of the source notes)

A cheap-tier failure must degrade to the baseline (a full expensive review) — never to less review
than the baseline would have given. Router unavailable, timed out, crashed, out of context,
unparseable, naming a unit not in the range, or silently omitting a unit: every one of these takes
the degrade path. Per design:

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as it does today |

### Cheap tier execution contract

Runs headless, never as a herdr pane: `opencode run --agent plan -m <model>`, read-only via
`--agent plan` with `--auto` absent; `readonly_displace` (`cli/src/config.rs:589`) runs first.
**Reason:** every cold `opencode` reviewer pane swallows its seed and the panel fails to converge
(`docs/known-issues.md:3437`); `opencode run` stdout is a subprocess pipe rather than the rendered
terminal view `cli/src/code_review.rs:1` refuses to scrape, so the pane path is closed for this
backend and the headless path routes around the open bug rather than fixing it.

Cheap-as-explorer's output is a context bundle; angle/file/change routing's output is a routing
decision. Under every design, the cheap tier's output is either a routing decision or a context
bundle — **never a finding that reaches a verdict** — noted explicitly because
`ko-ag/qwen3.6-35b-abliterated` is an abliterated (safety-tuning-removed) build, and that fact must
be recorded rather than omitted.

### Cheap-as-explorer ship metric

Non-inferiority of end-to-end defect recall against the unaided expensive panel on the same
fixtures. **Reason:** "the expensive tier will notice a gap and explore further" is a hypothesis,
not a guaranteed property — a partial bundle could equally anchor the reviewer into exploring less
— so completeness of the bundle cannot be the bar; only measured recall can. Context completeness
(did the bundle contain the file/symbol a defect required) is retained only as a diagnostic for
explaining a failure, not as the ship metric.

### Per-file routing's measured ceiling

For every class-3 fixture, the files the fix commit touched are compared against the files the
introducing PR changed; a defect whose fix lands outside the introducing diff is one no per-file
router could have routed correctly. This fraction is computed and reported as the empirical recall
ceiling for any per-file design — a required deliverable, not optional context.

### Data handling and provenance typing

- `sauyon/drovr` is public; `modularml/modular` and `quitesh/quite-app` are private. Private
  fixtures and probe transcripts live outside any checkout, at `~/.local/share/drovr/cascade-corpus/`.
  Only aggregates (recall, precision, counts, analysis) are committed for private strata — no diffs,
  source excerpts, file paths, or defect descriptions detailed enough to reconstruct internal design.
- Every fixture carries a `provenance: Public | Private` field, assigned at harvest time from the
  source repo's GitHub visibility (not from path convention or recollection).
- **Write guard:** refuses to write `Private`-derived content to any path resolving inside a git
  checkout, after canonicalisation (so a symlink escape doesn't defeat it). Shaped after
  `ReviewOutcome::EmptyRange` (`cli/src/code_review.rs:94`): a fixture's body is reachable only
  through an accessor requiring a token proving the destination was checked, rather than a guard at
  one call site that leaves the illegal state representable elsewhere. Ships with tests in the same
  change, including the symlink-escape case.
- `provenance` has a single consumer (the write guard) now that the egress guard is withdrawn with
  its premise — accepted as better than one field serving two purposes with one vestigial.
- Not closed by this run: a human running an ad-hoc command outside the harness can still leak
  private content; this is a stated limitation, not a guarded case.

### Corpus contracts

- Ground-truth classes (never pooled into one recall figure): **1** — human review comment that
  caused a same-PR change; **2** — bot review comment that caused a same-PR change *and* was
  accepted by a human author (the acceptance filter is what makes this admissible despite being
  bot-found); **3** — post-merge fix/revert/regression-fix of code the PR introduced (review missed
  it).
- Class 1/2 attribution rules: a PR with `commits == 1` is disqualified (cannot contain a
  comment-driven fix commit); a later commit in the same PR must touch the commented file (ideally
  the commented lines), with the verification method recorded per fixture; docs-only PRs excluded.
- Class 3 pipeline: candidate fix commits found via `git log -i --grep` for
  `revert|regression|broke` and kin; `git blame` the lines the fix deleted/replaced at `fix^`;
  require a single introducing commit (fan-out is rejected as not cleanly attributable); that
  commit's PR at pre-merge state is the fixture, the fix commit's diff states the defect. Attrition
  is reported at every stage (candidates → single-attribution → adjudicated-as-defect).
- Strata: `router_model × stratum × class` is a full factorial — every stratum (D, M, Q, N) is
  probed by every router model, since model access is no longer a stratifying factor once the
  egress constraint is withdrawn. Results are reported per repo and per class; a thin cell (e.g.
  `quite-app` class 1, which has essentially no human review) is reported as thin, never merged into
  a neighbour.
- Freezing: stratum D and N fixtures frozen by a MANIFEST in the shape of
  `docs/skill-evidence/arms/MANIFEST.md` (`git hash-object --no-filters` blob SHAs, a commit cell
  containing the blob at the recorded path, header-resolved columns, a test re-checking every row).
  Strata M and Q are frozen the same way in the private corpus directory, with only the row count
  and manifest digest committed publicly.
- Ledger: every cheap-tier invocation (retries included) counted in an append-only ledger with
  per-stage ceilings, arithmetic checked by a test.
- Guard-with-artifact: every set this run extends (config keys, the `mode` enum, the cheap tier's
  output vocabulary, ledger columns, MANIFEST rows, fixture list, the class enum) ships its guarding
  test extended in the same change.

## Deliverables

1. Task 0 cost instrumentation and its report.
2. Relational-defect recall ceiling for per-file routing.
3. Corpus harvesters (class 1/2 attribution, class 3 blame-back), each reporting attrition.
4. Fixtures + MANIFESTs; D and N committed publicly, M and Q private.
5. `provenance` typing, write guard, and tests.
6. Cheap-tier implementation for the selected mode (per decision 1) plus the per-file control arm.
7. Cascade stage in `cli/src/code_review.rs`, shipped behind `enabled = false`.
8. `docs/cascade-evidence/results.md`: controls, dev numbers, one held-out score per
   (model × stratum × class), each gate's result in order, ship decisions, stated limitations,
   aggregates only (no private-repo detail).
9. Run ledger.

## Out of scope

- Flipping `enabled` to true by default.
- Changing the angle set, severity model, or the merge/resume path.
- A second measurement instrument beyond this run's.
- Fixing the `opencode` cold-pane seed bug (`docs/known-issues.md:3437`) — this run routes around it
  via the headless path; the pane bug stays open and documented, not fixed.
- Any tier between qwen and opus.
- Whole-change triage as a general mechanism (retained only as the narrow rule-based complement
  described under decision 1).

## Stated limitations (carried into the results writeup, not resolved by this run)

1. Corpus construction, not model access, is now the largest limitation: every class is defined by a
   filter (comment→fix attribution, single-blame attribution, verified-real), each filter selects a
   reachable subset of defects, and class 3 in particular keeps only cleanly-attributable defects
   (7 of 40 candidates in the `quite-app` sample) — plausibly the simpler ones, so the measured
   ceiling may be optimistic in a direction no confidence interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never an absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted" — both miss what review missed entirely, which only class 3 supplies.
4. Class 1 rests on modular and neovim only (`quite-app` has essentially no human review: 13 human
   comments of 300 sampled, versus 287 bot).
5. The write guard does not close a human running an ad-hoc command outside the harness.
