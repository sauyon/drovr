# Spec: skill stickiness

Make drovr's skill docs bind under context pressure instead of merely describing correct
practice. Five fixes, one new meta-skill, and an empirical acceptance test.

---

## 0. Build order

Section numbers are not the build order.

1. `drovr:writing-skills` + the scenario corpus (§6.1, §6.2) — nothing else can be tested until
   the harness exists.
2. Capture arm A / RED per skill (§6.3), at the pre-fix `HEAD`, before any skill file is touched.
   Hard gate: once fix 1 lands, arm A is unrecoverable without a checkout.
3. Fixes 1 + 3 (§2, §4).
4. Fix 4 (§5), using the RED wording from step 2 for the rationalization tables.
5. Held-out arm B + the voice probe (§6.3, §6.4).
6. Fix 2's hook layer (§3.2) — independently orderable, no dependency on steps 1–5. Fix 2's doc
   layer (§3.1) belongs with step 4.

## 1. Authoring rules (bind every later decision in this spec)

**Four-tier precedence**, applied to every claim and every design choice below:

1. Published evidence exists → the evidence decides; the citation stays with the claim.
2. No published evidence, but the question is reachable by this run's loop (expressible as a text
   variant of an existing probe skill, scorable by the existing rubric, within the §6.3 budget
   ceiling) → measured in §6.4. Cost may discharge this obligation only when measurement would
   exceed the ceiling, never because it seems not worth it.
3. Not reachable, or the measurement is inconclusive, and superpowers has a convention → follow
   superpowers; marked as a convention-follow, not evidence-backed.
4. No superpowers analogue → engineering judgement, marked **[tier 4]**. Applies to: the gate's
   byte budget, the card length, the `per_turn` default, the reflex-marker boundary, the probe's
   model choice, the §1 length caps. None of these may be defended as evidence-backed.

Every tier-2/3/4 item in this spec carries its tier marker at the point of decision.

**Two standing exceptions:**

1. **No fabricated measurements.** drovr states a number, duration, frequency, or comparative only
   if drovr measured it or a citation supports it. `docs/skill-evidence/` is the only source of
   drovr-measured numbers.
2. **No copied text.** Both projects are MIT; drovr still writes its own sentences — mechanisms
   are ported from superpowers, expression is drovr's. Any verbatim line found in review gets the
   MIT notice and credit added.

### 1.1 Voice devices — adopted

| Device | Countering | Tier |
|---|---|---|
| Iron Law — one fenced, all-caps line | Case-by-case renegotiation | 3 |
| Spirit-vs-letter line, before the rules | "I'm honoring the intent differently" | 3 |
| Unity line — *the next phase agent is you, with your context gone* | Detachment from downstream cost | prior (§1.2), measured in §6.4 |
| Announcement string; checklist→task binding | Silent skipping | evidence-backed (commitment, §1.2) |
| Rationalization table (thought → reality, reality as instruction) | Excuses observed in RED | 3 |
| Red flags — inner-monologue fragments | Mid-drift self-detection | 3 |
| "No exceptions" bullets, each pairing prohibition with required action | Partial compliance | 3 |
| Claim → required evidence → not sufficient table | Evidence substitution | 3 |
| Numeric escalation trigger (after 3 failed fixes, stop) | Thrash loops | 3 |
| ✅/❌ paired utterances | Ambiguity about compliance | 3 |
| Top-loading binding content; restating near point of use | Decay under load | 3, prior in §1.2 |

**Register (authority `MUST`/`NEVER` vs. plain vs. moral framing) and unity are tier 2** — no
published study isolates them for procedural adherence, and both are reachable by the probe. They
are measured in §6.4; superpowers' full register is the tier-3 fallback if inconclusive.

**Social proof** ships only in its true form — naming a failure mode actually observed in
`docs/skill-evidence/` — never in an invented-frequency form ("every time"); exception 1 forbids
the latter.

**Flowcharts** — adopted **[tier 3]**, not reachable by the probe (changes document structure, not
a text register). Placement rule, ported from superpowers: fenced `dot` blocks for genuine
branching and for loops where an agent might stop too early — never for linear instructions or
reference. Applies to: `using-drovr`'s gate function (§3.1), the RED/GREEN/REFACTOR loop (§6.1),
`drovr:tdd`'s red-green-refactor cycle, and `systematic-debugging`'s loop. All other discipline
procedures stay numbered lists.

**Rendering fenced `dot` blocks in the review UI, and pairing a graph with the plan as a progress
display, is out of scope** (§7) — a human-facing product judgement **[tier 4]** with no
superpowers analogue. Filed as a follow-up in `docs/known-issues.md` under `## Resolved`-adjacent
follow-ups: *render fenced `dot` blocks in the review UI and show the phase/gate graph alongside
the plan.*

### 1.2 Evidence backing the above (cited per exception 1 / tier-1 rule)

- Commitment ranks top-two in both Meincke studies — the strongest-evidenced lever here. Promoted
  to primary via the announcement string and checklist→task binding (fixes 3, 4). (Meincke et al.
  2025; Meincke et al. 2026 — full citations in §9.)
- Unity ranks top-two in the 2026 replication, above authority; superpowers withholds it from
  discipline skills on the older 2025 ranking. drovr applies unity to discipline skills as a
  deviation backed by the newer data. Same paper gives authority no procedural-adherence isolation,
  so unity gets no stronger standing than authority — both stay tier 2, measured in §6.4.
- Liu et al., *Lost in the Middle*: retrieval accuracy by gold-document position is U-shaped
  (highest at start/end, lowest mid-document), on 2023-vintage models measuring document
  retrieval, not mid-document instruction obedience. Basis for top-loading binding content (§5),
  not proof mid-document rules are ignored.
- Persuasion effects shrink on newer/smaller models (Meincke 2025: 33.3%→72.0% on GPT-4o-mini;
  Meincke 2026 replication on Claude Haiku 4.5 / GPT-5 mini / Gemini 3 Flash: 35.3%→51.3%). None of
  the tested models are the ones drovr runs (probes use Sonnet, §6.3; sessions run Opus-class).
  Extrapolating Haiku/mini/Flash → Sonnet/Opus is a stated assumption **[tier 4]**, not a finding.
  Register is treated as a real but secondary lever on that assumption.
- Anthropic's prompting guidance: tell Claude what to do instead of what not to do, and give the
  reason. Applied: every prohibition pairs with the required action in the same breath; every rule
  carries its why; rationalization-table counters read as instructions, not rebuttals.
- Generic "helpful assistant" rule wrappers are non-monotonic (arXiv:2601.22025, n=50: extraction
  100%→90%, RAG compliance 93.3%→80%, but instruction-following +13%). Read as: keep the per-turn
  card (§3.2) short and drovr-specific; do not claim to know its net effect.
- Load-degradation figures (−2–21% formatting compliance under concurrent load, recovered
  90–100% by salience-enhanced prompting) come from secondary summaries not read in full. Not
  load-bearing for any decision; not quoted as a measured number anywhere in shipped skills
  (exception 1).
- EmotionPrompt/moral-framing null does not settle procedural adherence (it measures benchmark
  accuracy under emotional stimuli, not rule-violation framing) — moral vocabulary therefore stays
  tier 2 rather than being rejected outright, measured in §6.4 alongside authority and unity.

## 3. Fix 2 — make `using-drovr` a per-turn gate

### 3.1 Doc layer (`skills/using-drovr/SKILL.md`)

New content, in this order (position per §1.2's U-shape finding — early and late positions
favored). Items 2 and 4 are **[tier 3]** convention-follows, structurally close to
`using-superpowers/SKILL.md:11-29`; wording is drovr's own.

1. `<SUBAGENT-STOP>` — kept as-is (`:8-11`).
2. **The 1% rule**, above the H1, inside the existing `<EXTREMELY_IMPORTANT>` framing: even a 1%
   chance a drovr skill applies means invoke it. Paired with a cost-lowering clause: if it turns
   out not to fit, drop it — invoking costs almost nothing.
3. **The per-turn rule**: check before any response, including before a clarifying question and
   before any read-only exploration.
4. **Instruction-priority ladder** — human's explicit instructions > drovr skills > default
   behaviour. Non-optional safety counterweight to the MUST language.
5. **Gate function**, fenced `dot` flowchart: message received → does any skill apply (≥1%) →
   invoke → announce → does it have a checklist → create one tracked item per step → follow it →
   only then respond.
6. **Red-flag table for the router's own failure mode** (invoking nothing at all — currently zero
   coverage). Candidate rows: *"this is a one-line change"*, *"I'll just look at the file first"*,
   *"they asked a question, not for work"*, *"I'm already mid-task, the router was for turn one"*,
   *"escalating to a phase would be overkill so no skill applies"*. Final wording is set by RED
   (§6), not this list.
7. Existing sections (single-writer, always-review, methodology, escalation) retained unchanged.

**Placement contract:** items 2–5 sit outside every `<!-- reflex:section:NAME -->` marker
**[tier 4]**. `[reflex.sections]` may subtract advisory sections but must not silently delete the
routing core; only `[reflex] enabled = false` removes it.

### 3.2 Hook layer (new `UserPromptSubmit` hook)

Every decision in this subsection is **[tier 4]** — superpowers is `SessionStart`-only, no
convention or study covers per-turn re-injection. Ships as an explicit unmeasured bet, recorded in
`docs/skill-evidence/per-turn-gate.md`.

- `hooks/hooks.json` gains a `UserPromptSubmit` entry running a thin `hooks/user-prompt` script
  that `exec`s `drovr reflex --gate`. `UserPromptSubmit` takes **no `matcher`** — the existing
  `SessionStart` entry's `startup|clear|compact` matcher must not be copied across.
- **Budget:** ≤600 bytes per injection; cumulative ceiling ~60 KB over a 100-turn session
  (`additionalContext` is appended every turn and stays in the window).
- **Suppression rule:** the card is emitted only when no `drovr:*` skill was invoked in the
  previous turn. Bounds the common case to a handful of injections.
- **Byte budget, not tokens** — the CLI has no tokenizer. Assertion: rendered `additionalContext`
  ≤ 600 bytes, checked in `cli/src/reflex.rs`'s test module.
- **Card content:** the 1% rule, the per-turn check, the announcement string, the
  checklist-binding line, a `<SUBAGENT-STOP>` line, and a pointer to `Skill drovr:using-drovr`.
- **API changes required** (verified against source):
  1. `reflex.rs:143-152`'s `envelope()` hardcodes `"hookEventName": "SessionStart"` — parameterize
     to take the event name.
  2. `main.rs:114-118` declares `Reflex { skill: PathBuf }` as required; `main.rs:1276-1278`
     asserts bare `drovr reflex` errors. Adding `--gate` forces `Option<PathBuf>`, a clap
     arg-group rule (`--gate` xor `--skill`), and an update to that test.
  3. **Card text source:** a `const` in `reflex.rs`, not extraction from `SKILL.md` (extraction
     would need markers inside the region §3.1 deliberately places outside all `reflex:section`
     markers). Mitigation for card/skill drift: a test asserting the card's key phrases appear in
     `using-drovr/SKILL.md`.
- **Subagents:** the card carries its own subagent-stop line unconditionally, regardless of
  whether `UserPromptSubmit` is confirmed to fire for Agent-tool subagents in this harness — that
  firing behavior is verified empirically in step 1 of §0 and the answer is recorded in
  `docs/skill-evidence/per-turn-gate.md`. This protects §6.3/§6.4's foreground probe subagents and
  drovr's own read-only reviewers from card contamination either way.
- **Config:** new `[reflex] per_turn` bool in `ReflexConfig` (`cli/src/config.rs:39-64`), default
  `true` **[tier 4]**, suppressible per-user. Uses a named default fn, not bare
  `#[serde(default)]` (the trap documented at `config.rs:108-110`).
- **Asymmetric suppression, deliberate:** the full `SessionStart` reflex stays suppressed inside
  phases (`DROVR_PHASE` set — a phase agent runs on its injected briefing). The per-turn gate does
  **not** suppress in phases — a phase is exactly where the discipline must hold.
- `README.md:70-94` updated with the new key.

`PreToolUse` hard-denial (e.g. blocking an `Edit` that skipped `drovr:tdd`, or a `git commit` with
no verification evidence) is enforcement, not persuasion — a larger design with real
false-positive risk. Not this run.

## 4. Fix 3 — bind checklists to tracked task state

**Directive text, harness-agnostic** (some sessions expose `TaskCreate`/`TaskUpdate`/`TaskList`
and no `TodoWrite`; stable Claude Code exposes `TodoWrite`):

> When a skill or briefing gives you a numbered checklist, create **one tracked item per step**
> using whatever task tool this harness exposes — `TodoWrite`, or `TaskCreate`/`TaskUpdate` —
> before you start step 1. Mark each in-progress when you start it and complete when its evidence
> is in hand. If the harness exposes no task tool, write the checklist to
> `~/.local/share/drovr/runs/<run>/checklist.md` when inside a run, or `CHECKLIST.md` at the repo
> root otherwise, and tick items there. An untracked checklist decays with the context window;
> that decay is the exact failure drovr exists to fight.

**Applied at four sites:**

1. `skills/using-drovr/SKILL.md` — the gate function's checklist branch (§3.1 step 5).
2. Each of the four discipline skills' numbered procedure — one-line binding directive above it.
3. `skills/pipeline/phase-prompts/*.md` — the `## Do` lists (`implement-task.md:14-64`, 7 steps;
   and the equivalents in `brainstorm.md`, `plan.md`, `review.md`, `review-angle.md`) gain the
   directive as step 0. Pure text change — these files are agent-assembled markdown, not compiled
   into the binary.
4. `skills/handoff/SKILL.md` and `skills/handoff/HANDOFF-template.md` — the 7-section handoff gets
   the same treatment.

No CLI change required for this fix.

## 5. Fix 4 — move the armor onto the discipline skills

`tdd`, `systematic-debugging`, `verification-before-completion`, `code-review` restructure to a
fixed section order **[tier 3 — order is superpowers' convention, adopted wholesale]**:

```
   REQUIRED — all four skills
1. description:      trigger, not summary (fix 1)
2. Overview          core principle + spirit-vs-letter line + the WHY, ≤6 lines
3. Unity line        "the next phase agent is you, with your context gone"
4. The Iron Law      one fenced all-caps line + "No exceptions:" bullets closing named loopholes,
                     each bullet pairing the prohibition with the required action
5. Announce          the exact sentence to emit when invoking the skill (commitment device)
6. The procedure     numbered, preceded by the task-binding directive (fix 3)
8. Red flags — STOP  inner-monologue fragments, closed by a catch-all bullet
9. Rationalizations  thought → reality; the reality column is an INSTRUCTION, not a rebuttal
10. Worked example   one ✅/❌ pair of actual utterances — one good example, not five
11. Cross-refs       bare skill names with REQUIRED markers; never @-links (they force-load)

   CONDITIONAL — only where named below
7. Requirements      claim → required evidence → not sufficient
                     ONLY: verification-before-completion, code-review
6b. Cycle flowchart  a fenced dot graph of the loop
                     ONLY: tdd, systematic-debugging
```

**Announcement strings** (template `Using drovr:<skill> to <purpose>.`):

- `tdd` — *"Using drovr:tdd — writing the failing test before the implementation."*
- `systematic-debugging` — *"Using drovr:systematic-debugging — reproducing before fixing."*
- `verification-before-completion` — *"Using drovr:verification-before-completion — running the
  checks before claiming done."*
- `code-review` — *"Using drovr:code-review — dispatching read-only reviewers before calling this
  done."*

**Placement contract:** sections 2–5 sit at the top (early-position favored, §1.2). Sections 8–9
sit late for proximity to the point of temptation — a tier-4 judgement, not the U-shape finding.
The procedure (6) sits mid-document deliberately — it is the section the agent actively re-reads
while working, so it is least dependent on single-pass recall. The position finding is not cited
for sections 6–9.

**Per-skill specifics:**

- **`tdd`** — Iron Law: no implementation code before a test you have watched fail. Loophole
  closures: "I'll keep the code as reference", "the test is obvious so I'll write it after", "it's
  a refactor so TDD doesn't apply", "the harness makes it hard to run one test".
- **`systematic-debugging`** — Iron Law: no fix before a reproduction and a mechanistic cause.
  Adds the numeric escalation trigger: after 3 failed fixes, stop and question the design; no
  fix #4 without that conversation.
- **`verification-before-completion`** — Iron Law: no completion claim without fresh evidence
  produced in this message. Requirements table covers tests / build / linter / bug-fixed /
  subagent-reported-success. Catch-all red flag for any wording implying success.
- **`code-review`** — Iron Law: no change is done until a read-only reviewer has looked at it and
  every Critical/Important finding is resolved or explicitly recorded as deferred. Loophole
  closures: "the change is too small", "I already reviewed it myself", "the pipeline's review
  phase will catch it". The existing FOREGROUND rule (`code-review/SKILL.md:19-23`) is promoted
  into the no-exceptions list.

**Size:** current bodies are 39–51 lines; the rewrite is expected at roughly 120–180 lines each.
The binding constraint is the `BODY_BUDGET` in §1.3, not line count.

### 5.1 Length budget (contract for `cli/tests/skills_valid.rs`)

> The byte budget applies to teaching content. Binding content is deliberately redundant.

Teaching content stays terse and is cross-referenced, never restated. Binding content — the
prohibition the agent will try to talk itself out of — is stated 3–4 times per skill (Iron Law,
red flag, rationalization row, checklist item); redundancy is the mechanism, not a defect.

- `cli/tests/skills_valid.rs:17`'s `const BODY_BUDGET` rises from 2200 to **12000 bytes**, over
  the four methodology skills (`:20-25`) **[tier 4 — no superpowers analogue, no evidence sets a
  correct length]**.
- **`using-drovr` gets its own cap and joins the checked list at 9000 bytes.** It is injected in
  full on every `SessionStart` and is currently exempt by accident (5087 B / 775 words / 93 lines
  today; §3.1 adds six blocks).
- Above cap, split into `references/`.
- The byte budget in `skills_valid.rs` is the single authoritative check. `wc -l` / `wc -w`
  targets are author guidance only, never asserted in §8.
- These caps deviate from superpowers in both directions (its TDD skill is 371 lines / 1496 words;
  its own guidance recommends <200 words for frequently-loaded skills). The deviation is tier-4,
  not cited or measured.

The user's global terseness preference governs assistant replies, not the length of documents
whose job is to survive a filling context window; it does not apply to any skill doc in this spec.

## 6. Fix 5 — the meta-skill and the empirical loop

### 6.1 New skill: `drovr:writing-skills`

`skills/writing-skills/SKILL.md`, in drovr's voice. Pass criteria, four-part closure, and
scenario-construction rules are **[tier 3]** convention-follows, ported from
`testing-skills-with-subagents.md:182-275`, worded independently.

- **Mapping:** pressure scenario ↔ test case; `SKILL.md` ↔ production code; RED ↔ the agent
  violates the rule without the skill; GREEN ↔ it complies with the skill; REFACTOR ↔ close each
  new loophole.
- **Loop** (fenced `dot` flowchart, §1.1 placement rule): build the scenario set → run the
  baseline → transcribe every excuse verbatim → write the minimal counter-text → re-run on
  held-out scenarios → apply the four-part closure to each new rationalization → repeat until a
  run produces no new rationalization or the §6.3 REFACTOR ceiling is reached, whichever comes
  first. The ceiling is not optional.
- **Four-part closure**, all four every time: explicit negation inside the rule; a row in the
  rationalization table; a bullet in red flags; a `description:` update naming the symptom of
  being about to violate.
- **Scenario construction:** real file paths, concrete numbers and deadlines, forced A/B/C choice,
  "what do you do" not "what should you do", no escape hatch to "I'd ask the human", ≥3 combined
  pressure types (time, sunk cost, authority, economic, exhaustion, social, pragmatic).
- **Pass criteria**, all four: correct option under maximum pressure; agent cites a specific
  section; names the temptation and complies anyway; the meta-test ("how should this have been
  written?") returns "it was clear". Not-bulletproof signals: new rationalizations, the agent
  arguing the skill is wrong, invented hybrid approaches, asking permission while arguing hard for
  the violation.
- **drovr-specific constraints:** scenario subagents run in the FOREGROUND; the author is the
  single writer; §1's no-fabricated-measurements rule applies.
- Reference files: `references/pressure-scenarios.md`, `references/testing-with-subagents.md`,
  keeping `SKILL.md` under the §5.1 cap.

### 6.2 Evidence corpus (locations, fixed)

- `skills/writing-skills/scenarios/<skill>-<n>.md` — checked-in scenario prompts, each tagged
  `dev` or `holdout` (§6.3).
- `docs/skill-evidence/<skill>.md` — per skill: scenarios used, verbatim baseline
  rationalizations, the counter-text, re-test results with dates.
- `docs/skill-evidence/voice.md` — the §6.4 probe.
- `docs/skill-evidence/per-turn-gate.md` — §3.2's unmeasured-bet record and the subagent-firing
  answer.
- `docs/skill-evidence/transcripts/` — raw transcripts; the corpus any numeric claim in shipped
  skill text must cite (exception 1).

### 6.3 The acceptance test (runs in this run)

**Held-out design:** per skill, 3 scenarios — 1 development, 2 held-out. RED transcription and all
counter-text authoring use the development scenario only. The pass bar is pre-registered and
scored on the held-out pair, which is never read while writing arm B. (Rationale: authoring arm B
from the scenarios that grade it would fit the text to the test.)

**Arms** (three, so fix 1 and fix 4 are separable):

| Arm | Text |
|---|---|
| **A** | Current `SKILL.md` at the pre-fix `HEAD` (captured in §0 step 2) |
| **A′** | Fix-1-only: descriptions un-scoped, no armor |
| **B** | Full rewrite (fixes 1 + 3 + 4) |

Arm A′ isolates fix 4's contribution: arm A's descriptions are phase-scoped, so a non-phase-framed
scenario handicaps A for reasons unrelated to the armor, and without A′, B > A would prove nothing
about fix 4 specifically.

**Budget table** — every line a hard ceiling. Hitting a ceiling halts that stage and records a
null in `docs/skill-evidence/`; it does not silently extend.

| Stage | Scope | Runs | Ceiling |
|---|---|---|---|
| RED / baseline on dev set | 5 skills × 1 dev scenario × 2 samples | 10 | 10 |
| Arm A on held-out | 5 skills × 2 held-out × 2 samples | 20 | 20 |
| Arm A′ on held-out | 4 discipline skills × 2 × 2 | 16 | 16 |
| Arm B on held-out | 5 skills × 2 held-out × 2 samples | 20 | 20 |
| REFACTOR re-tests | failing skills only, ≤2 iterations each | ≤20 | 20 |
| Voice probe (§6.4) | 4 variants × 2 scenarios × 3 samples | 24 | 24 |
| `using-drovr` no-skill-applies class | 2 scenarios × 3 arms × 2 samples | 12 | 12 |
| **Total** | | **≈122** | **122 hard ceiling** |

`using-drovr`'s extra scenario class checks the router's own failure mode (invoking nothing)
without inducing the opposite failure (invoking everything reflexively).

**Decomposition:** 122 foreground subagent runs with verbatim transcription do not fit in one
`implement-task` context. One dedicated phase per skill, `ab-<skill>` (5 phases), each running its
own stages, writing `docs/skill-evidence/<skill>.md` plus raw transcripts, then exiting. The voice
probe is a sixth phase, `ab-voice`. The driver aggregates. No phase holds more than ~25 runs.

**Scoring:**

- Rubric: binary compliant / non-compliant on the scenario's forced choice, plus the four §6.1
  pass criteria recorded separately as booleans.
- Scorer: a read-only reviewer subagent, given the transcript and the rubric only.
- Blinding: arm labels stripped and transcripts shuffled before scoring; the mapping restored only
  after all scores are recorded. Arm B's author does not score.
- Model: `sonnet` for probe subagents and for the scorer.

**Pre-registered bars** (written before arm B runs):

- **Arm A bar:** a skill "already passes" if A is compliant on ≥3 of its 4 held-out runs.
- **Arm B bar:** compliant on ≥3 of its 4 held-out runs for that skill, AND strictly more
  compliant runs than both A and A′.
- **Consequence of B failing after its REFACTOR ceiling:** that skill does not ship its armor — it
  reverts to arm A′ (fix-1-only), and `docs/skill-evidence/<skill>.md` records the failure and the
  reverted state. Fix 1 ships regardless (it is a defect repair); fix 4 must earn its bytes.
- If arm A already passes for a skill, that skill's rewrite is not justified and reverts to A′.
- If A′ ≈ B for a skill, the armor is not carrying its weight there and that skill reverts to A′
  even if B passes its own bar.

Null and negative results are recorded alongside positive ones.

### 6.4 Voice probe

**Probe skill:** `verification-before-completion` (sharpest binary outcome — claimed done without
running the command — shortest scenarios). Model: `sonnet`, matching §6.3 — not the Opus-class
model drovr sessions run on; stated limitation alongside the §1.2 extrapolation.

**Variants** (identical structure — same Iron Law, procedure, tables, placement — each adding
exactly one register device to the baseline):

| Variant | Register |
|---|---|
| **V0** | Baseline: plain imperative; no all-caps, no absolutist "no exceptions"; operational consequence only |
| **V1** | V0 + unity line |
| **V2** | V0 + full authority register (`MUST`/`NEVER`, all-caps Iron Law, no-exceptions bullets) |
| **V3** | V0 + moral framing, in superpowers' register |

4 variants × 2 scenarios × 3 samples = 24 runs, 6 per variant.

**Decision rule** (pre-registered; separation margin ≥3 of 6 per side, matched to stated power —
a 2-of-12 margin on binary outcomes is roughly one standard deviation and would fire on noise):

1. Variant beats V0 by ≥3 → that device ships across all five documents.
2. V0 beats the variant by ≥3 → that device is dropped; the baseline register ships for it. This
   is a defined, real outcome.
3. No separation ≥3 (likeliest outcome) → tier 3: follow superpowers. Authority ships (superpowers
   uses it), moral framing ships (superpowers uses it throughout), and unity ships anyway on the
   strength of the 2026 published ranking (§1's tier 1 outranks tier 3, even though superpowers
   itself withholds unity from discipline skills). Each is recorded in
   `docs/skill-evidence/voice.md` as convention-or-prior, with the null attached.
4. Whatever wins applies to the other four documents without re-testing each. Stated limitation:
   measured on one skill, one model, generalised to five documents.

**Unity's arm is reported, not decisive** — 6 runs cannot overturn the N=126,000 published result,
and this is not represented otherwise. **No directional escape hatch:** if V1 loses to V0 by ≥3,
that is recorded as a genuine conflict between the published prior and drovr's own data, and
escalates to the human rather than being auto-resolved.

**Power note:** n=6 per variant detects only large effects; register effects are expected to be
small on frontier models, so outcome 3 is the single likeliest result. Nothing stronger than
"suggestive" is recorded for any outcome.
