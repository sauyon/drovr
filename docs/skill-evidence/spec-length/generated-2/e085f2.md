# Spec: skill stickiness

## Objective

drovr's skill docs describe correct practice but do not bind an agent under context pressure.
This run ships five fixes, one new meta-skill (`drovr:writing-skills`), and an empirical
acceptance test that gates whether the armor (fix 4) ships per skill.

## Build order (binding — not the section order)

1. `drovr:writing-skills` + the scenario corpus (§7.1/§7.2) — nothing else is testable first.
2. Capture arm A / RED at pre-fix `HEAD`, before any skill file is touched. Hard gate: once fix 1
   lands, arm A is unrecoverable without a checkout.
3. Fixes 1 + 3 (descriptions, phase-framing demotions, task-binding directives).
4. Fix 4, using RED wording from step 2 for the rationalization tables.
5. Held-out arm B + the voice probe.
6. Fix 2's hook layer (the only Rust work; independently orderable). Fix 2's doc layer belongs
   with step 4.

## Decision-authoring rule (governs every decision below)

Four-tier precedence, applied in order: (1) published evidence, cited in the text; (2) no
evidence but the question is measurable by this run's probe/rubric within the §7.3 budget →
measure it, tagged **tier 2**; (3) not measurable, or measurement inconclusive, and superpowers
has a convention → follow it, tagged **tier 3** (a convention-follow, not evidence); (4) no
superpowers analogue → engineering judgement, tagged **[tier 4]**. Deviation from superpowers
requires a citation, a measurement, or an explicit tier-4 marking — never an unmarked departure.

Two standing constraints on all shipped text:
- **No fabricated measurements.** No number, duration, frequency, or comparative is stated as
  measured unless drovr measured it or a citation supports it.
- **No copied text.** Both projects are MIT; drovr still writes its own sentences. A verbatim
  survival gets the MIT notice and credit added.

Voice register decisions (authority, unity, moral framing) are **tier 2**, resolved empirically
in §7.4, not settled here. Flowcharts (doc placement) are **tier 3**: adopted per superpowers'
rule — genuine branching or stop-too-early loops only, never linear procedures.

## Fix 2 — `using-drovr` becomes a per-turn gate

### Doc layer (`skills/using-drovr/SKILL.md`)

New content, in this order (position effects favor start/end of document):

1. `<SUBAGENT-STOP>` — kept as-is (`:8-11`).
2. **The 1% rule** [tier 3], above the H1: even a 1% chance a drovr skill applies means invoke
   it, paired with a cost-lowering clause (drop it if it doesn't fit; invoking costs almost
   nothing).
3. **The per-turn rule**: check before any response, including clarifying questions and
   read-only exploration.
4. **Instruction-priority ladder** [tier 3]: human's explicit instructions > drovr skills >
   default behaviour. Safety counterweight to the MUST language.
5. **Gate function** — fenced `dot` flowchart (it branches): message received → does any skill
   apply (≥1%) → invoke → announce → has a checklist → create one tracked item per step → follow
   it → only then respond.
6. **Red-flag table** for the router's own failure mode (invoking nothing). Candidate rows: "this
   is a one-line change," "I'll just look at the file first," "they asked a question, not for
   work," "I'm already mid-task, the router was for turn one," "escalating would be overkill."
   Final wording comes from RED (§7.1), not this list.
7. Existing sections (single-writer, always-review, methodology, escalation) retained.

Items 2–5 sit outside every `<!-- reflex:section:NAME -->` marker [tier 4]: `[reflex.sections]`
can subtract advisory sections but cannot delete the routing core; only `[reflex] enabled = false`
removes it.

### Hook layer (new `UserPromptSubmit` hook) — all decisions here are [tier 4], an explicit

**Interfaces/contracts bound:**

  entry's `startup|clear|compact` matcher must not be copied across.
- `reflex.rs:143-152`'s `envelope()` currently hardcodes `"hookEventName": "SessionStart"`; it is
  parameterized to take the event name.
- `main.rs:114-118`'s `Reflex { skill: PathBuf }` (currently required) becomes `Option<PathBuf>`;
  a clap arg-group makes `--gate` and `--skill` mutually exclusive; `main.rs:1276-1278`'s
  bare-`drovr reflex` error assertion is updated accordingly.
- **Card text source**: a `const` in `reflex.rs`, not extracted from `SKILL.md` (extraction would

- **Card content**: the 1% rule, the per-turn check, the announcement string, the

  `Skill drovr:using-drovr`.
- **Byte budget** (not tokens — the CLI has no tokenizer): rendered `additionalContext` ≤ 600
  bytes per injection; cumulative ceiling ~60 KB over a 100-turn session (`additionalContext` is
  appended every turn and stays in the window). Asserted in `cli/src/reflex.rs`'s test module.
- **Suppression rule**: the card is emitted only when no `drovr:*` skill was invoked in the
  previous turn — bounds the cumulative cost; a session already running the discipline doesn't
  need re-telling.
- **Subagents**: the card carries its own unconditional subagent-stop line, because §7.3/§7.4

  `docs/skill-evidence/per-turn-gate.md`.
- **Config**: new `[reflex] per_turn` bool in `ReflexConfig` (`cli/src/config.rs:39-64`),
  **default true** [tier 4], suppressible per-user, using a named default fn (not bare
  `#[serde(default)]` — the trap already documented at `config.rs:108-110`).
- **Asymmetric suppression, deliberate**: the full `SessionStart` reflex stays suppressed inside
  phases (`DROVR_PHASE` set). The per-turn gate does **not** suppress in phases — a phase is
  exactly where the discipline must hold.
- `README.md:70-94` updated with the new key.

## Fix 3 — bind checklists to tracked task state

Stated harness-agnostically (some sessions expose `TaskCreate`/`TaskUpdate`/`TaskList`, stable
Claude Code exposes `TodoWrite`):

> When a skill or briefing gives you a numbered checklist, create one tracked item per step using
> whatever task tool this harness exposes — `TodoWrite`, or `TaskCreate`/`TaskUpdate` — before you
> start step 1. Mark each in-progress when you start it and complete when its evidence is in hand.
> If the harness exposes no task tool, write the checklist to
> `~/.local/share/drovr/runs/<run>/checklist.md` when inside a run, or `CHECKLIST.md` at the repo
> root otherwise, and tick items there.

Applied at four sites: `using-drovr`'s gate-function checklist branch; a one-line binding
directive above each discipline skill's numbered procedure; `skills/pipeline/phase-prompts/*.md`'s
`## Do` lists (`implement-task.md` and the `brainstorm.md`/`plan.md`/`review.md`/`review-angle.md`
equivalents) as step 0; `skills/handoff/SKILL.md` and `HANDOFF-template.md`'s 7-section handoff.
No CLI change required — this is a pure text change everywhere it's applied.

## Fix 4 — armor onto the four discipline skills

`tdd`, `systematic-debugging`, `verification-before-completion`, `code-review` restructure to a
fixed section order [tier 3 — superpowers' convention, adopted wholesale]:

```
   REQUIRED — all four skills
1. description:      trigger, not summary (fix 1)
2. Overview          core principle + spirit-vs-letter line + the WHY, ≤6 lines
3. Unity line        "the next phase agent is you, with your context gone"
4. The Iron Law      one fenced all-caps line + "No exceptions:" bullets closing named loopholes,
                     each pairing the prohibition with the required action
5. Announce          exact sentence to emit when invoking the skill (commitment device)
6. The procedure     numbered, preceded by the task-binding directive (fix 3)
8. Red flags — STOP  inner-monologue fragments, closed by a catch-all bullet
9. Rationalizations  thought → reality; reality column is an INSTRUCTION, not a rebuttal
10. Worked example   one ✅/❌ pair of actual utterances
11. Cross-refs       bare skill names with REQUIRED markers; never @-links (they force-load)

   CONDITIONAL — only where named below
7. Requirements      claim → required evidence → not sufficient
                     ONLY: verification-before-completion, code-review
6b. Cycle flowchart  fenced dot graph of the loop
                     ONLY: tdd, systematic-debugging
```

Placement rationale: sections 2–5 sit at the top (position effects favor document start).
Sections 8–9 sit late for proximity to the point of temptation [tier 4 judgement — not the
position-effects finding]. The procedure (6) sits mid-document deliberately — it's what the agent
actively re-reads while executing, so it's least dependent on single-pass recall. The position
finding is not cited for sections 6–9.

**Announcement template**: `Using drovr:<skill> to <purpose>.` Shipped strings:
- `tdd` — "Using drovr:tdd — writing the failing test before the implementation."
- `systematic-debugging` — "Using drovr:systematic-debugging — reproducing before fixing."
- `verification-before-completion` — "Using drovr:verification-before-completion — running the
  checks before claiming done."
- `code-review` — "Using drovr:code-review — dispatching read-only reviewers before calling this
  done."

**Per-skill Iron Laws and loophole closures:**
- `tdd` — no implementation code before a test watched fail. Closures: "I'll keep the code as
  reference," "the test is obvious so I'll write it after," "it's a refactor so TDD doesn't
  apply," "the harness makes it hard to run one test."
- `systematic-debugging` — no fix before a reproduction and a mechanistic cause. Adds a numeric
  escalation trigger: after 3 failed fixes, stop and question the design before attempting fix #4.
- `verification-before-completion` — no completion claim without fresh evidence produced in this
  message. Requirements table covers tests/build/linter/bug-fixed/subagent-reported-success.
  Catch-all red flag for any wording implying success.
- `code-review` — no change is done until a read-only reviewer has looked at it and every
  Critical/Important finding is resolved or recorded as deferred. Closures: "the change is too
  small," "I already reviewed it myself," "the pipeline's review phase will catch it." The
  existing FOREGROUND rule (`code-review/SKILL.md:19-23`) is promoted into the no-exceptions list.

Expected size: 39–51 lines → roughly 120–180 lines each; the binding constraint is the byte
budget below, not line count.

## Fix 5 — `drovr:writing-skills` meta-skill and the empirical loop

### New skill: `skills/writing-skills/SKILL.md`

Ported in drovr's own wording from superpowers' `testing-skills-with-subagents.md:182-275`
[tier 3 convention-follow]. Contents:

- **Mapping**: pressure scenario ↔ test case; `SKILL.md` ↔ production code; RED ↔ agent violates
  the rule without the skill; GREEN ↔ complies with the skill; REFACTOR ↔ close each new
  loophole.
- **Loop** (fenced `dot` flowchart): build scenario set → run baseline → transcribe every excuse
  verbatim → write minimal counter-text → re-run on held-out scenarios → apply the four-part
  closure to each new rationalization → repeat until a run produces no new rationalization **or**
  the §7.3 REFACTOR ceiling is reached, whichever first. The ceiling is not optional.
- **Four-part closure** (all four, every time): explicit negation inside the rule; a
  rationalization-table row; a red-flags bullet; a `description:` update adding the symptom of
  being about to violate.
- **Scenario construction rules**: real file paths, concrete numbers/deadlines, forced A/B/C
  choice, ask "what do you do" not "what should you do," no escape hatch to "I'd ask the human,"
  ≥3 combined pressure types (time, sunk cost, authority, economic, exhaustion, social,
  pragmatic).
- **Pass criteria** (all four): correct option under maximum pressure; agent cites a specific
  section; names the temptation and complies anyway; meta-test ("how should this have been
  written?") returns "it was clear." Not-bulletproof signals: new rationalizations, agent arguing
  the skill is wrong, invented hybrid approaches, asking permission while arguing for the
  violation.
- **drovr-specific constraints**: scenario subagents run in the FOREGROUND; the author is the
  single writer; no-fabricated-measurements applies.
- Reference files: `references/pressure-scenarios.md`, `references/testing-with-subagents.md`,
  keeping `SKILL.md` under the length cap.

### Evidence corpus (new paths, all binding)

- `skills/writing-skills/scenarios/<skill>-<n>.md` — checked-in scenario prompts, tagged `dev` or
  `holdout`.
- `docs/skill-evidence/<skill>.md` — per skill: scenarios used, verbatim baseline
  rationalizations, counter-text, re-test results with dates.
- `docs/skill-evidence/voice.md` — the voice-probe record.
- `docs/skill-evidence/per-turn-gate.md` — fix 2's unmeasured-bet record and the subagent-firing
  answer.
- `docs/skill-evidence/transcripts/` — raw transcripts; the corpus any numeric claim in shipped
  skill text must cite.

### Acceptance test (runs in this run)

**Held-out design**: per skill, 3 scenarios — 1 development, 2 held-out. RED transcription and
counter-text authoring use only the development scenario. The pass bar is scored only on the
held-out pair, never read while writing arm B.

**Arms:**

| Arm | Text |
|---|---|
| A | Current `SKILL.md` at pre-fix `HEAD` |
| A′ | Fix-1-only: descriptions un-scoped, no armor |
| B | Full rewrite (fixes 1 + 3 + 4) |

A′ isolates fix 4's contribution — without it, B > A would be confounded by fix 1's un-scoping.

**Budget table** (hard ceilings; a hit ceiling halts and records a null, never silently extends):

| Stage | Scope | Runs | Ceiling |
|---|---|---|---|
| RED / baseline on dev set | 5 skills × 1 dev × 2 samples | 10 | 10 |
| Arm A on held-out | 5 skills × 2 held-out × 2 samples | 20 | 20 |
| Arm A′ on held-out | 4 discipline skills × 2 × 2 | 16 | 16 |
| Arm B on held-out | 5 skills × 2 held-out × 2 samples | 20 | 20 |
| REFACTOR re-tests | failing skills only, ≤2 iterations each | ≤20 | 20 |
| Voice probe | 4 variants × 2 scenarios × 3 samples | 24 | 24 |
| `using-drovr` no-skill-applies class | 2 scenarios × 3 arms × 2 samples | 12 | 12 |
| **Total** | | **≈122** | **122 hard ceiling** |

**Execution**: one dedicated phase per skill, `ab-<skill>` (5 phases), each writing its own
`docs/skill-evidence/<skill>.md` and transcripts, plus a sixth phase `ab-voice`. No phase holds
more than ~25 runs. The driver aggregates.

**Scoring** (pre-registered, not by arm B's author):
- Rubric: binary compliant/non-compliant on the scenario's forced choice, plus the four §7.1 pass
  criteria as separate booleans.
- Scorer: a read-only reviewer subagent given the transcript and rubric only.
- Blinding: arm labels stripped, transcripts shuffled before scoring; mapping restored only after
  all scores are recorded.
- Model: `sonnet` for probe subagents and the scorer.

**Pre-registered bars:**
- Arm A "already passes": compliant on ≥3 of its 4 held-out runs.
- Arm B bar: compliant on ≥3 of its 4 held-out runs **and** strictly more compliant runs than
  both A and A′.
- **Consequence of failure**: a skill whose B fails after its REFACTOR ceiling does not ship its
  armor — it reverts to arm A′, and the failure and reverted state are recorded in
  `docs/skill-evidence/<skill>.md`. Fix 1 ships regardless (it's a defect repair); fix 4 must earn
  its bytes.
- If arm A already passes for a skill, that skill's rewrite is not justified and it reverts to A′.
- If A′ ≈ B for a skill, the armor isn't carrying its weight there and it reverts to A′ even if B
  passes its own bar.
- Null and negative results are recorded alongside positive ones.

### Voice probe (register as a measured variable)

Probe skill: `verification-before-completion` (sharpest binary outcome, shortest scenarios).
Model: `sonnet`, matching the acceptance test — a stated limitation, since drovr sessions run
Opus-class.

Four variants, identical structure (same Iron Law, procedure, tables, placement), each adding one
register device to the baseline:

| Variant | Register |
|---|---|
| V0 | Baseline: plain imperative, no all-caps, no absolutist "no exceptions," operational consequence only |
| V1 | V0 + unity line |
| V2 | V0 + full authority register (`MUST`/`NEVER`, all-caps Iron Law, no-exceptions bullets) |
| V3 | V0 + moral framing, superpowers' register |

4 variants × 2 scenarios × 3 samples = 24 runs, 6 per variant.

**Decision rule**, each variant vs. V0 on 6 runs per side, separation margin ≥3 of 6:
1. Variant beats V0 by ≥3 → that device ships across all five documents.
2. V0 beats the variant by ≥3 → that device is dropped; baseline register ships.
3. No separation ≥3 (likeliest outcome) → tier 3: follow superpowers — authority ships, moral
   framing ships, and unity ships anyway on the strength of the published 2026 ranking (tier 1
   outranks tier 3). Each recorded in `docs/skill-evidence/voice.md` as convention-or-prior, null
   attached.
4. Whatever wins applies to the other four documents without re-testing each (stated limitation:
   measured on one skill, one model, generalized to five documents).

Unity's arm is reported, not decisive — 6 runs cannot overturn the published N=126,000 result. No
directional escape hatch: if V1 loses to V0 by ≥3, that is recorded as a genuine conflict between
the published prior and drovr's own data, and escalates to the human rather than being
auto-resolved.
