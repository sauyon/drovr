# Spec: TUI deploy-config picker — browse any config in the project

## Decided

**Q1 — Picker shape: three levels, project → config → version.** Cross-project adoption
follows as a consequence: every project in the org is a tree root, so a deployment can be
switched to a config in any project, not just its own.

**Q5 (turn 2 revision) — Presentation: one browsable collapsible tree**, not three sequential
`huh.Select` prompts. Same three levels as Q1, built on the browser's existing `fieldTree`
widget (`browse_fieldtree.go:151`) rather than a new widget. Reason: browsing sideways
("what else is in this project? what other versions does that config have?") is the point of
the feature, and a stepped picker forces backing out and restarting to compare two configs.
Cost accepted: `fieldTree` has no type-to-filter (the `huh.Select` steps had
`.Filtering(true)`) — pushed to Follow-ups, not silently dropped.

**Q2 — Project level when it can't be inferred: auto-expand the sole project when the org has
exactly one, otherwise leave all projects collapsed with the cursor on the first.** Applies
even to linked deployments beyond their own project — a linked deployment auto-expands its
own project and config regardless of how many other projects exist.

**Q3 — Unlinked deployment adopting a config: preserve the deployment's current configuration
as overrides**, via a two-way deep merge (target config as base, deployment's current
configuration as overlay, overlay wins on conflicting leaves). Reason: with no linked
baseline, `preserveDeploymentDivergences` today returns the target verbatim, which would reset
every field the deployment has (including a pinned `engine_spec.image`) — the exact incident
class `preserveDeploymentDivergences` was written to prevent (commit `e351fdd69`). The edit
form already avoids this via `completeConfigPick`'s fallback to
`overridesFromConfiguration(prior)`; `V` must match it.

**Q4 — Switching across config names: keep the existing three-way divergence merge** against
the previously-linked baseline, even though that baseline has no relationship to the new
target. Reason: a pinned image surviving the switch matters more than merge purity, and
applying the target verbatim on a name change would reopen the same unpinning hazard Q3
closes. Applies identically to a cross-project switch. Confirm copy must say overrides are
being carried across.

**Entry gate removed.** `V` no longer requires `m.sel.DeployConfigID != nil`
(`browse_model.go:1910-1917`); it is valid on any detail-screen selection, and
`helpAdapter.dcLinked` (`browse_model.go:2916`) advertises the key on unlinked deployments too.

**No server or API change.** `deployConfigService.List` with no name filter already returns
every distinct config in the project including shared ones; `ListDeployConfigs` is already
exposed on the typed client. Confirmed by reading `api-server/services/deploy_config.go:194-201`
and `internal/mcloudcli/api/deploy_config.go:26`.

## Interfaces / contracts

### New `appModel` state (`browse_model.go`, alongside existing `dc*` block)

```go
dcTree    *fieldTree                     // the picker; non-nil exactly while it is open
dcLinked  *schemasv1.DeployConfigSchema  // linked config if any: auto-expand/cursor seed,
                                         // and merge baseline for the confirm
dcLoading map[string]bool                // in-flight branch loads, keyed "" (projects) /
                                         // "<project>" / "<project>\x00<config>"
```

`dcForm`, `dcVersions`, `dcCurrent`, `dcChoice` are removed (replaced by the tree).
`dcVersLoading` is replaced by `len(dcLoading) > 0`.

### `fieldNode` selection payload

`fieldNode` (`browse_fieldtree.go:139-146`) gains one optional field:

```go
pick any // non-nil only on picker version leaves; nil on every node other trees build
```

Zero value is `nil`, so config/revision/diff trees are unaffected. The picker sets `pick` to
the `*schemasv1.DeployConfigSchema` on each version leaf; `enter` reads it back. Branch nodes
(project, config) always leave `pick` nil — that nil-ness is the "a branch is never a
selection" rule, no separate node-kind enum. `fieldTree` gains a `current() *fieldNode`
accessor returning the node under the cursor, so the picker doesn't reach into unexported
`flat`/`cursor` internals.

### Lazy loading contract

| Level | Loaded when | Call |
|---|---|---|
| projects | picker opens | `ListBenchmarkProjects` |
| configs of a project | that project's first expand | `ListDeployConfigs(project)` + `latestPerConfig` |
| versions of a config | that config's first expand | `fetchDeployConfigVersions(project, name)` |

An unexpanded branch holds one placeholder child (`loading…`, replaced on arrival; `(none)` if
the listing is empty). Each branch caches its children after first load; re-collapse/re-expand
does not refetch.

### New messages

```go
type dcProjectsMsg struct { name string; items []*schemasv1.BenchmarkProjectSchema; err error }
type dcConfigsMsg  struct { name, project string; items []*schemasv1.DeployConfigSchema; err error }
type dcVersionsMsg struct { name, project, config string; items []*schemasv1.DeployConfigSchema; err error }
```

`name` is the deployment name on all three, preserving the existing stale-result drop
(`msg.name != m.sel.Name`). `project`/`config` identify which branch the result fills, so a
result for a branch the user has since collapsed lands on that branch without moving the
cursor. `dcVersionsMsg` drops the `current uint` field the old design carried — current version
now comes from `dcLinked`.

### Overlay routing

`currentOverlay()` (`browse_model.go:880`) keeps a single arm: `case m.dcTree != nil:` →
`overlayHandler{m.updateDCPicker, m.dcPickerView}`.

`autoRefreshPaused()`: the `m.dcVersLoading` arm is replaced by `m.dcTree != nil`, so
auto-refresh cannot swap `m.sel` while the picker is open, including while it's idle between
branch loads.

### Input contract

`↑`/`↓` move the cursor (`fieldTree.up`/`down`). `→`/`l` expand, `←`/`h` collapse
(`fieldTree.setCollapsed`); `space` toggles (`fieldTree.toggle`). `enter` on a version leaf
arms the confirm with that leaf's `pick`; `enter` on a project/config branch only toggles it.
`esc` cancels and sets `statusDCCanceled`.

### Transport — unchanged

`switchDeployConfigVersion` (`deploy_config.go:406`) already takes `(project, name, version)`
via `confirmState`'s `dcProject`/`dcName`/`dcVersion` fields and already sends
`deploy_config_id` + full `configuration`. `completeDCSelection` populates `dcProject`/`dcName`
from the chosen leaf's project/config instead of the linked config's — no transport change.

### Merge semantics contract (`deploy_config.go`)

`preserveDeploymentDivergences`'s nil-baseline branch changes from "return target verbatim" to
a **recursing two-way deep merge** (target = base, deployment's current configuration =
overlay, overlay wins on conflict; keys only the target carries still land). This must be a
distinct map-level helper (the map twin of `mergeJSONPtr`), not `threeWayMerge` fed an empty
map — `threeWayMerge`'s "value only current has" branch takes `curVal` wholesale for any key
absent from the baseline (`deploy_config.go:479-481`), which would replace target keys
wholesale and drop nested target-only keys. This fixes `preserveDeploymentDivergences` itself,
so it also fixes the same nil-baseline gap in `mcloud deployment deploy-config set`, which
shares the function.

### Labelling contract

- Project node: `"<name>"`.
- Config node: `"<name>  (latest v<N>)"`, plus `"  (shared)"` when `Shared` is true, plus
  `"  (current)"` when it's the linked config.
- Version leaf: `"v<N>  <created>  <description>"` (reusing the label
  `newDeployConfigVersionPicker` already builds, `browse_source_config.go:361-362`), plus
  `"  (latest)"` on the newest and `"  (current)"` on the deployment's current version.
- Panel label (`browse_panels.go:226-228`): `"V: switch version"` → `"V: switch deploy config"`.

`Shared` (`schemasv1.DeployConfigSchema:16`) is already returned by the list endpoint but
currently surfaced nowhere in CLI or TUI — this is its first use.

### Confirm copy contract

`actionSwitchDeployConfig`'s confirm states, one line each: (1) switching redeploys the
deployment (already true today); (2) the deployment's overrides are carried across (decisions
Q3/Q4); (3) when the chosen config is shared, that the next `mcloud deploy-config apply`
creates a new version from the shared spec and moves the config's *latest* — the deployment
stays pinned to the version selected here because versions are immutable rows.

### Acceptance (behavioral contract, enforced by tests)

- `V` opens the picker on unlinked deployments (no more `"not based on a deploy config"`).
- Two configs' version leaves coexist in one tree with distinct `pick` payloads (regression
  guard for the `Select[uint]` collision the prior design had).
- `(shared)`, `(current)`, `(latest)` markers render correctly.
- Auto-expand matches Q2/on-open rules for linked, single-project-unlinked, and
  multi-project-unlinked cases.
- `enter` on a version leaf arms the confirm with that leaf's project/config, including the
  cross-project case.
- `enter` on a branch toggles it and arms no confirm.
- Expanding a branch twice issues one fetch; children are cached.
- Esc clears `dcTree` and sets `statusDCCanceled`.
- Stale-result drop by deployment name; branch-targeted fill by project/config key.
- `currentOverlay()` routes to `updateDCPicker` exactly when `dcPickerView` renders.
- `fieldNode.pick` is nil on every node built by the config/revision/diff tree builders.
- Nil-baseline merge preserves a pinned field and recurses into nested target-only keys
  (Q3 regression guards).
- Non-nil-baseline (three-way) merge behavior is unchanged (Q4 regression guard).

## Out of scope

- Any API-server or schema change — the existing `List` endpoint and typed client already
  return every config in the project, shared included.
- **Type-to-filter in the picker.** `fieldTree` has no equivalent of `huh.Select`'s
  `.Filtering(true)`; the tree is cursor-navigated only. Follow-up: add filtering to
  `fieldTree` itself (shared widget, own blast radius), not in this change.
- Converting the create/edit form's source picker (`browse_source_config.go`) or the sync
  picker (`browse_form_sync.go`) to the tree. They keep their `huh.Select` steps; only `V`
  changes. Follow-up once `fieldTree` has filtering.
- Warning that editing a shared config gets reverted — moot: the TUI/CLI has no deploy-config
  write path at all (reads only via `internal/mcloudcli/api/deploy_config.go`; the sole write
  is `mcloud deploy-config apply`). Nothing here edits a config, so there is nothing to warn
  about; the one line of relevant copy (latest moving out from under a shared-config link) is
  covered under Confirm copy above.
- Refactoring `browse_source_config.go` and the new `V` flow into one generic picker — they
  differ in presentation, terminal action (reseed a form vs. arm a confirm + PATCH), and entry
  conditions. Shared *data* helpers (`latestPerConfig`, `findDeployConfigVersion`,
  `fetchDeployConfigVersions`) are reused as-is, not refactored.
