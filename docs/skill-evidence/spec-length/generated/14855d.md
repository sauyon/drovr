# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`

## 1. Problem

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), every one on the same expensive model,
over the whole `base..head` range. Cost scales with `angles × range size`, and the driver re-runs
the full panel unconditionally regardless of what the author already ran
(`docs/known-issues.md:589`).

A cheap-first cascade is the obvious saving and the obvious way to ship a silent quality
regression: a cheap tier's false negative is unrecoverable (nothing downstream re-checks what it
waved through, and a `Clean` it produces is byte-identical to a real one) — the vacuous-pass
failure this repo has hit ten times (`docs/known-issues.md:526`, `:589`). This run is therefore a
**measurement** with a feature attached, not a feature with a measurement attached.

## 2. Decisions (approved 2026-08-06, turn 1)

| # | question | decision | binds |
|---|---|---|---|
| 1 | Unit of escalation | **`measure-first`** — Task 0 measures `E/(E+D)`; the pre-registered rule (§4.1) picks explorer / angle / per-file as the primary design | §4 |
| 2 | Ship bar shape | **`by-failure-mode`** — recall ≥ 0.98, Wilson LB ≥ 0.95, N ≥ 142, for designs with an unrecoverable-miss class; non-inferiority (cascade recall LB ≥ 0.90 of unaided point estimate), N ≥ 69, for designs that degrade to baseline on failure | §6.4 |
| 3 | Class 3's role | **`gates-conditional`** — gates on conditional recall against the expensive tier's own finds; absolute detection rate on class 3 is reported, not gating | §6.2, §6.4 |
| 4 | Stratum D scope | **`both-stratified`** — `D-rs` and `D-md` are scored and reported as separate cells, never summed; the ship bar must pass on `D-rs` alone | §5.6 |

No open questions remain. Anything the plan phase discovers outside these four is a new question
for a new gate, not a gap in this one.

## 3. The degrade invariant

> A cheap-tier failure must degrade to the baseline — a full expensive review — never to less
> review than the baseline would have given.

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as today |

Router unavailable, timed out, crashed, out of context, unparseable, naming a unit not in the
range, or silently omitting a unit — every one takes the degrade path. There is no code path from
"the cheap tier had a problem" to "less review happened."

Whether a design has an unrecoverable-miss class at all is what §6.4's ship bar is keyed on.

## 4. Design selection

### 4.1 Task 0 — cost instrumentation, and the pre-registered rule

Instrument expensive-tier reviews on a fixture sample; split cost (tokens and wall-clock) into:

- **E — exploration:** tool calls searching or reading outside the diff (grep, unchanged-file
  reads, call-site following, test reads).
- **D — diff-reading and finding-writing.**

Report `E/(E+D)` as a per-fixture distribution, not just a mean. The rule below was fixed before
the number is known, and no design is committed to ahead of Task 0 running:

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 | cheap-as-explorer (§4.2) |
| ≤ 0.30 | per-file routing (§4.4) |
| 0.30 – 0.60 | angle routing (§4.3) |

Angle routing is additionally evaluated as a composable second stage under all three outcomes: it
is orthogonal to the primary-design choice.

### 4.2 Cheap tier as explorer

Cheap model builds a context bundle (call sites, tests, invariants, prior art); expensive model
reviews the whole diff with that bundle in its seed. Failure (incomplete bundle) degrades to the
expensive tier exploring for itself, per §3.

**Ship metric: non-inferiority of end-to-end defect recall against the unaided expensive panel on
the same fixtures** — not context completeness, because a plausible failure mode is the bundle
*anchoring* the reviewer into exploring less, which context-completeness cannot detect. Context
completeness is retained only as a diagnostic for explaining a failure.

### 4.3 Angle routing

Cheap handles angles whose judgement is local; expensive keeps `correctness`/`security`. Maps onto
today's fan-out: one `AgentLaunch` per angle becomes a per-angle choice of tier. No
unrecoverable-miss class — every angle is still reviewed by someone; failure is a per-angle quality
drop, bounded and measurable. "Local judgement" must be verified per angle from the corpus (stratum
D findings carry their angle), not assumed.

### 4.4 Per-file routing — retained as a measured control arm

Run alongside whichever primary design §4.1 selects, so the spec reports what per-file *would* have
cost and missed rather than assuming it away. Has a structural recall ceiling: a router judging one
file cannot see relational defects visible only from a different file's call site, invariant, or
test. **Deliverable:** for every class-3 fixture, compare files the *fix* commit touched against
files the *introducing* PR changed; a defect whose fix lands outside the introducing diff is one no
per-file router could have routed to. That fraction is per-file's empirical recall ceiling.

### 4.5 Whole-change triage — not a general design

One skip/review decision per change. Rejected as a general mechanism (one false clean loses an
entire change's review). Retained only as a narrow, conservative complement on changes where
near-certainty is available — dependency bumps, generated files, pure formatting — expressed as a
fixed rule, never a model judgement.

## 5. Corpus

### 5.1 Ground-truth classes — never pooled into one recall figure

| class | signal | proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change (human author agreed and changed the code) | same, bot-found |
| 3 | post-merge fix / revert / regression-fix of code a PR introduced | review **missed** it |

Class 2 is reported separately from class 1 so a reader who doubts bot-comment validity can discount
it independently.

### 5.2 Strata — full factorial, every stratum probed by every router model

| stratum | source | visibility | classes carried |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific (§5.5) |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin, §5.3) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

Neovim was chosen over `ghostty-org/ghostty` (33 inline review comments per 40 merged PRs vs. 9 per
40) for a third language plus public reproducibility off this machine. Design is
`router_model × stratum × class`; model access is not a stratifying factor (§7).

### 5.3 Class 1/2 attribution — verified, not assumed

- `commits == 1` disqualifies the PR (a single-commit PR cannot contain a comment-driven fix
  commit) — disqualifies modular PR 94850 and 95031 despite high comment counts.
- A later commit in the same PR must touch the commented file (ideally the commented lines); how
  this was verified is recorded per fixture.
- Docs-only PRs are excluded (e.g. modular PR 95055).
- Fixture selected for class-1/2: modular **PR 94953** (26 comments — 5 bot, 21 human — 9 files,
  +339/−158, 6 commits). PR 94602 (13 human comments, 71 files, +6851/−108) is available as a
  large-diff fixture if one is wanted.
- `quite-app`'s comment mix is 287 bot / 13 human (all from `sauyon`), so it cannot carry class 1;
  results are reported per repo and per class, and a thin cell is reported as thin, never merged
  into a neighbour.

### 5.4 Class 3 pipeline — validated end-to-end

1. Candidate fix commits: `git log -i --grep` for `revert|regression|broke` and kin.
2. `git blame` the lines the fix **deleted or replaced**, at `fix^`.
3. Require a single introducing commit; fan-out (defect not cleanly attributable) is rejected.
4. That commit's PR at pre-merge state is the fixture; the fix commit's diff states the defect and
   where it was — human-authored label, no invention.

Validated on `quite-app`: fix `cb1adad` → deleted lines in `quited/qrun/src/sip_clone.rs` → blame
resolves to single commit `55b80032`. Attrition is reported at every stage (candidates →
single-attribution → adjudicated-as-defect): of 40 class-3 candidates sampled in `quite-app`, only 7
touched ≤ 2 files.

### 5.5 Stratum D

Source: `~/.local/share/drovr/runs/skill-stickiness/` — 376 per-angle findings files across 100
panels over 22 tasks, plus every `<task>-base.sha` and `<task>-review-<iter>.head`. All 100 head and
22 base SHAs resolve from this worktree (shared object database,
`git rev-parse --git-common-dir` → `/home/sauyon/devel/drovr/.git`). 131 blocking findings: 79
`.rs`, 51 `.md`, 1 `.json`, over 20 tasks. Findings carry their angle (makes §4.3's per-angle premise
testable).

Labels: *verified-real* (fix landed, or written up in `docs/known-issues.md`) — the only set that
feeds the ship bar; *unverified* — reported, not scored; *rejected* — excluded with reason recorded.

Per decision 4 (§2): `D-rs` (79 blocking findings pre-filter) and `D-md` (51) are scored and
reported as separate cells, never summed. The ship bar must pass on `D-rs` alone; `D-md` is reported
with its own interval and cannot rescue a failing `D-rs`. Rust review and prose review are different
tasks; pooling would hide a cheap tier that is competent at one and not the other.

## 6. The measurement

### 6.1 Arms

`router_model ∈ {qwen, sonnet} × stratum ∈ {D, M, Q, N} × class ∈ {1, 2, 3}`, design fixed by §4.1,
per-file routing run as a control arm alongside. The ship decision is per router model —
`router_agent`/`router_model` are separate config keys (§8); a sonnet-routed cascade and a
qwen-routed one ship independently.

### 6.2 Class 3's second metric (decision 3, §2)

For classes 1, 2 and stratum D, the expensive tier found the defect by construction. Class-3
defects were missed by review, so the expensive tier may miss them too and a cheap tier cannot be
blamed for failing where the expensive tier also would. Two numbers:

- **Conditional recall** (gates): of the class-3 defects the expensive tier finds, how many survive
  the cascade.
- **Expensive-tier absolute detection rate on class 3** (reported, does not gate): what fraction of
  review-missed defects the full panel finds at all.

### 6.3 Controls

- **NULL** (everything cleared, recall 0) and **FLOOD** (everything escalated, recall 1.0) bracket
  every stratum/class cell on both recall and saving; a real cheap tier must land strictly inside
  the bracket on both axes or those fixtures are rebuilt before scoring.
- **Positive control:** re-running the expensive tier on a sample must re-find recorded class-1/2
  defects at a high rate; if not, the corpus needs re-cutting, not the cheap tier.
- **Dev/held-out split**, assigned before any cheap-tier prompt is written, at task/PR level (no
  diff in both). Held-out is scored once, after the prompt is frozen and its `git hash-object`
  recorded. Scoring is set membership with no human judgement, so the split — not a blinding
  scheme — is the load-bearing control against prompt overfitting: there is no `blind-map.json`.

### 6.4 Ship bar (decision 2, §2)

Wilson 95% lower bound; N required to clear the target given misses observed:

| LB target | 0 misses | 1 miss | 2 misses |
|---|---|---|---|
| ≥ 0.90 | 35 | 53 | 69 |
| ≥ 0.95 | 73 | 110 | 142 |

- **Unrecoverable-miss designs** (per-file, whole-change): recall ≥ 0.98, Wilson LB ≥ 0.95, target
  **N ≥ 142** per gated cell — a miss there is a defect nobody looks at again.
- **Baseline-degrading designs** (angle routing, cheap-as-explorer): non-inferiority against the
  unaided expensive panel, cascade recall LB ≥ 0.90 of the unaided point estimate, target
  **N ≥ 69** — failure there is a cost regression, not a lost defect.

Going past LB ≥ 0.95 is out of scope: the next tier (N ≥ 239 for LB ≥ 0.97) buys 0.02 of interval
against uncertainty dominated by corpus construction (§9), not sampling error.

**Gate order:** 0. N floor met, else null for that cell. 1. Instrument discriminates (§6.3). 2. The
recall bar above. 3. Escalation/skip rate leaves a real saving. 4. Measured end-to-end cost < 0.80×
the non-cascade panel. Bars 1–2 are the ship decision; failing 3 or 4 ships the code behind
`enabled = false` with the negative economics written up. Precision, hint quality, context
completeness, and class-3 absolute detection are reported and are not decision inputs.

**Pooling:** `N ≥ 142` per `(model × stratum × class)` cell is 24 cells and unreachable. The floor
applies to the gated number pooled **across strata** within one `(model × class)` — pooling across
classes is forbidden (§5.1), pooling across strata is not. Per-stratum numbers are always reported
alongside; if per-stratum recall is more heterogeneous than sampling explains, the pooled figure is
not reported as the headline and the discrepant stratum is reported as the finding.

### 6.5 Freezing and ledger

Stratum D and N fixtures are frozen by a MANIFEST in the shape of
`docs/skill-evidence/arms/MANIFEST.md`: `git hash-object --no-filters` blob SHAs, a commit cell that
must contain the blob at the recorded path, header-resolved columns, a test re-checking every row.
Strata M and Q are frozen the same way inside the private corpus directory, with only the row count
and the manifest's digest committed to this repo.

Every cheap-tier invocation is counted in an append-only ledger with per-stage ceilings, arithmetic
checked by a test. Retries count.

## 7. Data handling

Qwen is self-hosted: no third-party egress, no restriction on which model may read which stratum.
`sauyon/drovr` is public; `modularml/modular` and `quitesh/quite-app` are not. Private fixtures and
probe transcripts live outside any checkout (`~/.local/share/drovr/cascade-corpus/`). Only
aggregates (recall, precision, counts, analysis) are committed — no diffs, no source excerpts, no
file paths from those repos, no defect description detailed enough to reconstruct internal design.

**Provenance typing.** Every fixture carries `provenance: Public | Private`, assigned at harvest
from the source repo's GitHub visibility, not from a path convention. A write guard refuses to write
`Private`-derived content to any path resolving inside a git checkout after canonicalisation, so a
symlink out of the corpus directory and back into the repo does not defeat it — shaped after
`ReviewOutcome::EmptyRange` (`cli/src/code_review.rs:94`): the illegal state is made unrepresentable
by requiring a fixture body be reached only through an accessor holding a token that proves the
destination was checked, rather than a guard at one call site. The write guard ships with its tests
(including the symlink-escape case) in the same change. Not closed: a human running an ad-hoc
command outside the harness.

## 8. Configuration

```toml
[review.cascade]
enabled = false            # DEFAULT, and it stays off in this run regardless of result
mode = "<undecided>"       # explorer | angle | file | change — SET BY TASK 0, not before (§4.1).
                           # No default ships until the measurement picks one.
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000       # expiry takes the degrade path of §3
```

The cheap tier runs **headless**, not as a herdr pane: `opencode run --agent plan -m <model>`,
verified working this session. Every cold `opencode` reviewer pane swallows its seed and the panel
cannot converge (`docs/known-issues.md:3437`), so the pane path is closed for this backend; `opencode
run` stdout is a subprocess pipe, not the rendered terminal view `cli/src/code_review.rs:1` refuses
to scrape. Read-only via `--agent plan` with `--auto` absent; the `readonly_displace` protection
(`cli/src/config.rs:589`) runs first.

`ko-ag/qwen3.6-35b-abliterated` is an abliterated build (safety tuning removed). Under every design
in §4, its output is either a routing decision or a context bundle, never a finding that reaches a
verdict.

**Guard-with-artifact.** Every set this run extends — config keys, the `mode` enum, the cheap
tier's output vocabulary, ledger columns, MANIFEST rows, fixture list, the class enum — has its
guarding test extended in the same change.

3. Corpus harvesters — class 1/2 attribution, class 3 blame-back — each reporting attrition.

   (model × stratum × class), each bar in order, ship decisions, §10 limitations, aggregates only.
9. Run ledger.

## 10. Stated limitations

1. Corpus construction, not model access, is now the largest limitation: every class is defined by
   a filter (comment→fix attribution, single-blame attribution, verified-real), and each filter
   selects a reachable subset of defects. Class 3 keeps only cleanly-attributable defects (7 of 40
   candidates, §5.4), which are plausibly the simpler ones — the measured ceiling may be optimistic
   in a direction no interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never an absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed entirely, which class 3 supplies.
4. Class 1 rests on modular and neovim only (§5.3).

## 11. Scope boundaries

**Out, deliberately:** flipping the `enabled` default on; changing the angle set, severity model,
merge or resume path; a second measurement instrument; fixing `docs/known-issues.md:3437` (the
headless cheap tier routes around it — the pane bug stays open and documented); any tier between
qwen and opus.
