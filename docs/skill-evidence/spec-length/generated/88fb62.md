# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`

## 1. Problem and shape of this run

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), every one on the same expensive model,
over the whole `base..head` range. Cost scales with `angles × range size`, and the driver re-runs
the panel unconditionally regardless of what the author already ran
(`docs/known-issues.md:589`).

A cheap-first cascade is the obvious saving and the obvious way to ship a silent regression: a
cheap tier's false negative is unrecoverable in most designs, and a `Clean` verdict produced that
way is byte-identical to a real one. This repo has hit that vacuous-pass class ten times
(`docs/known-issues.md:526`, `:589`).

**This run is a measurement with a feature attached, not a feature with a measurement attached.**
No cascade design is chosen until Task 0 (§3) reports where review cost actually goes. The feature
ships behind `enabled = false` (§8) regardless of outcome.

## 2. Binding invariant

> A cheap-tier failure must degrade to the baseline — a full expensive review — never to less
> review than the baseline would have given.

Applies to every design in §4:

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as today |

Router unavailable, timed out, crashed, out of context, unparseable, naming a unit not in the
range, or silently omitting a unit — all take the degrade path. No code path exists from "the
cheap tier had a problem" to "less review happened."

Designs differ in whether they have an unrecoverable-miss class at all; §7.4's ship bar is set
per design from that fact, not uniformly.

## 3. Decision: how the design is chosen

**Task 0** instruments expensive-tier reviews on a sample of fixtures and reports the cost split,
in tokens and wall-clock, as `E/(E+D)`:

- **E — exploration:** tool calls that search or read outside the diff (grep, reads of unchanged
  files, call-site following, reading tests).
- **D — diff-reading and finding-writing.**

Reported as a per-fixture distribution, not just a mean.

**Decision (pre-registered before the number is known):**

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 | cheap-as-explorer (§4.1) |
| ≤ 0.30 | per-file routing (§4.4) |
| 0.30 – 0.60 | angle routing (§4.2) |

Angle routing is additionally evaluated as a composable second stage under all three branches —
it is orthogonal to the router unit and its evaluation does not depend on the ratio.

Per-file routing (§4.4) runs as a measured control arm regardless of which branch the ratio
selects, so the spec reports what it would have cost and missed rather than assuming it away.

## 4. Candidate designs

### 4.1 Cheap tier as explorer

Cheap model builds a context bundle (call sites, tests, invariants, prior art); expensive model
reviews the whole diff with that bundle seeded in. No file or angle is skipped, so this design has
no unrecoverable-miss class — failure is a partial bundle, which degrades to the expensive tier
exploring for itself.

**Ship metric is non-inferiority of end-to-end defect recall against the unaided expensive panel
on the same fixtures** — not context completeness. A partial bundle can anchor the reviewer into
exploring less than if it had been handed nothing; that would be a silent recall loss, and
completeness doesn't detect it. Context completeness is retained only as a diagnostic for
explaining a failure after the fact, never as the bar.

### 4.2 Route by angle

Cheap tier handles angles with local judgement; expensive tier keeps `correctness` and `security`.
Smallest diff of any candidate (`cfg.angles` is already the fan-out dimension; change is a
per-angle `AgentLaunch` instead of one shared launch). Insensitive to the E/D ratio. No
unrecoverable-miss class — every angle is still reviewed by someone; failure is "the cheap tier
did a worse job on that angle," bounded and measurable per angle. "Local judgement" is measured
per angle, not assumed, using stratum D's per-angle findings (§5.6).

### 4.3 Whole-change triage

One decision per change: does it need deep review at all. Matches how exploration amortises
(per-change, not per-file) but is the highest-stakes decision available — one false clean loses
an entire change's review. **Not a general design.** Retained only as a narrow, conservative
complement on changes where near-certainty is available (dependency bumps, generated files, pure
formatting), expressed as a conservative rule, never a model judgement.

### 4.4 Per-file routing (control arm)

The original design, retained as a measured control regardless of §3's outcome. Structural
objection, decisive if it holds: a router judging a file in isolation cannot see relational
defects visible only from a call site, invariant, or test in a different file — a recall ceiling
no model quality fixes.

**Measured, not argued:** for every class-3 fixture, compare files the *fix* commit touched
against files the *introducing* PR changed. A defect whose fix lands outside the introducing diff
is one no per-file router could have routed to. That fraction is the empirical recall ceiling for
per-file designs, reported as a deliverable (§8 item 2).

## 5. Corpus

### 5.1 Ground-truth classes — never pooled into one recall figure

| class | signal | what it proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change | same, bot-found |
| 3 | post-merge fix / revert / regression-fix of code a PR introduced | review MISSED it |

Class 3 is the ceiling question; the design is weighted toward it. Class 2's "found by the kind
of agent being tested" circularity is addressed by the acceptance filter: the label requires a
human author to have agreed and changed the code, not merely that a bot commented. Reported
separately from class 1.

### 5.2 Strata — every stratum probed by every router model (full factorial, no legs)

| stratum | source | visibility | classes carried |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific (§5.6) |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

Neovim's role is diversity and reproducibility: a third language/codebase, and a public corpus
independently rebuildable off this machine. `ghostty-org/ghostty` was measured and rejected (9
inline comments per 40 merged PRs vs. neovim's 33).

### 5.3 Class 1/2 attribution — verified per fixture, never assumed from comment existence

- `commits == 1` disqualifies a PR (a single-commit PR cannot contain a comment-driven fix
  commit). Disqualifies modular 94850 and 95031 despite high comment counts.
- A later commit in the same PR must touch the commented file (ideally the commented lines); the
  verification method is recorded per fixture.
- Docs-only PRs excluded (modular 95055).

Primary class-1/2 fixture: modular PR 94953 (26 comments — 5 bot, 21 human — 9 files, 6 commits).
PR 94602 (13 human comments, 71 files, 5 commits) is available as a large-diff fixture if needed.

### 5.4 Reviewer composition

Of the 300 most recent review comments per repo: modular is 47 bot / 253 human; quite-app is 287
bot / 13 human (240 from `gemini-code-assist[bot]`; its only human reviewer is `sauyon`, 13
comments). **quite-app cannot carry class 1** — it has essentially no human review. Results are
reported per repo and per class; a thin cell is reported as thin, never merged into a neighbour.

### 5.5 Class 3 pipeline

1. Candidate fix commits: `git log -i --grep` for `revert|regression|broke` and kin.
2. `git blame` the lines the fix deleted or replaced, at `fix^`.
3. Require a single introducing commit; fan-out (multiple introducing commits) is rejected as not
   cleanly attributable.
4. That commit's PR at pre-merge state is the fixture; the fix commit's diff states the defect.

Validated end-to-end on quite-app: fix `cb1adad` → deleted lines in
`quited/qrun/src/sip_clone.rs` → blame resolves to single commit `55b80032`.

Attrition is reported, not hidden: of 40 class-3 candidates sampled in quite-app, only 7 touched
≤ 2 files (step 3's single-attribution requirement rejects the rest).

### 5.6 Stratum D — scored as two stratified cells (decision: `both-stratified`)

Source: `~/.local/share/drovr/runs/skill-stickiness/` — 376 per-angle findings files across 100
panels over 22 tasks, plus every `<task>-base.sha` / `<task>-review-<iter>.head`. All 100 head and
22 base SHAs resolve from this worktree (`git rev-parse --git-common-dir` →
`/home/sauyon/devel/drovr/.git`). 131 blocking findings: 79 `.rs`, 51 `.md`, 1 `.json`, over 20
tasks.

Labels: *verified-real* (a fix landed, or written up in `docs/known-issues.md`) — the only set
that feeds the ship bar; *unverified* — reported, not scored; *rejected* — excluded with reason
recorded.

**`D-rs`** (79 blocking findings pre-filter) and **`D-md`** (51, skill/scenario prose) are
measured and reported separately, never summed. **The ship bar must pass on `D-rs` alone**;
`D-md` is reported with its own interval and cannot rescue a failing `D-rs`. Rejected alternative:
scoring `.md` only would have been cheaper but was rejected — Rust and prose review are different
tasks a cascade could be good at one and useless at the other, and pooling would hide that.

## 6. Data handling

**Qwen is self-hosted.** No third-party egress; no restriction on which model reads which
stratum. (Supersedes an earlier egress constraint based on a mistaken premise — that constraint,
its two-legs corpus structure, and the qwen-on-real-traffic gap it caused are withdrawn in full.)

What is unchanged: `sauyon/drovr` is public; `modularml/modular` and `quitesh/quite-app` are not.
Private fixtures and probe transcripts live outside any git checkout
(`~/.local/share/drovr/cascade-corpus/`). Only aggregates are committed — recall, precision,
counts, analysis. No diffs, source excerpts, file paths, or defect descriptions detailed enough to
reconstruct internal design from those repos.

**Contract: write guard.** Every fixture carries a `provenance: Public | Private` field, assigned
at harvest time from the source repo's GitHub visibility (not from a path convention or
recollection). The write guard refuses to write `Private`-derived content to any path resolving
inside a git checkout, after canonicalisation — a symlink out of the corpus directory and back
into the repo does not defeat it. Modeled on `ReviewOutcome::EmptyRange`
(`cli/src/code_review.rs:94`): the guard is a type-level property, not a call-site check — a
fixture's body is reachable only through an accessor requiring a token proving the destination was
checked. Ships with tests in the same change, including the symlink-escape case.

The prior egress guard is withdrawn with its premise; `provenance` keeps its one remaining
consumer (the write guard) rather than serving two purposes with one vestigial.

**Not closed by this run:** a human running an ad-hoc command outside the harness can still leak
private content. Recorded as a residual gap, not solved here.

## 7. The measurement

### 7.1 Arms

`router_model ∈ {qwen, sonnet}` × `stratum ∈ {D, M, Q, N}` × `class ∈ {1, 2, 3}`, design fixed by
§3's decision rule, per-file routing (§4.4) run as a control arm alongside.

**Contract:** the ship decision is per router model — `router_agent` and `router_model` are
separate config keys (§8). A sonnet-routed cascade and a qwen-routed cascade are shipped/not
shipped independently.

### 7.2 Class 3 gating (decision: `gates-conditional`)

For classes 1, 2, and stratum D, the expensive tier found the defect by construction. Class-3
defects were missed by review, so the expensive tier may miss them too, and the cheap tier cannot
be blamed for a defect the expensive tier would also have missed. Two numbers, one gates:

- **Conditional recall** (gates): of the class-3 defects the expensive tier finds, how many
  survive the cascade.
- **Expensive-tier absolute detection rate on class 3** (does not gate): what fraction of
  review-missed defects the full panel finds at all. Reported as the run's most interesting
  scientific output — the ceiling of the review system as a whole — but not a decision input.

### 7.3 Discrimination and stopping

Two free synthetic controls bracket every metric: **NULL** (everything cleared; recall 0, saving
maximal) and **FLOOD** (everything escalated; recall 1.0, saving 0). Per stratum and per class, a
real cheap tier must land strictly inside the bracket on both axes, or those fixtures are rebuilt
before anything is scored. (Motivation: the prior run's instrument did not discriminate —
unaided agents scored 3/4 and 4/4 with no skill at all.)

**Positive control:** re-running the expensive tier on a sample must re-find recorded class-1/2
defects at a high rate, or the fixtures are not reviewable in isolation and the corpus is
re-cut — not the cheap tier retuned.

**Dev/held-out split** assigned before any cheap-tier prompt is written, at task/PR level (no diff
in both sets). Held-out is scored once, after the prompt is frozen and its `git hash-object`
recorded. No `blind-map.json` — a deliberate departure from the prior protocol: the threat here is
prompt overfitting (the split is the control), not scorer bias (scoring is set membership with no
human judgement), so a blind map buys nothing.

### 7.4 Ship bar (decision: `by-failure-mode`, non-uniform)

N is not the binding constraint — qwen is unlimited and may read every stratum, so the corpus is
sized to the power the bar needs.

Bar is set by failure mode (§2's distinction), not uniformly:

- **Designs with an unrecoverable-miss class** (per-file, whole-change): a miss is a defect nobody
  ever looks at again. **Recall ≥ 0.98, Wilson 95% LB ≥ 0.95, target N ≥ 142 per gated cell.**
- **Designs whose failure degrades to baseline** (angle routing, cheap-as-explorer): failure is a
  cost regression, not a lost defect. **Non-inferiority against the unaided expensive panel — the
  cascade's recall LB ≥ 0.90 of the unaided panel's point estimate, target N ≥ 69.**

Rejected: pushing either bar higher (e.g. LB ≥ 0.97, N = 239 for two-miss tolerance) — the gain is
smaller than the uncertainty already contributed by corpus construction (§7.5), and the corpus
budget is worth more spent on a fourth stratum than a tighter interval over three.

**Evaluation order:** (0) N floor met, else null for that cell — (1) instrument discriminates
(§7.3) — (2) recall bar above — (3) escalation/skip rate leaves a real saving — (4) measured
end-to-end cost < 0.80× the non-cascade panel. **Bars 1 and 2 are the ship decision.** Failing 3
or 4 ships the code behind `enabled = false` with the negative economics written up. Precision,
hint quality, context completeness, and class-3 absolute detection are reported but are not
decision inputs.

**Contract: N pooling.** `N ≥ 142` per `(model × stratum × class)` cell would require 24 cells and
is not reachable. The gated floor applies to the number **pooled across strata within one
`(model × class)`** — pooling across strata buys power; pooling across classes would destroy
meaning (§5.1 forbids only the latter). Per-stratum numbers are always reported alongside pooled
ones. Pooling is conditional: if per-stratum recall is more heterogeneous than sampling explains,
the pooled figure is not reported as the headline, and the discrepant stratum is reported as its
own finding.

**Contract: freezing.** Strata D and N fixtures are frozen by a MANIFEST in the shape of
`docs/skill-evidence/arms/MANIFEST.md` — `git hash-object --no-filters` blob SHAs, a commit cell
that must contain the recorded blob at the recorded path, header-resolved columns, a test
re-checking every row. Strata M and Q are frozen the same way inside the private corpus directory,
with only the row count and the manifest's digest committed publicly.

**Contract: ledger.** Every cheap-tier invocation is counted in an append-only ledger with
per-stage ceilings; arithmetic checked by a test. Retries count.

### 7.5 Stated limitations

1. Corpus construction, not model access, is now the largest limitation. Every class is defined
   by a filter (comment→fix attribution, single-blame attribution, verified-real), and each filter
   selects a reachable subset of defects — class 3 keeps only cleanly-attributable defects (7 of
   40 candidates in the §5.5 sample), which are plausibly the simpler ones. The measured ceiling
   may be optimistic in a direction no confidence interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never an absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed entirely; class 3 is what supplies that.
4. Class 1 rests on modular and neovim only (§5.4 — quite-app cannot carry it).

## 8. Configuration and deliverables

```toml
[review.cascade]
enabled = false            # default, and stays off in this run regardless of result
mode = "<undecided>"       # explorer | angle | file | change — SET BY TASK 0 (§3), not before.
                            # No default ships until the measurement picks one.
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000        # expiry takes the degrade path of §2
```

**Contract: cheap-tier execution.** Runs headless — `opencode run --agent plan -m <model>` — not
as a herdr pane. Every cold `opencode` reviewer pane swallows its seed and the panel cannot
converge (`docs/known-issues.md:3437`), so the pane path is closed for this backend; `opencode
run`'s stdout is a subprocess pipe, not the rendered terminal view `cli/src/code_review.rs:1`
refuses to scrape. Read-only via `--agent plan` with `--auto` absent; the `readonly_displace`
protection (`cli/src/config.rs:589`) runs first, ahead of anything cascade-specific.

`ko-ag/qwen3.6-35b-abliterated` is an abliterated build (safety tuning removed). Recorded because
omitting it would describe a different experiment. Under every design in §4, its output is either
a routing decision or a context bundle — never a finding that reaches a verdict directly.

**Deliverables:**

1. Task 0 cost instrumentation and its report.
2. Relational-defect recall ceiling for per-file routing (§4.4).
3. Corpus harvesters — class 1/2 attribution, class 3 blame-back — each reporting attrition.
4. Fixtures + MANIFESTs; D and N committed, M and Q private.
5. `provenance` typing, write guard, and tests (§6).
6. Cheap-tier implementation for the mode selected by §3, plus the per-file control arm.
7. Cascade stage in `cli/src/code_review.rs`, behind `enabled = false`.
8. `docs/cascade-evidence/results.md`: controls, dev numbers, one held-out score per
   `(model × stratum × class)`, each ship-bar check in order, ship decisions, §7.5 limitations,
   aggregates only (no private-repo content, per §6).
9. Run ledger.

**Contract: every set this run extends carries its own guarding test in the same change** — config
keys, the `mode` enum, the cheap tier's output vocabulary, ledger columns, MANIFEST rows, fixture
list, the class enum. This is the discipline that prevents the vacuous-pass class described in
§1.

## 9. Out of scope

- Flipping `enabled` on by default.
- Changing the angle set, severity model, merge path, or resume path.
- A second measurement instrument beyond this one.
- Fixing the `opencode` pane seed bug (`docs/known-issues.md:3437`) — the headless cheap tier
  routes around it; the pane bug stays open and documented, unfixed.
- Any router tier between qwen and opus.

## 10. Decisions

Approved 2026-08-06, turn 1. All four questions were answered at the gate; they bind the plan
phase and are not re-litigated there.

the decision that was made.

No open questions remain. Anything the plan phase discovers outside these four is a new question
for a new gate, not a gap in this one.
