# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`
**Status:** approved 2026-08-06, turn 1. No open questions remain.

## 1. Problem and shape of this run

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), every one on the same expensive model,
over the whole `base..head` range. Cost scales with `angles × range size`, and the driver re-runs
the panel unconditionally on top of whatever the author already ran (`docs/known-issues.md:589`).

This run is a **measurement with a feature attached**, not a feature with a benchmark attached. The
cascade design is chosen by the measurement (§3), not committed to up front. The feature ships
**off by default** regardless of outcome (§8); a positive result changes the default in a later run,
not this one.

## 2. Binding invariant

> **A cheap-tier failure must degrade to the baseline — a full expensive review — never to less
> review than the baseline would have given.**

Instantiated per design, and every design in §3 is judged against its own row:

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as today |

Router unavailable, timed out, crashed, out of context, unparseable, naming a unit not in the
range, or silently omitting a unit — every one takes the degrade path. There is no code path from
"the cheap tier had a problem" to "less review happened".

**Designs split into two failure classes**, and §7.4's ship bar is set from this split rather than
uniformly:

- **Unrecoverable-miss designs** (per-file routing, whole-change triage): a miss is a defect nobody
  ever looks at again.
- **Degrades-to-baseline designs** (angle routing, cheap-as-explorer): a miss is a cost regression —
  the expensive tier still reviews everything.

## 3. Design selection: measure first

**Decision (`decisionrule: measure-first`) — APPROVED.** Task 0 instruments expensive-tier reviews
on a sample of fixtures and reports the cost split, in tokens and wall-clock, as `E/(E+D)` with a
per-fixture distribution (not just a mean):

- **E — exploration:** tool calls that search or read outside the diff (grep, file reads of
  unchanged files, following call sites, reading tests).
- **D — diff-reading and finding-writing:** reading the diff itself, reasoning over it, composing
  findings.

The design is picked by a rule pre-registered before the number is known:

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 — exploration dominates | cheap-as-explorer |
| ≤ 0.30 — diff-reading dominates | per-file routing |
| 0.30 – 0.60 | angle routing (insensitive to the ratio) |

**Angle routing is additionally evaluated as a composable second stage in all three branches** — it
is orthogonal to the ratio, so it is measured regardless of which primary design wins.

**Per-file routing runs as a measured control arm regardless of which design the rule selects**, so
the spec reports what it would have cost and missed rather than assuming it away. Its ship metric
includes the **relational-defect recall ceiling**: for every class-3 fixture, compare the files the
*fix* commit touched against the files the *introducing* PR changed — a defect whose fix lands
outside the introducing diff is one no per-file router could have routed correctly, computed from
real defects rather than argued (this is a required deliverable, §8).

**Cheap-as-explorer's ship metric is non-inferiority of end-to-end defect recall against the unaided
expensive panel on the same fixtures** — not context completeness — because a partial context bundle
may anchor the reviewer into exploring less, and only an end-to-end recall comparison catches that.
Context completeness is retained as a diagnostic for explaining a failure, not as the bar.

**Whole-change triage is scoped to a narrow, conservative complement**, not a general design: it is
expressed as a conservative rule (dependency bumps, generated files, pure formatting), never as a
model judgement, because a false-clean there loses an entire change's review.

## 4. Corpus

### 4.1 Ground-truth classes

| class | signal | what it proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change | same, bot-found |
| 3 | post-merge fix / revert / regression-fix of code a PR introduced | review MISSED it |

Classes are **never pooled into one recall figure** — they differ in difficulty and meaning.

Class 2's label is not "a bot said so" but "a human author agreed and changed the code" (the
acceptance filter); it is reported separately from class 1 so a reader who disputes the filter can
discount it independently.

### 4.2 Strata

| stratum | source | visibility | classes carried |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific (§4.5) |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin — §4.4) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

Every stratum is probed by every router model: the design is a full factorial
`router_model × stratum × class`, with no model-access-based subsetting.

### 4.3 Class 1/2 attribution contract

A PR qualifies as class 1 or 2 only if all hold:

- **`commits == 1` disqualifies the PR** — a single-commit PR cannot contain a comment-driven fix
  commit.
- **A later commit in the same PR must touch the commented file**, ideally the commented lines. How
  it was verified is recorded per fixture; "the comment exists" is never accepted on its own.
- Docs-only PRs are excluded.

Selected fixtures: modular **PR 94953** (26 comments — 5 bot, 21 human — 9 files, +339/−158, 6
commits) is the primary class-1/2 candidate. Modular **PR 94602** (13 human comments, 71 files,
+6851/−108, 5 commits) is available as a large-diff fixture if one is wanted.

`quite-app` carries essentially no human review (13 human comments in the last 300 vs. 287 bot) and
does not carry class 1. Results are reported **per repo and per class**; a thin cell is recorded as
thin, never merged into a neighbour.

### 4.4 Class 3 harvesting contract

1. Candidate fix commits: `git log -i --grep` for `revert|regression|broke` and kin.
2. `git blame` the lines the fix **deleted or replaced**, at `fix^`.
3. Require a **single introducing commit** — fan-out means the defect is not cleanly attributable;
   reject.
4. That commit's PR at pre-merge state **is** the fixture; the fix commit's diff states what the
   defect was and where. Human-authored label, no invention.

Harvesters report attrition at every stage: candidates → single-attribution → adjudicated-as-defect.
Attrition is expected to be severe (validated during investigation at roughly 7 of 40 candidates
surviving to single-attribution in `quite-app`) and is reported as a stated limitation (§6.5), not
smoothed over.

### 4.5 Stratum D

Source: `~/.local/share/drovr/runs/skill-stickiness/` — per-angle findings files across prior
panels, plus every `<task>-base.sha` and `<task>-review-<iter>.head`. Findings carry their angle,
which is what makes the angle-routing premise testable per angle rather than assumed.

Labels: **verified-real** (a fix landed, or it is written up in `docs/known-issues.md`) — the only
set that feeds the ship bar; **unverified** — reported, not scored; **rejected** — excluded with the
reason recorded.

**Decision (`corpus: both-stratified`) — APPROVED.** Stratum D is scored as two stratified cells,
`D-rs` (Rust findings) and `D-md` (prose/skill/scenario findings), measured and reported separately
and never summed into one stratum-D number. **The ship bar must pass on `D-rs` alone**; `D-md` is
reported with its own interval and cannot rescue a failing `D-rs`. Reason: reviewing Rust and
reviewing prose are different tasks a cheap tier could be good at one and useless at the other, so
pooling would hide a domain-shaped competence gap.

## 5. Data handling

**Qwen is self-hosted: no third-party egress, no restriction on which model may read which
stratum.** A prior egress-based restriction (a two-tier "legs" structure keyed to model provenance)
is withdrawn in full as based on a mistaken premise.

**What is unchanged:** `sauyon/drovr` is public; `modularml/modular` and `quitesh/quite-app` are
not. Private fixtures and probe transcripts live outside any git checkout
(`~/.local/share/drovr/cascade-corpus/`). Only aggregates are committed — recall, precision, counts,
analysis — never diffs, source excerpts, file paths from those repos, or defect descriptions
detailed enough to reconstruct internal design.

**Provenance contract.** Every fixture carries `provenance: Public | Private`, assigned at harvest
from the source repo's GitHub visibility, never from a path convention or recollection. A **write
guard** refuses to write `Private`-derived content to any path resolving inside a git checkout,
after canonicalisation (so a symlink out of the corpus directory and back into the repo does not
defeat it). Shaped after `ReviewOutcome::EmptyRange` (`cli/src/code_review.rs:94`): a fixture's body
is reachable only through an accessor requiring a token proving the destination was checked — the
guard lives in the type, not at a call site. The write guard ships with tests in the same change,
including the symlink-escape case (**guard-with-artifact**, §7).

`provenance` now has a single consumer (the write guard); the egress guard is withdrawn with its
premise rather than kept as a second, now-vestigial, consumer of the same field.

**Not closed by this design:** a human running an ad-hoc command outside the harness.

## 6. The measurement

### 6.1 Arms

`router_model ∈ {qwen, sonnet}` × `stratum ∈ {D, M, Q, N}` × `class ∈ {1, 2, 3}`, plus per-file
routing as a control arm (§3). The ship decision is made **per router model** — a sonnet-routed
cascade is a different product from a qwen-routed one — so `router_agent`/`router_model` are
separate config keys (§8).

### 6.2 Class 3 metric — `class3gate: gates-conditional` — APPROVED

For classes 1, 2, and stratum D the expensive tier found the defect by construction. Class-3
defects were missed by review, so the expensive tier may miss them too, and a cheap tier cannot be
blamed for failing on a defect the expensive tier would also fail on. Two numbers are reported:

- **Conditional recall** (gates): of the class-3 defects the *expensive tier* finds, how many
  survive the cascade. This is the cascade-safety number on the hardest defects available.
- **Expensive-tier absolute detection rate on class 3** (does not gate): what fraction of
  review-missed defects the full panel finds at all — reported as the run's scientific output on the
  ceiling of the review system as a whole, not a decision input.

### 6.3 Discrimination and stopping controls

- **NULL** (everything cleared: recall 0, saving maximal) and **FLOOD** (everything escalated:
  recall 1.0, saving 0) bracket every metric. **Per stratum and per class**, a real cheap tier must
  land strictly inside the bracket on both axes, or those fixtures are rebuilt before anything is
  scored.
- **Positive control:** re-running the expensive tier on a sample must re-find recorded class-1/2
  defects at a high rate. If not, the fixtures are not reviewable in isolation and the corpus is
  re-cut — the cheap tier is not touched.
- **Dev/held-out split**, assigned before any cheap-tier prompt is written, at task/PR level so no
  diff appears in both. Held-out is scored **once**, after the prompt is frozen and its
  `git hash-object` recorded. There is **no `blind-map.json`** — a deliberate departure from the
  prior run's protocol, recorded as a decision: the threat here is prompt overfitting, not scorer
  bias (scoring is set membership with no human judgement), so the dev/held-out split is the
  load-bearing control and a blind map adds nothing.

### 6.4 Ship bar — `barshape: by-failure-mode` — APPROVED, non-uniform

Corpus size is set by the power the bar needs, not the bar trimmed to fit the corpus (qwen is
unlimited and may read every stratum, so N is no longer bounded by model access).

- **Unrecoverable-miss designs** (per-file, whole-change): **recall ≥ 0.98 with Wilson 95% lower
  bound ≥ 0.95**, target **N ≥ 142** per gated cell.
- **Degrades-to-baseline designs** (angle routing, cheap-as-explorer): **non-inferiority** against
  the unaided expensive panel, cascade recall lower bound ≥ 0.90 of the unaided panel's point
  estimate, target **N ≥ 69** per gated cell.

Reason for the split: demanding LB ≥ 0.95 on a design whose failure is only a cost regression buys
nothing real and costs a corpus. Reason for not going higher than LB ≥ 0.95 on the unrecoverable
designs: N = 239 for a two-miss tolerance at LB ≥ 0.97 buys a 0.02 tightening in a bound whose real
uncertainty is dominated by corpus-construction choices (§6.5), not sampling error — that corpus
spend buys more validity as a fourth stratum than as a tighter interval over three.

**Gate order:** **0.** N floor met for the cell, else the cell is null. **1.** Instrument
discriminates (§6.3). **2.** The recall bar above. **3.** Escalation/skip rate leaves a real saving.
**4.** Measured end-to-end cost < 0.80× the non-cascade panel.

**Bars 1 and 2 are the ship decision.** Failing 3 or 4 ships the code behind its off-by-default flag
with the negative economics written up — it does not block shipping the mechanism. Precision, hint
quality, context completeness, and class-3 absolute detection are reported and are **not** decision
inputs.

**Pooling contract.** `N ≥ 142` per `(model × stratum × class)` cell is 24 cells and unreachable. The
gated number pools across **strata** within one `(model × class)` — pooling across strata buys
power; pooling across **classes** is forbidden (§4.1) because it destroys meaning. Per-stratum
numbers are always reported alongside the pooled figure. **Pooling is conditional on agreement**: if
per-stratum recall is more heterogeneous than sampling explains, the pooled figure is not reported
as the headline, and the discrepant stratum is reported as the finding it is.

### 6.5 Freezing and ledger

- Stratum D and N fixtures are frozen by a MANIFEST in the shape of
  `docs/skill-evidence/arms/MANIFEST.md`: `git hash-object --no-filters` blob SHAs, a commit cell
  that must contain the blob at the recorded path, header-resolved columns, and a test re-checking
  every row.
- Strata M and Q are frozen the same way in the private corpus directory, with only the row count
  and the manifest's digest committed to the public repo.
- Every cheap-tier invocation is counted in an append-only **ledger** with per-stage ceilings;
  ledger arithmetic is checked by a test. Retries count.

### 6.6 Stated limitations (carried into the results writeup, not resolved by this spec)

1. Corpus construction, not model access, is now the largest limitation: every class is defined by a
   filter (comment→fix attribution, single-blame attribution, verified-real), each filter selects a
   *reachable* subset of defects, and cleanly-attributable defects are plausibly the simpler ones —
   the measured ceiling may be optimistic in a direction no interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never an absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed; class 3 supplies that.
4. Class 1 rests on modular and neovim only.

## 7. Configuration and deliverables

```toml
[review.cascade]
enabled = false            # DEFAULT, and it stays off in this run regardless of result
mode = "<undecided>"       # explorer | angle | file | change — SET BY TASK 0, not before (§3).
                            # No default ships until the measurement picks one.
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000        # expiry takes the degrade path of §2
```

`router_agent` / `router_model` are separate keys from the above per §6.1 (per-router-model ship
decision).

**Cheap-tier execution contract.** The cheap tier runs **headless**, not as a herdr pane:
`opencode run --agent plan -m <model>`. This is load-bearing, not stylistic: every cold `opencode`
*reviewer pane* swallows its seed and the panel cannot converge (`docs/known-issues.md:3437`), so
the pane path is closed for this backend. `opencode run` stdout is a subprocess pipe, not the
rendered terminal view `cli/src/code_review.rs:1` refuses to scrape. The cheap tier is read-only via
`--agent plan` with `--auto` absent, and the existing `readonly_displace` protection
(`cli/src/config.rs:589`) runs first.

**Guard-with-artifact.** Every set this run extends — config keys, the `mode` enum, the cheap tier's
output vocabulary, ledger columns, MANIFEST rows, the fixture list, the class enum — has its guarding
test extended in the same change that extends it.

**Deliverables:**

1. Task 0 cost instrumentation and its report (§3).
2. Relational-defect recall ceiling for per-file routing (§3).
3. Corpus harvesters — class 1/2 attribution (§4.3), class 3 blame-back (§4.4) — each reporting
   attrition.
4. Fixtures + MANIFESTs; D and N committed, M and Q private (§6.5).
5. `provenance` typing, write guard, tests (§5).
6. Cheap-tier implementation for the selected mode, plus the per-file control arm.
7. Cascade stage in `cli/src/code_review.rs`, behind `enabled = false`.
8. `docs/cascade-evidence/results.md` — controls, dev numbers, one held-out score per
   `(model × stratum × class)`, each gate in order, ship decisions, §6.6 limitations, aggregates
   only (no private-repo content per §5).
9. Run ledger.

## 8. Scope boundaries

**Out, deliberately:**

- Flipping the `enabled` default on.
- Changing the angle set, severity model, merge or resume path.
- A second measurement instrument.
- Fixing `docs/known-issues.md:3437` (the headless cheap tier routes around it; the pane bug stays
  open and documented).
- Any tier between qwen and opus.

**Model disclosure.** `ko-ag/qwen3.6-35b-abliterated` is an **abliterated** build (safety tuning
removed). This is recorded because a writeup omitting it would describe a different experiment.
Under every design in §3, its output is either a routing decision or a context bundle — never a
finding that reaches a verdict.
