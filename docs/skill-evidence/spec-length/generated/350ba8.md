# Tiered (cascade) code review for drovr

**Run:** `tiered-review` · **Worktree:** `.drovr/wt/tiered-review` · **Branch:** `drovr/tiered-review`

## 1. Problem

`drovr code-review run` spawns one read-only reviewer per angle (`correctness`, `security`,
`error-handling`, `type-design` — `cli/src/config.rs:436`), every one on the same expensive model,
over the whole `base..head` range. Cost scales with `angles × range size`, and the driver re-runs
the panel unconditionally on top of whatever the author already ran (`docs/known-issues.md:589`).

This run is a **measurement with a feature attached**, not a feature with a measurement bolted on.
No cascade design ships until it clears the bars in §7.4, and `enabled = false` regardless of
outcome (§8).

## 2. Binding invariant

> **A cheap-tier failure must degrade to the baseline — a full expensive review — never to less
> review than the baseline would have given.**

Instantiated per design:

| design | cheap-tier failure degrades to |
|---|---|
| per-file / whole-change routing | that unit escalates; nothing is skipped on error |
| angle routing | that angle re-runs on the expensive tier |
| cheap-as-explorer | the expensive tier explores for itself, exactly as today |

Router unavailable, timed out, crashed, out of context, unparseable, naming a unit not in the
range, or silently omitting a unit — every one takes the degrade path. No code path exists from
"the cheap tier had a problem" to "less review happened".

Designs differ in whether they have an unrecoverable-miss class at all; §7.4's ship bar is set from
that fact per design, not uniformly.

## 3. Decision: unit of escalation is measured, not chosen — `measure-first` (APPROVED)

**Task 0 — cost instrumentation**, run before any design is committed to. Instrument expensive-tier
reviews on a sample of fixtures and report the split, in tokens and wall-clock:

- **E — exploration:** tool calls that search or read outside the diff (grep, reads of unchanged
  files, following call sites, reading tests).
- **D — diff-reading and finding-writing:** reading the diff itself, reasoning over it, composing
  findings.

Reported as `E/(E+D)` with a per-fixture distribution, not just a mean.

**Pre-registered decision rule**, binding on Task 0's output:

| measured `E/(E+D)` | primary design |
|---|---|
| ≥ 0.60 — exploration dominates | cheap-as-explorer (§4.1) |
| ≤ 0.30 — diff-reading dominates | per-file routing (§4.4), evaluated as the control arm regardless |
| 0.30 – 0.60 | angle routing (§4.2) |

Angle routing is additionally evaluated as a composable second stage in all three branches — it is
orthogonal to the ratio and to whichever primary design is selected.

## 4. Design contracts (selection among these is governed by §3)

### 4.1 Cheap tier as explorer / context-builder

Cheap model locates call sites, related tests, invariants, prior art, and hands the expensive model
a context bundle; the expensive model reviews the **whole** diff with that bundle in its seed.
Nothing is skipped, so this design has no unrecoverable-miss class — failure (an incomplete bundle)
degrades to the expensive tier exploring for itself.

**Ship metric: non-inferiority of end-to-end defect recall against the unaided expensive panel on
the same fixtures** — not context completeness. Reason: "the expensive tier will notice the gap and
explore further" is a hypothesis, not a property; a partial bundle can anchor the reviewer into
exploring *less* than one handed nothing, which context-completeness cannot detect. Context
completeness (did the bundle contain the file/symbol the defect required?) is retained only as a
diagnostic for explaining a failure, never as the bar.

### 4.2 Route by angle

Cheap handles angles whose judgement is local; expensive keeps correctness and security. Change is
a per-angle `AgentLaunch` instead of one shared launch. Insensitive to the E/D ratio. Has no
unrecoverable-miss class — every angle is still reviewed by someone; failure is "the cheap tier did
a worse job on that angle," bounded and measurable per angle. "Local judgement" must be measured per
angle (the corpus supports this — stratum D findings carry their angle), not assumed.

### 4.3 Whole-change triage — narrow complement only, not a general design

One decision per change: does it need deep review at all. **Decision: not adopted as the general
mechanism** — a false-clean here loses an entire change's review, which would require a recall bar
this run is not built to clear at that stakes level. **Retained only as a conservative complement**
on changes where near-certainty is available (dependency bumps, generated files, pure formatting),
expressed as a fixed conservative rule, never as a model judgement.

### 4.4 Per-file routing — retained as a measured control arm regardless of §3's outcome

Kept in the run whatever the decision rule selects, so the spec reports what it *would* have cost
and missed rather than assuming it away.

**Deliverable: empirical recall ceiling for any per-file design.** For every class-3 fixture,
compare the files the *fix* commit touched against the files the *introducing* PR changed. A defect
whose fix lands outside the introducing diff is one no per-file router could have routed correctly;
that fraction is the ceiling, computed from real defects.

## 5. Corpus

### 5.1 Ground-truth classes — never pooled into one recall figure

| class | signal | what it proves |
|---|---|---|
| 1 | human review comment that caused a change in the same PR | review caught it pre-merge |
| 2 | **accepted** bot review comment that caused a change | same, bot-found |
| 3 | post-merge fix / revert / regression-fix of code a PR introduced | review MISSED it |

Class 2's label is "a *human author* agreed and changed the code," not "a bot said so" — this is
what rescues it from the found-by-the-kind-of-agent-being-tested problem. Reported separately from
class 1.

### 5.2 Strata — full factorial, every stratum probed by every router model

| stratum | source | visibility | classes |
|---|---|---|---|
| D — drovr | `skill-stickiness` run artifacts | public | drovr-specific (§5.6) |
| M — modular | `modularml/modular` | private | 1, 2, 3 |
| Q — quite-app | `quitesh/quite-app` | private | 2, 3 (class 1 too thin, §5.4) |
| N — neovim | `neovim/neovim` | public | 1, 2, 3 |

Design: `router_model × stratum × class`, no "legs" (model access is not a stratifying factor —
§6). N is included for corpus diversity and reproducibility (third language, rebuildable off this
machine): 33 inline review comments per 40 merged PRs measured this session (`ghostty-org/ghostty`
yielded 9/40 and is excluded).

### 5.3 Class 1/2 attribution — verification contract

- `commits == 1` disqualifies a PR (a single-commit PR cannot contain a comment-driven fix commit).
  Disqualifies modular PR 94850 (13 human comments, 16 files) and PR 95031 (11 comments, 11 files).
- A later commit in the same PR must touch the commented file, ideally the commented lines. The
  verification method is recorded per fixture; "the comment exists" is never accepted as proof.
- Docs-only PRs are excluded (modular PR 95055, 12 comments).

Selected fixture: modular PR 94953 — 26 comments (5 bot, 21 human), 9 files, +339/−158, 6 commits.
PR 94602 (13 human comments, 71 files, +6851/−108, 5 commits) is available as a large-diff fixture
if wanted.

### 5.4 Reviewer composition

Of the 300 most recent review comments: modular is 47 bot / 253 human (top: `cursor[bot]` 36,
ferasboulala 30, NathanSWard 21, JoeLoser 17, rachfop 12, zyx-billy 11); quite-app is 287 bot / 13
human (top: `gemini-code-assist[bot]` 240, coderabbitai 46, cursor 1; only human is `sauyon`, 13).

**Decision: quite-app cannot carry class 1** (essentially no human review). Results are reported per
repo and per class; a thin cell is recorded as thin, never merged into a neighbour. Neovim is what
keeps class 1 from resting on modular alone.

### 5.5 Class 3 pipeline — validated end-to-end

1. Candidate fix commits: `git log -i --grep` for `revert|regression|broke` and kin.
2. `git blame` the lines the fix **deleted or replaced**, at `fix^`.
3. Require a single introducing commit; fan-out (multiple introducing commits) is rejected as not
   cleanly attributable.
4. That commit's PR at pre-merge state is the fixture; the fix commit's diff states the defect and
   its location. Human-authored label, no invention.

Validated on quite-app: fix `cb1adad` → deleted lines in `quited/qrun/src/sip_clone.rs` → blame
resolves to single commit `55b80032`.

Raw signal (matching commits in last 2000, overlapping, case-insensitive): modular Revert 28 /
regression 70 / broke 26; quite-app 29 / 36 / 28.

**Attrition is reported.** Of 40 class-3 candidates sampled in quite-app, only 7 touched ≤ 2 files —
step 3 rejects the rest as batched fixes. Harvesters report candidates → single-attribution →
adjudicated-as-defect at every stage.

### 5.6 Stratum D — scored as two stratified cells — `both-stratified` (APPROVED)

`~/.local/share/drovr/runs/skill-stickiness/` holds 376 per-angle findings files across 100 panels
over 22 tasks, plus every `<task>-base.sha` and `<task>-review-<iter>.head`. All 100 head SHAs and
22 base SHAs resolve from this worktree (shared object database, `git rev-parse --git-common-dir` →
`/home/sauyon/devel/drovr/.git`). 131 blocking findings: 79 `.rs`, 51 `.md`, 1 `.json`, over 20
tasks. Findings carry their angle, which makes §4.2's per-angle premise testable.

Labels: *verified-real* (a fix landed, or it is written up in `docs/known-issues.md`) — the only set
that feeds the ship bar; *unverified* — reported, not scored; *rejected* — excluded with the reason
recorded.

**Decision: `D-rs` (79 blocking findings pre-filter) and `D-md` (51, skill/scenario prose) are
measured and reported separately, never summed.** The ship bar must pass on `D-rs` alone; `D-md` is
reported with its own interval and cannot rescue a failing `D-rs`. Reason: reviewing Rust and
reviewing prose are different tasks a cheap tier could be good at one and useless at the other —
pooling would hide that, and `D-md` is a free second look at whether competence is domain-shaped.

## 6. Data handling

**Decision: the egress constraint from the prior protocol is withdrawn in full**, including the
two-legs structure it forced. Qwen is self-hosted — no third-party egress, no restriction on which
model may read which stratum.

**What is unchanged, because it was always about publishing, not about which model reads what:**
`sauyon/drovr` is public; `modularml/modular` and `quitesh/quite-app` are not. Private fixtures and
probe transcripts live outside any checkout (`~/.local/share/drovr/cascade-corpus/`). Only
aggregates are committed — recall, precision, counts, analysis. No diffs, no source excerpts, no
file paths from those repos, no defect description detailed enough to reconstruct internal design.

**Contract: `provenance: Public | Private`**, assigned at harvest from the source repo's GitHub
visibility, not from a path convention or recollection. The **write guard** refuses to write
`Private`-derived content to any path resolving inside a git checkout, after canonicalisation, so a
symlink out of the corpus directory and back into the repo does not defeat it. Shaped after
`ReviewOutcome::EmptyRange` (`cli/src/code_review.rs:94`): a fixture's body is reachable only through
an accessor requiring a token proving the destination was checked — the illegal state is not
representable, it is not merely guarded at one call site.

`provenance` keeps a single consumer now that the egress guard is withdrawn — one field, one
purpose.

**Contract: guard ships with tests in the same change**, including the symlink-escape case. **Not
closed by this run:** a human running an ad-hoc command outside the harness.

## 7. The measurement

### 7.1 Arms

`router_model ∈ {qwen, sonnet}` × `stratum ∈ {D, M, Q, N}` × `class ∈ {1, 2, 3}`, design fixed by
§3, per-file routing run as a control arm alongside.

**Decision: the ship decision is per router model.** `router_agent`/`router_model` are separate
config keys (§8) — a sonnet-routed cascade is a different product from a qwen-routed one.

### 7.2 Class 3's role — `gates-conditional` (APPROVED)

For classes 1, 2, and stratum D, the expensive tier found the defect by construction. Class-3
defects were missed by review, so the expensive tier may miss them too, and a cheap tier cannot be
blamed for failing on a defect the expensive tier would also fail on. Two metrics:

- **Conditional recall** (gates): of the class-3 defects the *expensive tier* finds, how many
  survive the cascade.
- **Expensive-tier absolute detection rate on class 3** (does not gate): what fraction of
  review-missed defects the full panel finds at all — reported as the run's ceiling measurement.

### 7.3 Discrimination and controls

**Decision: two synthetic controls bracket every cell, per stratum and per class.** NULL (everything
cleared: recall 0, saving maximal) and FLOOD (everything escalated: recall 1.0, saving 0). A real
cheap tier must land strictly inside the bracket on both axes, or those fixtures are rebuilt before
anything is scored. Reason: the prior run's first instrument did not discriminate — unaided agents
scored 3/4 and 4/4 with no skill at all.

**Positive control:** re-running the expensive tier on a sample must re-find recorded class-1/2
defects at a high rate; if not, the fixtures are not reviewable in isolation and the corpus is
re-cut, not the cheap tier retuned.

**Decision: dev/held-out split, no `blind-map.json`.** Split assigned before any cheap-tier prompt
is written, at task/PR level so no diff appears in both. Held-out is scored once, after the prompt
is frozen and its `git hash-object` recorded. Reason: the threat is prompt overfitting, not scorer
bias (scoring is set membership, no human judgement), so the split is the load-bearing control and a
blind map adds nothing. Recorded as a deliberate departure from the prior protocol.

### 7.4 Ship bar — `by-failure-mode`, non-uniform (APPROVED)

N is sized for the power the bar needs; qwen is unlimited and may read every stratum, so N is no
longer corpus-constrained.

Wilson 95% lower-bound N required to clear each target given misses observed:

| LB target | 0 misses | 1 miss | 2 misses | 3 misses | 4 misses |
|---|---|---|---|---|---|
| ≥ 0.85 | 22 | 34 | 45 | 55 | 64 |
| ≥ 0.90 | 35 | 53 | 69 | 84 | 99 |
| ≥ 0.95 | 73 | 110 | 142 | 173 | 202 |
| ≥ 0.97 | 125 | 185 | 239 | 290 | 339 |

**Decision: the bar is set by failure mode, not uniformly.**

- **Designs with an unrecoverable-miss class** (per-file, whole-change): a miss is a defect nobody
  ever looks at again. Recall ≥ 0.98 with Wilson LB ≥ 0.95, target N ≥ 142 per gated cell.
- **Designs whose failure degrades to baseline** (angle routing, cheap-as-explorer): failure is a
  cost regression, not a lost defect — the expensive tier still reviews everything. Non-inferiority
  against the unaided expensive panel, cascade recall lower bound ≥ 0.90 of the unaided panel's point
  estimate, target N ≥ 69.

Reason for not going past LB ≥ 0.95 even for unrecoverable designs: N = 239 for a two-miss tolerance
at LB ≥ 0.97 buys a 0.02 improvement in a bound whose real uncertainty is dominated by corpus
construction choices (§7.5), not sampling error — that corpus spend buys more validity as a fourth
stratum than as a tighter interval over three.

**Decision order:** 0. N floor met, else null for that cell. 1. Instrument discriminates (§7.3).
2. Recall bar above. 3. Escalation/skip rate leaves a real saving. 4. Measured end-to-end cost <
0.80× the non-cascade panel. **Bars 1 and 2 are the ship decision.** Failing 3 or 4 ships the code
behind `enabled = false` with the negative economics written up. Precision, hint quality, context
completeness, and class-3 absolute detection are reported and are **not** decision inputs.

**Decision: pooling.** `N ≥ 142` per `(model × stratum × class)` cell would be 24 cells and is not
reachable. The floor applies to the gated number **pooled across strata within one
`(model × class)`** — pooling across strata buys power; pooling across classes would destroy
meaning, which is why §5.1 forbids only the latter. Per-stratum numbers are always reported
alongside; pooling is conditional on them agreeing — if per-stratum recall is more heterogeneous
than sampling explains, the pooled figure is not reported as the headline, and the discrepant
stratum is reported as the finding.

**Freezing contract:** stratum D and N fixtures frozen by a MANIFEST in the shape of
`docs/skill-evidence/arms/MANIFEST.md` — `git hash-object --no-filters` blob SHAs, a commit cell that
must contain the blob at the recorded path, header-resolved columns, a test re-checking every row.
Strata M and Q frozen the same way in the private corpus directory, with only the row count and the
manifest's digest committed.

**Ledger contract:** every cheap-tier invocation counted in an append-only ledger with per-stage
ceilings, arithmetic checked by a test. Retries count.

### 7.5 Stated limitations

1. The largest limitation is corpus construction, not model access: every class is defined by a
   filter (comment→fix attribution, single-blame attribution, verified-real), and each filter
   selects a reachable subset of defects. Class 3 keeps only cleanly-attributable defects (7 of 40
   candidates, §5.5), which are plausibly the simpler ones — the measured ceiling may be optimistic
   in a direction no interval captures.
2. Stratum D ground truth is "what an Opus/Sonnet panel found and someone fixed" — recall against
   the expensive tier, never absolute.
3. Class 1 is "what a human caught and the author fixed"; class 2 is "what a bot nominated and a
   human accepted." Both miss what review missed entirely, which class 3 supplies.
4. Class 1 rests on modular and neovim only (§5.4).

## 8. Configuration and deliverables

```toml
[review.cascade]
enabled = false            # DEFAULT, and it stays off in this run regardless of result
mode = "<undecided>"       # explorer | angle | file | change — SET BY TASK 0, not before (§3).
                            # No default ships until the measurement picks one.
cheap_agent = "opencode"
cheap_model = "ko-ag/qwen3.6-35b-abliterated"
timeout_ms  = 120000        # expiry takes the degrade path of §2
```

**Cheap-tier execution contract.** The cheap tier runs headless, not as a herdr pane:
`opencode run --agent plan -m <model>`, verified working this session. Not stylistic: every cold
`opencode` reviewer pane swallows its seed and the panel cannot converge
(`docs/known-issues.md:3437`), so the pane path is closed for this backend. `opencode run` stdout is
a subprocess pipe, not the rendered terminal view `cli/src/code_review.rs:1` refuses to scrape.
Read-only via `--agent plan` with `--auto` absent; the `readonly_displace` protection
(`cli/src/config.rs:589`) runs first.

**Deliverables.**
1. Task 0 cost instrumentation and its report.
2. Relational-defect ceiling (§4.4).
3. Corpus harvesters — class 1/2 attribution, class 3 blame-back — each reporting attrition.
4. Fixtures + MANIFESTs; D and N committed, M and Q private.
5. `provenance` typing, write guard, tests.
6. Cheap-tier implementation for the selected mode plus the per-file control arm.
7. Cascade stage in `cli/src/code_review.rs` behind `enabled = false`.
8. `docs/cascade-evidence/results.md` — controls, dev numbers, one held-out score per
   (model × stratum × class), each bar in order, ship decisions, §7.5 limitations, aggregates only.
9. Run ledger.

**Contract: guard-with-artifact throughout.** Every set this run extends — config keys, the `mode`
enum, the cheap tier's output vocabulary, ledger columns, MANIFEST rows, fixture list, the class
enum — has its guarding test extended in the same change.

## 9. Scope boundaries

**Out, deliberately:**
- Flipping the default on.
- Changing the angle set, severity model, merge or resume path.
- A second measurement instrument.
- Fixing `docs/known-issues.md:3437` (the headless cheap tier routes around it; the pane bug stays
  open and documented).
- Any tier between qwen and opus.

**Recorded, not scoped away:** `ko-ag/qwen3.6-35b-abliterated` is an abliterated build — safety
tuning removed. A writeup omitting this would describe a different experiment. Under every design in
§4, its output is either a routing decision or a context bundle, never a finding that reaches a
verdict.

## 10. Decisions — approved 2026-08-06, turn 1

All four questions were answered at the gate. They are decisions; the plan phase inherits them and
does not re-litigate them.

| # | question | decision | where it binds |
|---|---|---|---|
| 1 | Unit of escalation | `measure-first` — Task 0 measures `E/(E+D)`, the pre-registered rule picks explorer / angle / per-file | §3, §4 |
| 2 | Ship bar shape | `by-failure-mode` — 0.98 / LB ≥ 0.95 (N ≥ 142) where a miss is unrecoverable; non-inferiority at LB ≥ 0.90 (N ≥ 69) where failure degrades to baseline | §7.4 |
| 3 | Class 3's role | `gates-conditional` — gates on conditional recall against the expensive tier's finds; absolute detection is reported, not gating | §7.2, §7.4 |
| 4 | Stratum D scope | `both-stratified` — `D-rs` and `D-md` scored and reported separately; the bar must pass on `D-rs` alone | §5.6 |

Decision 4 went against this spec's own earlier recommendation (`rs-only`); §5.6 carries the
reasoning for the decision that was made, not the one that was proposed.

No open questions remain. Anything the plan phase discovers that these do not cover is a new
question for a new gate, not a gap in this one.
