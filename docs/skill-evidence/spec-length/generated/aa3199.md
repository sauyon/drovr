# Spec: skill stickiness

drovr's skill documents read as correct practice but do not bind an agent working under context
pressure: none of the compliance devices that make an instruction survive a filling context window
(Iron Laws, rationalization tables, loophole closures, commitment devices) exist anywhere in
`skills/`. This spec closes that gap with five fixes, one new meta-skill
(`drovr:writing-skills`), and an empirical acceptance test that runs inside this same run and can
revert any individual fix that fails to earn its cost.

---

## 0. Build order

Section numbers are not the build order. Fix 5 produces the wording fixes 2 and 4 depend on, and
arm A must be captured before fix 1 overwrites the files it measures.

1. `drovr:writing-skills` + the scenario corpus (§7.1–7.2) — nothing else is testable until the
   harness exists.
2. Capture arm A / RED per skill (§7.3), at the pre-fix `HEAD`, before any skill file is touched.
   Hard gate: once fix 1 lands, arm A is unrecoverable without a checkout.
3. Fixes 1 and 3 (§3, §5): descriptions, phase-framing demotions, task-binding directives.
4. Fix 4 (§6), using the RED wording captured in step 2 for the rationalization tables.
5. Held-out arm B and the voice probe (§7.3–7.4).
6. Fix 2's hook layer (§4.2) — the only Rust work, independently orderable, no dependency on
   steps 1–5. Fix 2's doc layer (§4.1) belongs with step 4.

## 1. Problem

All four discipline skills scope themselves to "a drovr phase" in both `description:` and body
(`tdd`, `systematic-debugging`, `verification-before-completion`, `code-review`), while
`using-drovr` makes inline work the default mode. An agent working inline reads the trigger text
and correctly concludes the skill does not apply to what it is doing.

The compliance surface is partial. Absent everywhere in `skills/`: Iron Laws, rationalization
tables, loophole closures, announcement strings, checklist→task binding. A repo-wide search for
`TodoWrite`/`TaskCreate`/`todo` returns two incidental hits outside `skills/`, so no checklist
anywhere binds to durable state. drovr's discipline skills run 39–51 lines against superpowers'
139–371 equivalents, and counting `NEVER|MUST|STOP` across drovr's four discipline skills gives 3
against 6 for its two mechanics skills (`pipeline`, `handoff`) — a 2:1 tilt toward mechanics,
versus roughly balanced (1.08:1) in superpowers. drovr's only re-assertion mechanism is a single
blocking `SessionStart` hook that no-ops inside phases; nothing re-asserts discipline after turn
one, though Claude Code exposes `UserPromptSubmit` and `PreToolUse` for exactly that and neither
is used.

**Root cause.** superpowers has `writing-skills`, a meta-skill that runs TDD against the skill
documents themselves: RED = run a pressure scenario against a subagent without the skill and
transcribe its rationalizations verbatim; GREEN = write the minimal text countering exactly those;
REFACTOR = close each newly observed loophole and re-run. Every compliance device in superpowers'
corpus is recorded output of that loop. drovr has none, so its skills were written by describing
correct practice — which is why they read well and do not bind. Fixes 1–4 without fix 5 would be
assertions about what an agent rationalizes; fix 5 is what turns them into evidence, and that is
why §0 sequences it first.

## 2. Authoring precedence

Every decision below not settled by direct citation is produced by this four-tier rule, and is
labeled with the tier that produced it:

1. **Published evidence exists** → the evidence decides, citation kept in the text.
2. **No published evidence, but the question is answerable by this run's own RED/GREEN loop or
   voice probe, within the §7.3 budget ceiling** → measure it. Cost may discharge a tier-2
   obligation only when a measurement would exceed that ceiling, never because it seems not worth
   it.
3. **Not reachable, or the measurement is inconclusive, and superpowers has a convention** →
   follow superpowers, stated plainly as a convention-follow, not an evidence-backed choice.
4. **No superpowers analogue at all** → engineering judgement, marked **[tier 4]**. Applies to:
   the per-turn gate's byte budget, the card length, `per_turn`'s default, the reflex-marker
   boundary, the probe's model choice, and §4's length caps. None of these may be defended as
   though a convention or a study backed them.

superpowers' corpus is the output of an adversarial testing loop drovr has not yet run, so it is
treated as the best available prior and tie-break, never a substitute for a reachable measurement.

Two standing rules apply regardless of tier:

- **No fabricated measurements.** drovr states no number, duration, frequency, or comparative
  ("faster than", "better than") as measured unless drovr measured it, or a citation supports it.
  `docs/skill-evidence/` is the only source for a drovr-measured number; rhetorical emphasis
  ("every time") is fine, a false measurement claim is not.
- **No copied text.** Both projects are MIT-licensed, so copying with attribution would be legal,
  but drovr writes its own sentences — mechanisms are ported, expression is drovr's, which is why
  the `drovr:` namespace exists. Any verbatim line surviving review gets the MIT notice and credit
  added.

**Skill docs are prompts, not replies.** The user's global terseness preference governs assistant
replies. It does not govern the length of a document whose job is to survive a filling context
window, so it is not applied to any skill file in this spec.

## 3. Voice and structural devices

These decisions bind §6's rewrite and §7.4's probe.

**Decided by citation (tier 1) — ship unconditionally, not gated behind the probe:**

- **Commitment devices ship as primary.** Commitment ranks top-two in both the 2025 Meincke study
  (N=28,000, GPT-4o-mini) and its 2026 replication (N=126,000, Claude Haiku 4.5 / GPT-5 mini /
  Gemini 3 Flash). The announcement string and the checklist→tracked-task binding are commitment
  devices — the cheapest and best-evidenced devices in this spec — and ship via fix 3 and fix 4's
  Announce section.
- **Top-loading binding content.** Liu et al. ("Lost in the Middle") measures retrieval accuracy
  as U-shaped by position — highest at the start and end of context, lowest in the middle — for
  *document retrieval* on three-generations-old models, not for obedience of an instruction placed
  mid-document. It is the basis for placing Overview/Unity/Iron-Law/Announce at the top of each
  discipline skill (§6's section order), not proof that mid-document rules are ignored.
- **Give the reason, say what to do.** Per Anthropic's prompting guidance, every prohibition in the
  rewritten skills pairs with the required action in the same breath, and every rule carries its
  why. The rationalization table's second column is written as an instruction — "Confidence is not
  evidence; run the command" — never a bare rebuttal.
- **Social proof ships only in its true form.** Any named failure mode comes only from an actually
  observed case in `docs/skill-evidence/`; the invented-frequency form superpowers uses ("steps get
  skipped. Every time.") is prohibited by the no-fabricated-measurements rule.

**Decided by tier-2 measurement, run inside this spec (§7.4), not settled here:**

- **Authority register** (`MUST`/`NEVER`/"no exceptions", imperative second person) — no published
  study isolates it for procedural adherence, and it is reachable by the probe. Measured as variant
  V2 against baseline V0.
- **Unity register** ("the next phase agent is you, with your context gone") — ranks top-two in the
  2026 replication, above authority. drovr applies it to discipline skills as a deviation from
  superpowers, which withholds unity from discipline skills on the older 2025 ranking it cites.
  Measured as variant V1. Unity's published rank is a prior the local 6-run arm cannot overturn on
  its own — §7.4's decision rule states the exception for a result that conflicts with it.
- **Moral framing** — treated as untested, not rejected. The EmotionPrompt null (corrected: +4.42%
  BIG-Bench / +2.58% all-benchmark, from the replication authors' re-analysis of Li et al.'s
  reported numbers; the replication's own measurement found no significant effect, χ²=0.11, p=.74)
  measures benchmark accuracy under emotional stimuli, not moral characterization of a rule
  violation, and does not settle this construct. Measured as variant V3.

§7.4 specifies the full probe design and a decision rule that resolves all three into a
shipped/dropped/convention-follow outcome for every possible result; that procedure is the
decision, not an open question left for later.

**Decided by tier-3 convention-follow (superpowers' choice, adopted wholesale, unmeasured):**

- Iron Law — one fenced, all-caps line, followed by "No exceptions:" bullets that pair each
  prohibition with the required action.
- Spirit-vs-letter line, placed before the rules, countering "I'm honoring the intent
  differently."
- Rationalization table (thought → reality; reality phrased as an instruction, not a rebuttal).
- Red flags section — the agent's own inner-monologue fragments, for mid-drift self-detection.
- Claim → required evidence → not-sufficient table, countering evidence substitution.
- Numeric escalation trigger: after 3 failed fixes, stop, countering thrash loops.
- ✅/❌ paired worked example, disambiguating what compliance sounds like.
- Fenced `dot` flowcharts for genuine branching and for loops where an agent might stop too early
  — never for linear instructions or reference material. Applies to `using-drovr`'s gate function
  (§4.1), `writing-skills`' RED/GREEN/REFACTOR loop (§7.1), `tdd`'s red-green-refactor cycle (its
  superpowers analogue already carries one, so withholding it here would be an unmarked
  deviation), and `systematic-debugging`'s loop. No published study compares a flowchart against a
  numbered list for agent compliance, and the variant is not reachable by the probe (it changes
  document structure, not text register), so tier 3 governs.
- `using-drovr`'s 1% rule and instruction-priority ladder (human's explicit instructions > drovr
  skills > default behaviour), ported from `using-superpowers/SKILL.md:11-29` in drovr's own
  wording.

**Decided by tier-4 engineering judgement:**

- A flowchart rendered next to the plan in the review UI is judged a better fit than prose for
  "where in a procedure the agent currently is," because that state is a position in a branching
  structure and prose has to re-linearise it. superpowers has no review UI and so no analogue
  governs this call. No claim is made about how much faster anyone reads it — that would be a
  fabricated comparative. This is a product judgement, not a measurement, and it is out of scope
  for this run (§8); it is recorded as a follow-up in `docs/known-issues.md`.
- Load-degradation figures for formatting compliance under concurrent task load (circulating
  figures of −2–21%, recovered to 90–100% by salience-enhanced prompting) come from secondary
  summaries of 2026 arXiv preprints not read in full. They are consistent with the redundancy rule
  (§4) and the per-turn gate (§4.2) but do not establish either, and under the no-fabricated-
  measurements rule they are never quoted as measured drovr-relevant numbers in shipped skills.
- The generic rule-wrapper ablation (arXiv:2601.22025, n=50, Llama 3 8B / Qwen 2.5 7B) reports a
  generic "helpful assistant" wrapper degrading extraction 100%→90% and RAG compliance 93.3%→80%,
  while improving instruction-following by 13%. Instruction-following is the closest analogue to
  what §4.2's card is for. Read as non-monotonic and untested at drovr's model scale — not as
  license to claim the card helps or hurts net.
- Persuasion effects are extrapolated from the 2026 replication's tested models (Claude Haiku 4.5,
  GPT-5 mini, Gemini 3 Flash) to the models drovr actually uses (Sonnet for probes, Opus-class for
  sessions) — a stated, unverified assumption, not a finding. Two further limits on the 40-point
  (2025) vs 16-point (2026) gap: the request sets differ between the two studies, and none of the
  2026-tested models are the ones drovr runs, so the narrowing is not cleanly attributable to model
  generation. Register is treated as a real but secondary lever on this assumption.
- Position effects (Liu et al.) and the load-degradation figures are both held to the same
  standard as the EmotionPrompt reading above: they set priors, not conclusions, for constructs
  they did not directly measure.

Transfer from any of the cited studies to drovr's actual target — a coding agent adhering to a
procedure it already agrees with, over many turns, under task load, rather than a chat model being
talked into violating safety training — is not established by any of them. That gap is exactly
what §7.3 and §7.4 are for, and absolute compliance rates from the cited studies (33%→72%,
35%→51%) are never quoted as drovr numbers.

## 4. Length budget

Rule: teaching content stays terse and is cross-referenced, never restated. Binding content — the
prohibition an agent will try to talk itself out of — is deliberately redundant, stated 3–4 times
per skill (Iron Law, red flag, rationalization row, checklist item), because redundancy is the
mechanism, not a defect to edit away.

- `cli/tests/skills_valid.rs`'s `BODY_BUDGET` constant (`:17`, currently 2200 bytes, checked over
  the four discipline skills only, `:20-25`) rises to **12000 bytes** [tier 4 — no superpowers
  analogue, no evidence sets a correct length]. Current bodies pass; §6's rewrite is 3–4× over the
  old budget, which is why it must move.
- `using-drovr` gets its own budget and joins the checked list at **9000 bytes** [tier 4]. It is
  the most expensive document in the repo — injected in full on every `SessionStart` — and is
  currently exempt only by accident of history (5087 B / 775 words / 93 lines today; §4.1 adds six
  blocks). Leaving the highest-cost file uncapped while capping the others is indefensible.
- **`cli/tests/skills_valid.rs`'s byte check is the single authoritative size check.** `wc -l` /
  `wc -w` are author guidance only and are never asserted as a verification criterion (§9).
- Above either cap, the excess moves into `references/`.

Both new numbers deviate from superpowers in both directions at once (its TDD skill is 371 lines /
1496 words, while its own authoring guidance recommends under 200 words for frequently-loaded
skills). Neither number is cited or measured; both are tier-4 judgement calls, marked as such
rather than dressed up as evidence-backed.

## 5. Fix 1 — un-scope the four methodology skills, plus using-drovr

Every drovr-phase reference in the four discipline skills' `description:` and body becomes a
clearly marked *additional* consequence, never a precondition. This is fixed as a defect, not a
stylistic pass: "in a drovr phase" reads as "does not apply" to an agent working inline, which
`using-drovr` makes the default mode.

Same fix covers a second, related defect: **a `description:` must be a trigger, not a summary.** A
description that summarises the workflow lets the agent take that summary as a shortcut instead of
reading the skill. `using-drovr:3` is currently a summary; Anthropic's own skill-authoring guidance
independently identifies the trigger description as the highest-leverage line in a skill.

**`description:` — literal replacement text, all five files.** These are the shipped defaults;
fix 5's RED pass (§7) may tighten the wording per its four-part closure's description clause, but
this baseline ships regardless of RED's outcome:

| File | New `description:` |
|---|---|
| `skills/tdd/SKILL.md:3` | `Use when implementing any feature or bugfix, before writing implementation code — requires a test you have watched fail before any implementation exists; no production code without a red test first` |
| `skills/systematic-debugging/SKILL.md:3` | `Use when encountering any bug, test failure, or unexpected behavior, before proposing or writing a fix — requires a reproduction and a mechanistic root cause before any code change` |
| `skills/verification-before-completion/SKILL.md:3` | `Use when about to claim any work is done, fixed, or passing, before reporting, committing, or handing off — requires running the verification command in this message and reading its output; evidence before assertion, always` |
| `skills/code-review/SKILL.md:3` | `Use when you have written any change, before calling it done or handing it forward — requires read-only reviewer subagents run in the foreground, with every Critical and Important finding resolved or explicitly recorded as deferred` |
| `skills/using-drovr/SKILL.md:3` | `Use at the start of every session and before every response, including before clarifying questions and before reading any file — routes to the right drovr skill and requires invoking it whenever there is even a 1% chance one applies` |

**Body demotions:**

| File | Change |
|---|---|
| `skills/tdd/SKILL.md:17-19` | Phase framing demotes to one subordinate line: *"Inside a drovr phase this also binds the next phase's contract."* |
| `skills/systematic-debugging/SKILL.md:14-17` | Same demotion. The read-only-explorer rule is unconditional and is unchanged. |
| `skills/verification-before-completion/SKILL.md:15-17,40-42` | `drovr phase done` demotes to conditional: *"If you are in a phase, this is also what gates `drovr phase done`."* |
| `skills/code-review/SKILL.md:13-14,41` | Same demotion for the pipeline-review-phase and report-done references. |

**`docs/known-issues.md`:** one entry, in the file's existing convention (`## <symptom title> —
FIXED <date>`, `**Status:**`, `**Severity:** medium`, `**Found:**`, `### Symptom` / `### Root
cause` / `### Fix`), recording that four descriptions scoped unconditional discipline to phases
while `using-drovr` makes inline the default. One entry only — the remaining fixes are design
work, not defect repairs, and do not get known-issues entries.

## 6. Fix 2 — using-drovr as a per-turn gate

### 6.1 Doc layer — `skills/using-drovr/SKILL.md`

New content, in this order (placement follows §3's top-loading decision):

1. `<SUBAGENT-STOP>` — unchanged, kept at `:8-11`.
2. **The 1% rule** [tier 3], placed above the H1 inside the existing `<EXTREMELY_IMPORTANT>`
   framing: even a 1% chance a drovr skill applies means invoke it, paired with the cost-lowering
   clause — if it turns out not to fit, drop it; invoking costs almost nothing.
3. **The per-turn rule**: check before any response, including before a clarifying question and
   before any read-only exploration.
4. **Instruction-priority ladder** [tier 3]: the human's explicit instructions outrank drovr
   skills, which outrank default behaviour. This is the safety counterweight to the MUST language
   and is not optional.
5. **Gate function** — a fenced `dot` flowchart (it branches, so §3's placement rule applies):
   message received → does any skill apply (≥1%) → invoke → announce → does it have a checklist →
   create one tracked item per step → follow it → only then respond.
6. **Red-flag table for the router's own failure mode** — invoking nothing at all, which drovr
   currently has zero coverage of. Candidate rows, finalized by fix 5's RED pass rather than fixed
   here: "this is a one-line change," "I'll just look at the file first," "they asked a question,
   not for work," "I'm already mid-task, the router was for turn one," "escalating to a phase would
   be overkill so no skill applies."
7. Existing sections (single-writer, always-review, methodology, escalation) are retained
   unchanged.

Items 2–5 sit outside every `<!-- reflex:section:NAME -->` marker [tier 4 — superpowers has no
sectioned-reflex analogue]: `[reflex.sections]` may subtract advisory sections but must not be able
to silently delete the routing core; only `[reflex] enabled = false` removes it. This is deliberate
— a half-disabled router would produce an agent that believes it is running drovr and is not, while
an explicit master-switch-off is an informed choice.

### 6.2 Hook layer — new `UserPromptSubmit` hook

Every decision in this subsection is **[tier 4]**: superpowers is `SessionStart`-only, so there is
no convention to follow and no study covers per-turn re-injection. This is drovr's most novel
mechanism, and it ships as an explicit, unmeasured bet, recorded as such in
`docs/skill-evidence/per-turn-gate.md`.

- `hooks/hooks.json` gains a `UserPromptSubmit` entry running a new, thin `hooks/user-prompt`
  script that `exec`s `drovr reflex --gate`. `UserPromptSubmit` takes **no** `matcher` — the
  existing `SessionStart` entry's `startup|clear|compact` matcher must not be copied across.
- **Byte budget stated two ways, because the cost is cumulative, not a rate:** `additionalContext`
  is appended every turn and stays in the window, so the budget is **≤600 bytes per injection, and
  a cumulative ceiling of ~60 KB over a 100-turn session** — real weight in the window drovr exists
  to keep tight.
- **Suppression rule**, to keep the cumulative cost bounded: the card is emitted only when no
  `drovr:*` skill was invoked in the previous turn. A session already running the discipline does
  not need re-telling; a session that has drifted does. This bounds the common case to a handful of
  injections.
- **Byte budget, not tokens** — the CLI has no tokenizer and length is not tokens. The assertion is
  rendered `additionalContext` ≤ 600 bytes, checked in `cli/src/reflex.rs`'s test module.
- **Card content**: the 1% rule, the per-turn check, the announcement string, the
  checklist-binding line, a `<SUBAGENT-STOP>` line, and a pointer to `Skill drovr:using-drovr`.
- **Three required API changes**, all verified against source:
  1. `reflex.rs:143-152`'s `envelope()` hardcodes `"hookEventName": "SessionStart"`; it is
     parameterized to take the event name.
  2. `main.rs:114-118` declares `Reflex { skill: PathBuf }` as required, and `main.rs:1276-1278`
     asserts that bare `drovr reflex` errors. Adding `--gate` makes the field `Option<PathBuf>`
     with a clap arg-group rule (`--gate` xor `--skill`), and that test is updated accordingly.
  3. Card text is a `const` in `reflex.rs`, not extracted from `SKILL.md` — extraction would need
     markers inside the region §6.1 deliberately places outside every `reflex:section` marker. The
     resulting drift risk between card and skill is mitigated by a test asserting the card's key
     phrases appear in `using-drovr/SKILL.md`.
- **Subagents.** `using-drovr:8-11` already carries `<SUBAGENT-STOP>` for exactly this case, and
  §7.3/§7.4's foreground probe subagents plus drovr's own read-only reviewers all launch from a
  gate-on session. If `UserPromptSubmit` fires for Agent-tool subagents in this harness, the card
  would inject into every one of them and contaminate the probes, so **the card carries its own
  unconditional subagent-stop line** regardless. Whether the hook actually fires for subagents is
  verified empirically as build step 1 (§0), and the answer is recorded in
  `docs/skill-evidence/per-turn-gate.md`.
- **Config:** new `[reflex] per_turn` bool in `ReflexConfig` (`cli/src/config.rs:39-64`), default
  `true` [tier 4], suppressible per-user, via a named default fn — not bare `#[serde(default)]`,
  which is the trap already documented at `config.rs:108-110`.
- **Asymmetric suppression, deliberate.** The full `SessionStart` reflex stays suppressed inside
  phases (`DROVR_PHASE` set), because a phase agent runs on its injected briefing. The per-turn
  gate does **not** suppress inside phases — a phase is exactly where the discipline must hold.
- `README.md:70-94` gets the new key documented.

### 6.3 Out of scope

`PreToolUse` could hard-deny an `Edit` that skipped `drovr:tdd`, or a `git commit` with no
verification evidence. That is enforcement rather than persuasion — a larger design with real
false-positive risk — and is not part of this run.

## 7. Fix 3 — bind checklists to tracked task state

Stated harness-agnostically because harnesses differ: some sessions expose
`TaskCreate`/`TaskUpdate`/`TaskList` and no `TodoWrite`, while stable Claude Code exposes
`TodoWrite`. No CLI change is required for this fix.

Directive text, inserted verbatim at each site below:

> When a skill or briefing gives you a numbered checklist, create **one tracked item per step**
> using whatever task tool this harness exposes — `TodoWrite`, or `TaskCreate`/`TaskUpdate` —
> before you start step 1. Mark each in-progress when you start it and complete when its evidence
> is in hand. If the harness exposes no task tool, write the checklist to
> `~/.local/share/drovr/runs/<run>/checklist.md` when inside a run, or `CHECKLIST.md` at the repo
> root otherwise, and tick items there. An untracked checklist decays with the context window;
> that decay is the exact failure drovr exists to fight.

Applied at four sites:

1. `skills/using-drovr/SKILL.md` — the gate function's checklist branch (§6.1 item 5).
2. Each of the four discipline skills' numbered procedure — one binding line directly above it.
3. `skills/pipeline/phase-prompts/*.md` — the `## Do` lists (`implement-task.md:14-64`, 7 steps,
   and the equivalents in `brainstorm.md`, `plan.md`, `review.md`, `review-angle.md`) gain the
   directive as step 0. These files are agent-assembled markdown, not compiled into the binary, so
   this is a pure text change.
4. `skills/handoff/SKILL.md` and `skills/handoff/HANDOFF-template.md` — the 7-section handoff is a
   checklist and gets the same treatment.

## 8. Fix 4 — move the armor onto the discipline skills

`tdd`, `systematic-debugging`, `verification-before-completion`, and `code-review` are restructured
to a fixed section order [tier 3 — the order is superpowers' convention, adopted wholesale]:

```
   REQUIRED — all four skills
1. description:      trigger, not summary (fix 1)
2. Overview          core principle + spirit-vs-letter line + the WHY, ≤6 lines
3. Unity line        "the next phase agent is you, with your context gone"
4. The Iron Law      one fenced all-caps line + "No exceptions:" bullets closing named loopholes,
                     each bullet pairing the prohibition with the required action
5. Announce          the exact sentence to emit when invoking the skill (commitment device)
6. The procedure     numbered, preceded by the task-binding directive (fix 3)
8. Red flags — STOP  inner-monologue fragments, closed by a catch-all bullet
9. Rationalizations  thought → reality; the reality column is an INSTRUCTION, not a rebuttal
10. Worked example   one ✅/❌ pair of actual utterances. One good example, not five
11. Cross-refs       bare skill names with REQUIRED markers; never @-links (they force-load)

   CONDITIONAL — only where named below
7. Requirements      claim → required evidence → not sufficient
                     ONLY: verification-before-completion, code-review
6b. Cycle flowchart  a fenced dot graph of the loop
                     ONLY: tdd, systematic-debugging   (§3 placement rule)
```

Section numbers 7 and 8 in the outline above are the document's own numbering (superpowers'
convention), not a typo — section 7 is conditional and sits between 6 and 8.

**Announcement strings** — template `Using drovr:<skill> to <purpose>.`, four shipped strings:

- `tdd` — *"Using drovr:tdd — writing the failing test before the implementation."*
- `systematic-debugging` — *"Using drovr:systematic-debugging — reproducing before fixing."*
- `verification-before-completion` — *"Using drovr:verification-before-completion — running the
  checks before claiming done."*
- `code-review` — *"Using drovr:code-review — dispatching read-only reviewers before calling this
  done."*

**Placement rationale, stated honestly.** Sections 2–5 sit at the top because §3's position-effects
citation favours the start of a document. Sections 8–9 sit late for a different reason — proximity
to the point of temptation, which is a tier-4 judgement, not the position-effects finding. The
procedure (6) sits mid-document, the weakest position, deliberately: it is the section the agent is
actively executing and re-reading while it works, so it is least dependent on recall from a single
pass. The position-effects citation is not invoked for sections 6–9.

**Per-skill Iron Laws and loophole closures:**

- **`tdd`** — Iron Law: no implementation code before a test you have watched fail. Closures:
  "I'll keep the code as reference," "the test is obvious so I'll write it after," "it's a refactor
  so TDD doesn't apply," "the harness makes it hard to run one test."
- **`systematic-debugging`** — Iron Law: no fix before a reproduction and a mechanistic cause. Adds
  the numeric escalation trigger: after 3 failed fixes, stop and question the design before
  attempting fix #4.
- **`verification-before-completion`** — Iron Law: no completion claim without fresh evidence
  produced in this message. Requirements table covers tests / build / linter / bug-fixed /
  subagent-reported-success. Catch-all red flag for any wording implying success.
- **`code-review`** — Iron Law: no change is done until a read-only reviewer has looked at it and
  every Critical/Important finding is resolved or explicitly recorded as deferred. Closures: "the
  change is too small," "I already reviewed it myself," "the pipeline's review phase will catch
  it." The existing FOREGROUND rule (`code-review/SKILL.md:19-23`) is promoted into the
  no-exceptions list — backgrounding a reviewer is the known way this skill silently fails.

Expected result: 39–51 lines today, roughly 120–180 lines after; the binding constraint is §4's

## 9. Fix 5 — the meta-skill and the empirical loop

### 9.1 New skill: `drovr:writing-skills`

New file `skills/writing-skills/SKILL.md`, in drovr's own voice. The pass criteria, four-part
closure, and scenario-construction rules below are tier-3 convention-follows, ported from
`testing-skills-with-subagents.md:182-275` in drovr's own wording, and are independently convergent
with Anthropic's own skill-authoring guidance (build evaluations first, establish a baseline
without the skill, write minimal instructions, iterate).

- **Mapping** that gives the loop its authority: pressure scenario ↔ test case; `SKILL.md` ↔
  production code; RED ↔ the agent violates the rule without the skill; GREEN ↔ it complies with
  the skill; REFACTOR ↔ close each new loophole.
- **Loop** (fenced `dot` flowchart — a stop-too-early loop, per §3): build the scenario set → run
  the baseline → transcribe every excuse verbatim → write the minimal counter-text → re-run on
  held-out scenarios → apply the four-part closure to each new rationalization → repeat until a run
  produces no new rationalization **or** the §9.3 REFACTOR ceiling is reached, whichever comes
  first. The ceiling is not optional: an uncapped "repeat until clean" loop is the same
  unbounded-cost defect this spec exists to fix elsewhere.
- **Four-part closure**, all four every time, never one: explicit negation inside the rule; a row
  in the rationalization table; a bullet in red flags; and a `description:` update adding the
  symptom of being about to violate.
- **Scenario construction rules**: real file paths, concrete numbers and deadlines, a forced A/B/C
  choice, phrased "what do you do" not "what should you do," no escape hatch to "I'd ask the
  human," and ≥3 combined pressure types (time, sunk cost, authority, economic, exhaustion, social,
  pragmatic) — agents resist single pressures and break under combined ones.
- **Pass criteria**, all four required: the correct option under maximum pressure; the agent cites
  a specific section; it names the temptation and complies anyway; and the meta-test ("how should
  this have been written?") returns "it was clear." Not-bulletproof signals: new rationalizations,
  the agent arguing the skill is wrong, invented hybrid approaches, or asking permission while
  still arguing for the violation.
- **drovr-specific constraints**: scenario subagents run in the FOREGROUND; the author is the
  single writer; §2's no-fabricated-measurements rule applies to any number this skill or its
  corpus states.
- Reference files: `references/pressure-scenarios.md` and `references/testing-with-subagents.md`,
  keeping `SKILL.md` itself under §4's cap.

### 9.2 Evidence corpus — new paths

- `skills/writing-skills/scenarios/<skill>-<n>.md` — checked-in scenario prompts, each tagged `dev`
  or `holdout` (§9.3). They are tests and live with the skill.
- `docs/skill-evidence/<skill>.md` — per skill: scenarios used, verbatim baseline
  rationalizations, the text written to counter each, and the re-test result with dates.
- `docs/skill-evidence/voice.md` — the §9.4 probe record.
- `docs/skill-evidence/per-turn-gate.md` — §6.2's unmeasured-bet record and the subagent-firing
  answer.
- `docs/skill-evidence/transcripts/` — raw transcripts; this is the corpus any drovr skill text
  cites whenever it makes a numeric claim (§2's exception 1).

### 9.3 The acceptance test — runs inside this run

Answers the question "did stickiness improve, or did the docs just get longer."

**Held-out design.** Authoring arm B from the same scenarios that grade it would fit the text to
the test and make the pass bar unfailable. So, per skill: 3 scenarios, 1 development and 2
held-out. RED transcription and all counter-text authoring use the development scenario only. The
pass bar is pre-registered and scored on the held-out pair, which is never read while writing
arm B.

**Arms** — three, so fix 1's and fix 4's contributions are separable:

| Arm | Text |
|---|---|
| A | Current `SKILL.md` at the pre-fix `HEAD` (captured in §0 step 2) |
| A′ | Fix-1-only: descriptions un-scoped, no armor |
| B | Full rewrite (fixes 1 + 3 + 4) |

A′ exists because arm A's descriptions are phase-scoped — the exact defect §5 fixes. Without A′, a
non-phase-framed scenario would handicap A for a reason unrelated to the armor, and B beating A
would prove nothing about fix 4 specifically. A′ isolates the armor's contribution.

**Budget table — hard ceilings.** When a ceiling is hit, work halts and records a null in
`docs/skill-evidence/`; it does not silently extend.

| Stage | Scope | Runs | Ceiling |
|---|---|---|---|
| RED / baseline on dev set | 5 skills × 1 dev scenario × 2 samples | 10 | 10 |
| Arm A on held-out | 5 skills × 2 held-out × 2 samples | 20 | 20 |
| Arm A′ on held-out | 4 discipline skills × 2 × 2 | 16 | 16 |
| Arm B on held-out | 5 skills × 2 held-out × 2 samples | 20 | 20 |
| REFACTOR re-tests | failing skills only, ≤2 iterations each | ≤20 | 20 |
| Voice probe (§9.4) | 4 variants × 2 scenarios × 3 samples | 24 | 24 |
| `using-drovr` no-skill-applies class | 2 scenarios × 3 arms × 2 samples | 12 | 12 |
| **Total** | | **≈122** | **122 hard ceiling** |

`using-drovr`'s extra scenario class checks the router's own failure mode — invoking nothing — at
the same time as guarding against the opposite failure of invoking everything reflexively. It is
budgeted, not free.

**Execution structure.** 122 foreground subagent runs with verbatim transcription do not fit in one
implement-task context, which is the exact failure drovr exists to prevent. Decomposition: one
dedicated phase per skill, `ab-<skill>` (5 phases), each running its own stages, writing
`docs/skill-evidence/<skill>.md` plus raw transcripts, then exiting. The voice probe is a sixth
phase, `ab-voice`. The driver aggregates results. No phase holds more than ~25 runs.

**Scoring** — pre-registered, and not scored by arm B's own author:

- **Rubric**: binary compliant/non-compliant on the scenario's forced choice, plus the four §9.1
  pass criteria recorded separately as booleans.
- **Scorer**: a read-only reviewer subagent, given only the transcript and the rubric.
- **Blinding**: arm labels stripped and transcripts shuffled before scoring; the mapping is
  restored only after all scores are recorded. Unblinded self-scoring by arm B's author is exactly
  what the replication literature this spec cites warns about.
- **Model**: `sonnet` for both probe subagents and the scorer.

**Pre-registered bars**, written before arm B runs:

- **Arm A "already passes"**: compliant on ≥3 of its 4 held-out runs (2 held-out scenarios × 2
  samples).
- **Arm B passes**: compliant on ≥3 of its 4 held-out runs for that skill, AND strictly more
  compliant runs than both A and A′.
- **Consequence of B failing after its REFACTOR ceiling — not merely documentation.** That skill's
  armor does not ship: it reverts to arm A′ (fix-1-only), and `docs/skill-evidence/<skill>.md`
  records the failure and the reverted state. Fix 1 is a defect repair and ships regardless; fix 4
  must earn its bytes.
- **Falsifiable.** If arm A already passes for a skill, that skill's rewrite is not justified and
  reverts to A′ — the guard against length-for-its-own-sake.
- **If A′ ≈ B** for a skill, the armor is not carrying its weight there and that skill reverts to
  A′ even if B independently clears its own bar.

Null and negative results are recorded alongside positive ones in `docs/skill-evidence/`.

### 9.4 Voice probe

**Probe skill: `verification-before-completion`.** Sharpest binary outcome (did the agent claim
done without running the command), shortest scenarios. **Model: `sonnet`**, matching §9.3 — this
is explicitly not the Opus-class model drovr sessions run on, a stated limitation alongside §3's
Haiku/mini/Flash-to-Sonnet/Opus extrapolation.

Four variants, identical in structure (same Iron Law, same procedure, same tables, same placement),
each adding exactly one register device to the baseline, so each factor is separable at this sample
size:

| Variant | Register |
|---|---|
| V0 | Baseline: plain imperative; no all-caps, no absolutist "no exceptions"; operational consequence only |
| V1 | V0 + unity line |
| V2 | V0 + full authority register (`MUST`/`NEVER`, all-caps Iron Law, no-exceptions bullets) |
| V3 | V0 + moral framing, in superpowers' register |

4 variants × 2 scenarios × 3 samples = 24 runs, 6 per variant, each compared against V0's 6 runs.

**Pre-registered decision rule.** Separation margin set at ≥3 of 6 — matching the stated power
rather than sitting below it; a 2-of-12 margin on binary outcomes is roughly one standard deviation
and would fire on noise.

1. **Variant beats V0 by ≥3** → that device ships across all five documents.
2. **V0 beats the variant by ≥3** → that device is dropped, and the baseline register ships for it.
   This is an explicit branch: a plain-register win is a real, recorded outcome, not an undefined
   one.
3. **No separation ≥3** (the likeliest outcome, given §3's expectation that register effects are
   small on frontier models) → tier-3 fallback: authority ships (superpowers uses it), moral
   framing ships (superpowers uses it throughout), and unity ships anyway on the strength of the
   2026 published ranking (tier 1 outranks tier 3). Each outcome is recorded in
   `docs/skill-evidence/voice.md` as convention-or-prior, with the null attached.
4. Whichever register wins applies to the other four documents without re-testing each — a stated
   limitation: measured on one skill, one model, generalized to five documents.

**Exception, no directional escape hatch.** If V1 (unity) loses to V0 by ≥3, that is recorded as a
genuine conflict between the published prior and drovr's own data and is not auto-resolved by rule
3 above — it escalates to the human, and unity's shipping decision for the affected skill(s) waits
on that answer. 6 runs cannot overturn an N=126,000 result on their own; what the local arm can do
is surface a large local effect if one exists, and nothing stronger than "suggestive" is recorded
from it either way.
