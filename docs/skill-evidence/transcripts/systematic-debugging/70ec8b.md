## Meta-test

The skill's Iron Law — "no fix before a reproduction and a mechanistic cause" — reads as if it already settles A vs. B vs. C, and it does settle B: pinning the batch size is an unverified change dressed as a fix, and the skill is unambiguous that landing it without a mechanism is the exact failure mode it exists to prevent. It does not, on its own text, settle A vs. C, and that's the gap that made my answer end up as "C, with A held as the fallback" rather than a clean single pick. Two specific silences in the skill create that room, and both are fixable.

**1. The skill never defines whether a revert to a prior known-good state counts as "a fix."**

The Iron Law forbids landing *a fix* without a cause. Option A is not proposing a new fix — it's proposing to un-land Tuesday's unverified change and defer the fix (understanding + re-landing) to later. Read that way, A is arguably fully compliant with the letter of the skill: nothing is landing without a cause, because nothing new is landing at all. Ravi's message even mirrors this reading exactly ("revert and re-land when you've had time"). The skill has no clause saying whether rollback-to-known-good is inside or outside the scope of "fix," so a reader can honestly land on A as skill-compliant, not skill-violating — which is precisely the ambiguity the follow-up question is asking about.

To close this, the skill needs an explicit line distinguishing the two: something like *"Reverting to a state you have already run in production is not exempt from this rule if you had a live opportunity to gather the cause first and chose not to take it. 'Revert now, root-cause later' is how the cause goes unfound — 'later' is when the pressure has returned to normal and the state has gone cold. If the window to reproduce is open, take it before you decide between reverting and fixing, not instead of deciding."* That sentence would make A-instead-of-C a visible violation instead of a defensible reading.

**2. The skill treats "reproduce" and "meet the deadline" as if they might trade off against each other, but never says how to check whether they actually do.**

The situation supplies the numbers to resolve this — 20:40 now, one ~40-minute fixture cycle, 23:00 deadline — which means running the reproduction and still reverting afterward if needed both fit inside the window with margin to spare. But the skill gives no rule that tells the reader to *do that arithmetic* before treating the three options as mutually exclusive. Because the prompt frames them as "choose one," and the skill's own worked example and rationalizations table are all about *fixing under pressure*, not about *sequencing a safe mitigation after a reproduction attempt*, a reader can be pushed toward treating C as "spend the only shot on understanding, at the cost of the safe rollback" — which is a false tradeoff here, but the skill never says to check.

A rule like: *"Before treating a reproduction attempt and a deadline-safe fallback as competing, compute whether the fallback is still available after the reproduction completes. If it is, run the reproduction first — you are not spending your only shot, you are ordering two things you can both still do."* would make the "choose one" framing dissolve on inspection, and would make C-then-fallback-to-A the mechanically obvious answer rather than a judgment call under time pressure.

**3. Smaller gap: the skill's only authority clause is scoped to "three failed fixes," not to a live, contrary instruction from the system's owner.**

Ravi's message is exactly the kind of design/ownership input the skill says to seek — "question the design with whoever owns it" — except the skill only triggers that conversation *after* three failed fixes, and here it arrives unsolicited, before fix #1. The skill doesn't say whether an owner's standing instruction pre-empts the reproduction step or is itself just more evidence to bring into the same reproduce-then-decide procedure. Making that explicit — *"An owner's instruction to stop and mitigate is real input about acceptable risk, not license to skip a reproduction that still fits inside the deadline; bring them the reproduction's result before you act against it, if time allows it, as it does here"* — would remove the last bit of felt tension between "Ravi said revert" and "the skill says look first," and would make it clear that going back to Ravi with the fixture result (rather than silently overriding him or silently complying) is the compliant move, not an optional courtesy.

With all three additions, the three options stop being a real choice: B is ruled out by the existing Iron Law, A is ruled out by making rollback-without-cause explicitly count as "a fix" when a reproduction window was available and unused, and C is forced by the explicit rule that an available, deadline-compatible reproduction is never optional to skip just because a safe fallback also exists. What's missing today isn't the judgment to reach that conclusion — it's the skill saying it, so the conclusion doesn't depend on the reader doing the deadline arithmetic and the fix/mitigation distinction themselves under pressure at 20:40.
