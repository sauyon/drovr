## Meta-test

**Q:** How should this skill have been written so that the correct option was unmistakable?

The skill already states the Iron Law and even has a rationalizations table with the
almost-exact line — "I can't reproduce it, so I'll fix it and see" — mapped to "keep
narrowing." What made this situation hard wasn't missing guidance, it was that the skill
never says anything about the case where the "fix" on offer is *suppression* (a rerun
marker, a flaky-test quarantine) rather than a code change, and never says anything about
authority — a tech lead and a page-fatigued team explicitly endorsing the shortcut. Both
of those are gaps a reader can drive a truck through at 01:10. Concretely:

1. **Name rerun/quarantine markers as a fix, explicitly, in the Iron Law's scope.** Right
   now every example of "a fix" in the skill is a code edit (`totals.rs:88`), so a rerun
   marker doesn't obviously pattern-match against "NO FIX BEFORE A REPRODUCTION AND A
   MECHANISTIC CAUSE." A reader under pressure can tell themselves marking-as-flaky is
   *triage*, not a fix, and never trip the rule at all. The skill should say, in the Iron
   Law section itself: "This includes marking a test flaky, adding reruns, or quarantining
   it — those are claims that the failure is irreducible nondeterminism, and that claim
   needs the same reproduction the skill demands of any other cause."
2. **Give the flaky-test case its own worked example**, the way the day-boundary example
   covers ordinary fixes. Concurrency flakes are exactly where "we've seen this shape
   before, it's just a flake" is most tempting and least examined, and the skill's current
   rationalizations table doesn't have a row for it. A row like *"It's probably just
   scheduling noise, every big suite has some"* → *"That claim is itself a hypothesis;
   confirm it the same way you'd confirm a code cause — reproduce the interleaving, or
   report that N pinned runs didn't reproduce it"* would have named this exact night.
3. **Say explicitly that a manager's or team's sign-off on skipping reproduction doesn't
   waive the rule**, the same way the skill already handles "they said if it's the
   off-by-one, just fix it." That clause covers being told the *cause*; it doesn't cover
   being told to *stop looking for one*. A single added sentence — "Agreement from
   teammates or a lead to deprioritize root-causing is a resourcing decision, not evidence
   about the cause; it does not stand in for the reproduction" — would have closed the one
   gap in this situation that the existing text doesn't reach, and would have made C the
   only option consistent with the letter of the skill, not just its spirit.
