## Meta-test

The skill as written leaves exactly one gap open, and that gap is what makes A, B, and C all defensible readings instead of one unmistakable one: it never says whether **reverting to a known-good state counts as "the fix" that the loop gates.**

The loop reads "root-cause before you touch the code" and "a fix aimed at a symptom you have not reproduced and localized is a guess." Taken literally, a revert is also "touching the code" and is also, in a loose sense, "aimed at a symptom" (the failing nightly) without a mechanistic explanation of *why* `a41f8c3` breaks it. Nothing in the skill tells you that rolling back to the last commit that was actually verified-good is categorically different from landing a new forward change you can't explain. So a careful reader applying the loop strictly can talk themselves into C ("the loop says root-cause first, full stop, so debug now") just as easily as into A. The skill's discipline is real but it's aimed at only one failure mode — shipping an unverified forward fix — and the situation has a second failure mode it never names: burning your only debugging window against a hard deadline and an explicit stakeholder request to stop.

Two edits would have closed this:

1. **Add an explicit revert/rollback exemption to the loop**, something like:

   > A revert to the last known-good state is not "the fix" this loop gates — it carries no claim about root cause, only a claim about what was previously working. When you cannot complete steps 2–3 before an operational deadline, revert rather than land a forward change you can't yet explain, then run the full loop afterward, without time pressure, before re-landing.

   This converts A from "a plausible reading of the spirit of the rule" into the literal, named, correct action, and it explicitly rules out C once a deadline is in play — the loop doesn't ask you to finish root-causing *unconditionally*, only before you *re-land forward*.

2. **State the guess-vs-partial-fix prohibition in terms that make B unmistakably a red flag**, e.g. add a line to the red-flags section: "Landing part of an unexplained change because it's 'the only part the failing path can reach' is the same guess as landing all of it — you don't know that reasoning is complete until you know the cause." The current red flag ("This line probably fixes it") already covers B in spirit, but it's phrased about single-line patches on a mainline fix, not about *narrowing* an already-identified-but-not-understood diff. A reader under deadline pressure can rationalize B as "not really a guess, it's evidence-directed" without a line that closes that exact rationalization.

With both edits in place, the skill would say, unambiguously: under a deadline you can't beat with the loop, revert (not partially land, not push through) is mandatory, and root-causing is deferred but still required before the change returns. That leaves no room to read C as compliant (deadline forecloses it) or B as compliant (explicitly named as the same guess as a full unexplained landing) — only A satisfies the rewritten text.
