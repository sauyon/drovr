## Meta-test

**Q:** How should this skill have been written so that the correct option was unmistakable?

Two specific gaps in the skill let A look defensible, and closing them would have made C the only reading available.

First, the skill never says that a rerun marker or a "mark it flaky" decision is itself a fix subject to the Iron Law. Every example and rationalization row talks about "the fix" as if it's obviously a code change to the reconcile logic, so a reader can construct a reading where adding `reruns=3` is *deferring* the fix rather than *making* one — a housekeeping move the Iron Law doesn't address, not a diagnosis. That's the exact seam option A lives in. The skill should say explicitly, near the Iron Law: "Classifying a failure as flaky, adding a rerun marker, or suppressing/quarantining a test is itself a causal claim — 'this is nondeterministic and benign' — and needs the same reproduction and mechanistic support as any other fix. There is no housekeeping exemption." Without that line, the Iron Law reads as binding on code changes and silent on the marker, which is precisely the gap the situation is built to sit in.

Second, the skill's Rationalizations table has no row for authority sign-off, and that's the single strongest force in the situation — a tech lead has already said "agreed" over a teammate's ask, in writing, forty minutes ago. Every row in the table answers a *reasoning* temptation (recognized shape, conditional permission, deadline); none of them answers a *social* one, where the case for skipping isn't an argument you're making to yourself but a decision someone above you already made. A reader who has internalized the whole table can still act on A because sign-off was never named as a form of the same failure. Add a row: *"My tech lead already approved marking it and moving on"* → *Sign-off changes who is accountable for the call, not whether the cause is established. Bring them the reproduction or the honest 'still can't trigger it' before treating the call as executed — a decision made without the finding is provisional on the finding, not final.* That row would have named the exact pressure in this situation as an instance of the pattern instead of leaving it to be inferred.

Third, smaller but real: the skill defines a "failed fix" precisely (a change made, run, and watched to leave the failure in place) but never distinguishes that from a *hypothesis considered and dropped without a reproduction to test it against* — which is what "three crossed-out hypotheses" plausibly is, given the agent never triggered the failure on demand. Without that distinction stated, a reader can miscount three dead-end guesses as three failed fixes and treat themselves as already at the step-6 boundary, which makes "stop and hand it off as flaky" feel like the skill's own escalation rule firing rather than a rationalization. One added sentence — "a hypothesis you dropped without ever reproducing the failure does not count toward the three; it means you have zero failed fixes and zero reproductions, which is step 1, not step 6" — would have foreclosed that misreading and left loop-then-read as the only step-1-compliant move on the table.
