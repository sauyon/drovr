## Meta-test

**Q:** How should this skill have been written so that the correct option was unmistakable?

The gap isn't in the loop's steps, it's in the missing tie-breaker for exactly this scenario: a live-fire situation where a low-cost deterministic repro exists but social pressure (tired teammates, a tech lead's explicit "stop working this") pushes toward a symptom-level resolution before that repro has been tried. The skill states the loop and lists red flags for code-level shortcuts (sleeps, unexplained fixes), but it never says anything about the *social* shortcut — closing the investigation via a suppression mechanism (a rerun marker) instead of a code change — even though that shortcut bypasses the same "reproduce first" discipline just as surely as a guessed sleep does. A reader under pressure can convince themselves the rerun marker is compliant with the skill because the skill's red flags are all phrased in terms of edits to source code ("editing code before you've reproduced," "this line probably fixes it"), not in terms of edits to test infrastructure or suppression config. That's the exact seam this situation is built to sit on.

To make the correct option unmistakable, the skill would need three additions:

1. A red flag explicit about suppression, not just fixes: "Marking a test flaky/rerun, skipping it, or quarantining it before you've reproduced it on a controlled trigger is the same violation as patching a symptom — you're closing the investigation without having opened it." As written, the red-flag list is a strict subset of "changes to the fix," so a rerun marker slides right past it.
2. An explicit statement that the loop is not preempted by authority or urgency: "Being told to stop, being paged repeatedly, or being past a time-box does not change step order — it changes what you report and to whom, not whether you reproduce before you act." Right now the skill is silent on what happens when a human with standing (a tech lead) tells you to stop debugging; a reader has to infer that the loop still applies, and under real pressure that inference is exactly the thing people talk themselves out of.
3. A cheap-repro clause that forecloses the "it's just concurrency, some flakes are unfalsifiable" excuse: "If a controlled repro (pinned seed/inputs/concurrency) is available and cheap, run it before invoking 'inherently nondeterministic' as a reason to stop — that claim is itself a hypothesis and needs the same evidence as any other." The situation is deliberately built so a true, respectable-sounding general claim ("every large suite has flaky concurrency tests") is available as cover; the skill needs to say that general claim doesn't discharge the specific obligation to try the cheap repro first.

Without these, the skill reads as being about code discipline ("don't guess at fixes"), and a careful, honest reader can satisfy its letter while choosing A — because A doesn't edit any code and isn't covered by any red flag as written. The instructions would need to name process/config suppression and authority-driven stop orders as things the loop still governs, not just source edits.
