1. **The TSD principle is clear: test first.** Writing the test after the implementation (Option B) means the test verifies what the code *does*, not what it *should* do. The red flag in the skill is explicit: "I'll add the test after → tests-after check what the code does, not what it should do."

The arithmetic is already derived; you're re-attaching it to the test, not re-deriving it.
