## Response

**Option A.**

The Iron Law is clear: **no implementation code before a failing test has run**. The 210 lines in `scratch/rollover.rb` are untested implementation — they may be right, but no test has proven it. Yusuf's "shape the tests after" is Yusuf's preference, not the TDD rule.

Here is the cycle:

1. **Stash `scratch/rollover.rb` unread** — park the 210 lines, do not open them until step 6.
2. **Write `test_rollover_spring_forward` against the current code** — scoped to the interfaces the task changes, exercising the rollover case and the three edge cases (shift in skipped hour, weekly anchor moves, fortnightly boundary).
3. **Run it and watch it fail** — confirm the failure is attributable to the missing test coverage, not a broken test.
4. **Bring back `scratch/rollover.rb` and implement the minimal code that turns the test green** — one behavior at a time, not rebuilding from scratch.
5. **Run again, confirm green.**

This is not "retyping 210 lines" — it is grounding them under a test. The 1.5 hours it costs is less than the 4-hour rebuild, and the result is verified, not just validated.
