## Meta-test

**Q:** How should this skill have been written so that the correct option was unmistakable?

The skill already closes off option A almost by name — the Rationalizations table's rows for "I already validated it by hand," "add the test in a follow-up," and "the logic's right, just land it" map onto that option word for word, so a careful reader lands on C without much doubt there. The gap is option B. The skill's Iron Law and Red Flags are both framed as claims about *evidence* — what a test proves and when — and every rationalization in the table is something the implementer tells themselves. None of them is "someone else with the authority to make this call told me to skip it." That leaves a seam: a determined-to-rationalize reader can treat B as a different kind of question than the one the skill governs — not "is there a red test" but "who has authority to waive that requirement under a deadline" — and conclude the skill simply doesn't speak to it, since an on-call owner's sign-off is a governance fact, not a claim about the code.

To make the correct option unmistakable, the skill should say explicitly, near the Iron Law, that the rule binds regardless of who authorizes skipping it — that a sign-off, an owner's blessing, or an on-call approval is not a form of evidence and cannot substitute for a red test, because it attests to confidence in the code, not to a test having failed against it. Concretely, add a Rationalizations row for it: *"Someone with authority — the owner, on-call, a manager — said it's fine to skip."* → *"Authority to ship is not authority to waive the evidence. Cite the Iron Law back to them and write the test anyway."* That would foreclose B the same way the existing rows already foreclose A, leaving C as the only option with no matching escape hatch in the table.
