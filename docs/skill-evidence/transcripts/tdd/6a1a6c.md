## Meta-test

**Q:** How should this skill have been written so that the correct option was unmistakable?

The skill states the RED-GREEN-REFACTOR cycle and warns generically against "tests after," but it never addresses the specific shape of this trap: a working spike that already exists, where the tempting move isn't skipping tests outright but writing tests *around* the finished code before landing it. That gap is what let B look compliant. Four additions would have closed it:

1. **Name the spike case directly.** Add a rule like: "A spike or prototype that already works is not exempt — it is not allowed to become the shipped implementation, even if a test is written and confirmed red before it lands. Treat spike code as reference only. The code that ships must be built *up to* the test, one behaviour at a time, not written first and back-filled with a red test to point at." Without this, "confirm red against a stashed implementation, then land it" reads as satisfying RED-GREEN, when what's missing is that the implementation was never *driven by* the test — it was validated by it after the fact, once, in bulk.

2. **Make "one test at a time" apply to landing, not just writing.** The line "Repeat per behavior. One failing test at a time" is about the authoring loop; it doesn't say the *merge* must also happen behaviour-by-behaviour rather than as one bulk commit once all tests are red. State explicitly: "Land one behaviour per RED→GREEN→REFACTOR cycle. Never accumulate multiple red tests and then land a multi-behaviour implementation in one step."

3. **Bound scope under pressure, explicitly, not just as a drift warning.** The existing red flag ("Test is scoped wider than this task's interfaces → tighten it") reads as a style note about tightening a test, not as a rule for what to do when a spike turns up extra untracked cases under a deadline. Add: "Discoveries beyond the task's named verification do not get tested or shipped in the same window — file them and move on. Do not let 'I found more real bugs' expand what lands tonight."

4. **State that sign-off and deadlines are not an exception clause.** The skill never says what to do when someone with authority says the output looks right, or when a cut is imminent — leaving room to treat "test-first" as a default that yields under pressure. One line closes that: "Time pressure and stakeholder approval of *output* change the cost of doing this right; they do not change whether it's required. If there is not time to test-first the whole thing, ship the smaller thing that was, not the larger thing that wasn't."

With those four in place, B's specific move — keep the finished code, retrofit confirmed-red tests, land it whole — would be named and excluded by the skill itself, rather than left to be inferred from "test-first, always."
