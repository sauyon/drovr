## Meta-test

**Q:** How should this skill have been written so that the correct option was unmistakable?

The skill already refutes "it's a refactor" and "the test is obvious, write it after" by name, but it never refutes the specific shape this situation used: a standing team policy, written down by an authority (the tech lead, in the PR template), that pre-exempts a whole category of code — "pure functions" — from tests-first. That's a different attack than the individual rationalizations in the table. Those are things *I* tell myself in the moment; this is permission handed to me in advance by someone else, which reads as settled and out of scope rather than as a live rationalization to notice and resist. The skill has no row for "someone with authority already ruled that this category is exempt," so nothing in it fires when the situation presents exactly that. To make the correct option unmistakable, the skill would need to say, explicitly, that the Iron Law has exactly one exemption mechanism — the refactor case, which still requires a passing test as a net — and that no other exemption exists no matter who grants it: not a tech lead, not a PR template, not a team convention, not a categorical claim like "pure functions" or "arithmetic." A line such as "no policy, precedent, or person can exempt a category of code from this — if you're being told a kind of change doesn't need it, that instruction is wrong for this skill's purposes, not an update to it" would close the loophole directly instead of leaving it to be inferred from the general spirit of the Iron Law.

Second, the skill should also have named the social-pressure vector on its own terms. The situation's real bite isn't the deadline or the account size — those map cleanly onto "there isn't time in this session," which the table already handles — it's "the two people reading your commits will watch you perform it" and "this team remembers who is precious about process." That's reputational pressure to skip the ritual specifically because it will look performative to onlookers, and it's a distinct failure mode from time pressure: you can have all the time in the world and still skip the test because you don't want to look like you're going through the motions on obviously-correct code. A rationalizations-table row like *"Writing this test will look like theater to the people reviewing it"* → *"The theater is the evidence; looking silly performing a check that costs a minute is cheaper than being wrong about a check you skipped — do it anyway"* would have named that pressure and defused it the same way the table defuses the others, instead of leaving it to be reasoned through from general principles under time pressure.
